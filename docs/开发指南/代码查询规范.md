# 代码查询规范

## 核心原则

**所有代码查询、符号搜索、调用关系分析必须使用 codebase-memory MCP 知识图谱。** 禁止直接使用 grep、glob、LSP 等原始搜索工具进行代码查询。

## 为什么

- **知识图谱**（search_graph / query_graph / trace_path / get_code_snippet）提供了结构化的代码理解：函数定义、调用关系、数据流、跨服务链路，远比纯文本搜索准确和全面
- 原始搜索工具（grep / glob / ls / lsp_diagnostics 等）**仅限以下场景**：
  - 定位具体文件路径（已知文件名时用 glob）
  - 检查编译诊断（lsp_diagnostics）
  - 文件读写操作（read_file / edit_file / write_file）
  - 验证构建和测试结果（bash）

## 推荐工具对照

| 你需要做的事 | 应使用的工具 | 禁止使用的工具 |
|------------|------------|--------------|
| 搜索函数/类/变量定义 | `search_graph` + `get_code_snippet` | `grep`, `glob`, `lsp_definition` |
| 查询调用者/被调用者 | `trace_path(mode: "calls")` | `grep -r "funcName"`, `lsp_references` |
| 搜索自然语言关键词 | `search_graph(query: "关键词")` | `grep`, `glob` |
| 了解项目整体架构 | `get_architecture` | `ls -R`, `glob **/*.swift` |
| 查找所有实现某个接口的类 | `search_graph(name_pattern: ".*Impl")` | `grep "protocol"`, `glob` |
| 分析数据流 | `trace_path(mode: "data_flow")` | 手动 grep 追踪 |

## 索引要求

- 首次打开项目后，如果发现知识图谱未索引，**必须先执行 `index_repository` 进行索引**
- 每次有显著的代码结构变更（新增文件/模块/类）后，建议重新索引以保持图谱最新
- 索引命令：`index_repository(repo_path: "<repo>/NetworkMonitor")`

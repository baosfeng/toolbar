# 构建与测试

> ⚠️ **何时阅读：** 当你需要构建项目、运行测试或进行代码提交时，必须先阅读本文档。

## 环境要求

- macOS 14 (Sonoma) 或更高版本
- Xcode 16+ 或 Swift 6.3+ 命令行工具
- Apple Silicon (ARM64)

## 构建命令

```bash
# 调试构建
swift build

# 发布构建
swift build -c release

# 构建产物位置
# .build/debug/NetworkMonitor  （调试）
# .build/release/NetworkMonitor（发布）
```

## 运行

```bash
# 直接运行
swift run
```

## 测试执行要求

> **提交前必须运行全部测试，修复所有失败的测试用例，确保全部通过。**

- 每次提交前都应当运行项目对应的测试命令
- 如果存在测试失败，必须修复后才能提交

## 常用测试命令

本项目当前未包含单元测试。添加测试后可使用：

```bash
swift test
```

## 单元测试与集成测试

### 单元测试
- 单元测试与代码在同一个 target 中，**每次提交前必须自动运行并全部通过**
- 如果存在失败的单元测试，必须先修复后才能提交
- 运行命令：`swift test`

### 集成测试
- 本项目为 macOS 菜单栏应用，不涉及外部依赖的集成测试

## 异常处理原则

> **任何测试异常都必须被处理，不得遗留。**

### 与当前修改无关的异常
- 如果测试过程中出现异常，但经确认**与当前代码修改无关**（如已有缺陷、环境问题、依赖兼容性等）：
  1. 当前可以**只关注自己的修改**，继续完成当前任务
  2. 但**必须记录该异常**（记录到 `docs/踩坑/` 或提交一个 Issue）
  3. **事后必须及时修复**，不得无限期搁置
  4. 在提交信息或 PR 描述中注明已知的遗留异常
  5. **修复后更新踩坑记录**

### 必须修复的异常
- 与当前修改直接相关的测试失败 → **必须先修复才能提交**
- 与当前修改无关但阻塞后续工作的异常 → **记录并排期修复**
- 新引入的编译错误或依赖冲突 → **必须先解决**

### 故意抛出的异常
- 测试用例中**故意抛出**的异常（如测试异常处理逻辑、预期异常断言）→ 正常，无需处理
- 需在测试代码中有明确的注释说明该异常是预期行为

## 提交策略

- 代码修改完成后，**一次性提交**完整的代码 + 文档变更
- 确保提交后的仓库处于可构建状态
- 每次提交应只包含一个功能变更

## ✅ 操作前自查清单

在根据本文档执行构建、测试或提交操作前，请逐项确认：
- [ ] 单元测试已全部通过（强制要求）
- [ ] 与当前修改无关的测试异常已记录并承诺事后修复
- [ ] 我已按功能单次提交，提交信息符合提交规范

# 构建与测试

> ⚠️ **何时阅读：** 当你需要构建项目、运行测试或进行代码提交时，必须先阅读本文档。

## 环境要求

- macOS 14 (Sonoma) 或更高版本
- Xcode 16+ 或 Swift 6.3+ 命令行工具
- Apple Silicon (ARM64)

## 构建命令

```bash
# 调试构建
swift build

# 发布构建
swift build -c release

# 使用构建脚本（推荐）— 自动打包为 .app bundle 并生成图标
./Scripts/build-app.sh

# 构建产物位置
# .build/debug/NetworkMonitor       （调试，可执行文件）
# .build/release/NetworkMonitor     （发布，可执行文件）
# dist/NetworkMonitor.app           （完整的 app bundle，含图标）
```

## App 图标

图标使用 SF Symbols + 渐变背景自动生成：

```bash
# 手动重新生成图标
swift Scripts/generate-icon.swift Scripts
# 输出的 AppIcon.icns 会自动被 build-app.sh 使用
```

图标设计：
- 蓝紫渐变圆角矩形背景
- 中央为 SF Symbol `network`（网络符号）
- 下方有 `arrow.down.circle.fill`（绿色）和 `arrow.up.circle.fill`（橙色）箭头

## 打包为 .app

构建脚本 `Scripts/build-app.sh` 会自动完成所有步骤：

```bash
# 构建后自动打包到 dist/ 目录
mkdir -p dist
cp -r .build/arm64-apple-macosx/debug/NetworkMonitor.app dist/NetworkMonitor.app

# 或一步到位
make -C Scripts 2>/dev/null || {
  APP_BUNDLE="dist/NetworkMonitor.app"
  mkdir -p "$APP_BUNDLE/Contents/MacOS"
  cp .build/arm64-apple-macosx/debug/NetworkMonitor "$APP_BUNDLE/Contents/MacOS/NetworkMonitor"
  cat > "$APP_BUNDLE/Contents/Info.plist" <<- PLIST
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>CFBundleExecutable</key>
  <string>NetworkMonitor</string>
  <key>CFBundleIdentifier</key>
  <string>com.example.NetworkMonitor</string>
  <key>CFBundleName</key>
  <string>NetworkMonitor</string>
  <key>CFBundleVersion</key>
  <string>1</string>
  <key>CFBundleShortVersionString</key>
  <string>1.0</string>
  <key>LSUIElement</key>
  <true/>
</dict>
</plist>
PLIST
}
```

## 产物目录

构建后的可分发包统一放在 `dist/` 目录下：

```
dist/
├── NetworkMonitor.app      # 可直接双击运行的 app bundle
└── NetworkMonitor.dmg      # 磁盘映像（如已制作）
```

`dist/` 目录下的内容已添加到 `.gitignore`，不进入版本控制。

## 运行

```bash
# 方式一：直接运行（终端）
swift run

# 方式二：打开 .app bundle（菜单栏应用，无 Dock 图标）
open dist/NetworkMonitor.app

# 方式三：从终端启动可执行文件
.build/arm64-apple-macosx/debug/NetworkMonitor
```


## 单元测试与集成测试

### 单元测试
- 单元测试与代码在同一个 target 中，**每次提交前必须自动运行并全部通过**
- 如果存在失败的单元测试，必须先修复后才能提交
- 运行命令：`swift test`

### 集成测试
- 本项目为 macOS 菜单栏应用，不涉及外部依赖的集成测试

## 异常处理原则

> **任何测试异常都必须被处理，不得遗留。**

### 与当前修改无关的异常
- 如果测试过程中出现异常，但经确认**与当前代码修改无关**（如已有缺陷、环境问题、依赖兼容性等）：
  1. 当前可以**只关注自己的修改**，继续完成当前任务
  2. 但**必须记录该异常**（记录到 `docs/踩坑/` 或提交一个 Issue）
  3. **事后必须及时修复**，不得无限期搁置
  4. 在提交信息或 PR 描述中注明已知的遗留异常
  5. **修复后更新踩坑记录**

### 必须修复的异常
- 与当前修改直接相关的测试失败 → **必须先修复才能提交**
- 与当前修改无关但阻塞后续工作的异常 → **记录并排期修复**
- 新引入的编译错误或依赖冲突 → **必须先解决**

### 故意抛出的异常
- 测试用例中**故意抛出**的异常（如测试异常处理逻辑、预期异常断言）→ 正常，无需处理
- 需在测试代码中有明确的注释说明该异常是预期行为

## 提交策略

- 代码修改完成后，**一次性提交**完整的代码 + 文档变更
- 确保提交后的仓库处于可构建状态
- 每次提交应只包含一个功能变更

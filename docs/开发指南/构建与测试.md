# 构建与测试

> **何时阅读：** 构建项目、运行测试或打包 .app 前。

## 命令

```bash
cd NetworkMonitor

# 编译
swift build --disable-sandbox

# 测试（须显示「🎉 所有测试通过！」）
swift run --disable-sandbox TestRunner

# 打包部署（自动杀旧进程、复制到 /Applications、启动）
./Scripts/build-app.sh          # debug 模式
./Scripts/build-app.sh release  # release 模式

# 大文件门禁（在仓库根运行；单文件超 500 行 / 15360 字节即失败）
(cd .. && bash NetworkMonitor/Scripts/check-file-size.sh)
```

## 本机环境注意（无 Xcode 时）

**本机当前只安装了 Command Line Tools，没有 Xcode.app**，默认的 swiftbuild/XCBuild 后端在 session 初始化阶段就会失败：

```
SessionFailedError(... "Unknown error parsing property list")
```

**因此本机执行上面命令时，需要统一追加 `--build-system native`：**

```bash
swift build --disable-sandbox --build-system native
swift build -c release --disable-sandbox --build-system native
swift run --disable-sandbox --build-system native TestRunner
```

- 该故障与 `--disable-sandbox` 无关：带与不带都失败；本机只有 CLT 时默认后端必然初始化失败。
- 不是项目配置或代码问题：在干净 git 基线上同样复现。遇到时不要当成代码回归去回滚改动。
- 产物路径不变，仍是 `.build/arm64-apple-macosx/{debug,release}/NetworkMonitor`，`Scripts/build-app.sh` 的拷贝逻辑无需改动。
- `native` 引擎已被官方标记 deprecated，构建时会多一条 deprecation 警告，可忽略。
- 根治办法：安装 Xcode.app 后执行 `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`，或重装/升级 Command Line Tools；之后即可去掉 `--build-system native`。
- 详见 [swift build 会话初始化失败](../踩坑/构建/swift-build-会话初始化失败.md)。

## 测试约定

- 测试目标 `TestRunner`（手写断言，本机无 Xcode SDK，不用 XCTest）
- 新增测试：编辑 `Sources/TestRunner/main.swift`，使用 `assertEqual` / `assertNotNil`，失败 `exit(1)`
- 数据库测试用 `db.initializeInMemory()`（内存 SQLite，无需真实文件）
- 测试覆盖：Core 工具函数、Hook 事件解析、DatabaseManager（建表/迁移/清理/upsert）、TokenUsageProvider、HookEventDispatcher、AppEvents、货币时区配置

## 产物

- 可分发包在 `dist/NetworkMonitor.app`（已 .gitignore），部署目标 `/Applications/NetworkMonitor.app`
- 运行：`open /Applications/NetworkMonitor.app` 或 `swift run`

## 提交前流程（每次代码修改后）

```
① 大文件门禁 bash NetworkMonitor/Scripts/check-file-size.sh（在仓库根运行）
② 编译 swift build --disable-sandbox
③ 测试 swift run --disable-sandbox TestRunner
④ 打包 ./Scripts/build-app.sh（如需）
⑤ 提交（信息见提交规范）
```

> 提交前必须运行测试，修复所有失败用例。

### 大文件门禁 hook（可选安装）

把门禁挂到 pre-commit，提交时自动拦截超限文件（无需每次手动跑）：

```bash
# 在仓库根执行一次
git config core.hooksPath NetworkMonitor/Scripts/git-hooks
```

- 路径推荐用相对仓库根，换机器 / 换 clone 后仍直接生效。
- 关闭（恢复 git 默认钩子目录）：`git config --unset core.hooksPath`
- 临时跳过（不建议）：`git commit --no-verify`
- 门禁只读检查，不改文件；阈值可用 `CHECK_MAX_LINES` / `CHECK_MAX_BYTES` 覆盖。

# 提交规范

> **何时阅读：** 提交代码到 Git 前。

## 提交信息格式

```
<type>: <中文描述>
```

| Type | 使用场景 |
|------|---------|
| `feat` | 新增功能模块 |
| `fix` | 修复错误 |
| `docs` | 文档变更 |
| `refactor` | 重构（不改变行为） |
| `test` | 测试相关 |
| `chore` | 构建、配置等杂项 |

## 开发流程要求

1. **每功能一提交**：一个独立功能（含测试）完成并通过验证后立即单独提交，不攒批
2. **文档先行**：功能开发前先写设计/接口说明，确认后再编码
3. **提交前必须所有测试通过**
4. 计划/任务类临时文档**不得提交**

## 提交确认流程

- 提交前必须通过 `ask` 工具经用户确认，**禁止擅自 `git commit` / `git push`**
- 同一会话内用户确认过一次后，后续提交自动获得授权
- 展示变更清单（表格）→ `ask` → 按选择执行

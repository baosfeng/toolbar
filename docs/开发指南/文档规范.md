# 文档规范

> ⚠️ **何时阅读：** 当你需要创建、修改或删除项目文档时，必须先阅读本文档，了解文档结构、命名规则和渐进式加载约定。

## 语言要求

- 所有用户文档**必须使用中文**编写（包括标题、描述、表格内容）
- 代码标识符、关键字、报错信息等源码原文保留不译
- 技术术语首次出现时，可在括号内标注英文原文

## 目录与命名

- 所有文档统一放在 `docs/` 目录下
- 文档文件和目录名**必须使用中文**
- 文件名中不使用拼音或英文缩写
- `AGENTS.md` 位于项目根目录，不在 `docs/` 内

## AGENTS.md 规范

AGENTS.md 是 Reasonix 在每个会话启动时自动注入 system prompt 的文件，必须包含：
1. **项目标识**：项目名、版本号、语言、项目类型、技术栈
2. **项目简介**：一句话描述项目定位
3. **文档导航**：指向 `docs/` 中各关键文档的链接
4. **开发规范**：项目特有的开发规则

- AGENTS.md 是 **AI 的入口**，每个新会话自动加载
- `docs/索引.md` 是 **人类的入口**，更详细的文档导航
- 两者内容应保持一致：AGENTS.md 精简，索引.md 详细

## 目录生成规则

### 基线固化
- 首次全量扫描生成的目录结构即为基线，后续增量更新必须基于该基线
- 禁止在无重大重构的情况下更改已存在的目录结构

### 功能模块目录名生成规则

功能模块目录名必须保持固定映射：

| 源码路径 | 固定映射中文目录名 |
|---------|------------------|
| `com.example.user` / `user` | 用户系统 |
| `com.example.order` / `order` | 订单系统 |
| `com.example.payment` / `payment` | 支付系统 |
| `auth` / `security` | 认证系统 |
| `config` / `setting` | 配置中心 |
| `common` / `core` / `base` | 基础模块 |

### 子目录拆分规则

- 拆分阈值：核心类/子功能超过 3 个时拆分
- 拆分后，`概述.md` 作为入口索引各子目录文档
- 层级限制：不超过 2 层目录

## 文档结构与渐进式加载

- 每篇文档只聚焦一个主题
- 文档之间通过相对路径互相引用
- 禁止大而全的"万能文档"
- `AGENTS.md` 是入口，链接到各关键文档，所有文档按需加载

## 孤立文档禁令

- 每篇文档至少被索引或其他文档引用一次
- 新增文档必须同步更新索引
- 所有计划和任务类临时文档在文档体系中必须**孤立**

## 计划和任务类临时文档清理

所有规划和任务类临时文档（不限来源，包括但不限于 Superpowers 生成的）在任务完成后立即删除，不得残留。此类文档不得链接到正式文档。

## 代码示例规范

- Swift 代码使用 PascalCase 类名、camelCase 方法/变量名
- 使用项目版本支持的最新语法
- 注释使用中文编写

## 踩坑文档维护规范

- 踩坑按功能域组织，存储在 `docs/踩坑/` 下各子目录
- 每个踩坑条目一个文件，文件名使用中文描述
- 去重规则：相同 `file:line`（源码标记）或相同标题（执行踩坑）视为同一问题
- 踩坑反思在项目内完成，不在踩坑文档中展开

## ✅ 操作前自查清单

在创建、修改或删除文档前，请逐项确认：
- [ ] 文档文件名使用了中文
- [ ] 新增文档已在 `docs/索引.md` 或相关文档中添加引用链接
- [ ] 文档内容不构成孤立文档（至少有一条入链）
- [ ] 文档目录遵循了基线固化规则
- [ ] 如果文档是计划/任务类临时文档，完成后已删除
- [ ] 遇到报错时已先查看 `docs/踩坑/` 对应功能域是否有类似记录

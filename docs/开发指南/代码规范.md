# 代码规范

> ⚠️ **何时阅读：** 当你需要编写或修改代码时，必须先阅读本文档，了解编码风格、命名约定、推荐语法特性以及**必须遵守的架构设计原则**。

## 编码规范

### 命名约定

| 类别 | 规范 | 示例 |
|------|------|------|
| 类名 | PascalCase | `NetworkSpeedMonitor`, `MenuBarManager` |
| 方法名 | camelCase | `poll()`, `formatSpeedShort()` |
| 变量名 | camelCase | `downloadSpeed`, `totalRx` |
| 常量 | camelCase | `formatter`, `statusItem` |
| 枚举 case | camelCase | `.decimal`, `.useAll` |

### 代码风格

- **缩进：** 使用 4 空格（Swift PM 默认）
- **大括号：** 同一行左大括号（K&R 风格）
- **访问控制：** 优先使用 `private`，最小化公开 API
- **`@MainActor`：** UI 相关类标注 `@MainActor`，确保主线程执行
- **`final`：** 不打算继承的类使用 `final` 修饰
- **注释：** `// MARK: -` 用于代码分段

### 语言特性使用

- 使用 Swift 6 并发模型（`@MainActor`、`Task`）
- 使用 `let` 优先于 `var`
- 使用隐式返回值（单表达式函数可省略 `return`）
- 使用 `defer` 处理资源清理
- 使用 `guard let` 和 `if let` 处理可选值

### 注释规范

所有代码注释（包括行内注释、块注释、文档注释、TODO/FIXME 标记）**必须使用中文编写**；代码标识符、关键字、外部库名等源码原文保留不译。禁止中英文混杂、无意义注释和注释掉的代码。

## 架构设计原则（强制）

> 以下原则是项目架构审查（2026-08）后固化的硬性约束。**新增或修改代码时违反任一原则，Code Review 应拒绝合并。** 历史教训详见 `docs/踩坑/` 与 `~/Downloads/demo/架构重构复盘.md`。

### 1. 依赖倒置原则（DIP）

- **调用方只依赖协议，不依赖具体实现类**。例如 `TokenUsageProvider` 依赖 `any DatabaseService`，而不是 `DatabaseManager`
- **`AppCoordinator` 是唯一的组合根**，只有它允许创建具体实现（`DatabaseManager()`、`NetworkSpeedMonitor()` 等）并以协议类型注入下游
- 注入签名一律使用 `any 协议`（如 `any AppDatabase`、`any TrafficTrackingService`），禁止传具体类
- 反例教训：`TokenUsageProvider.init(database: DatabaseManager)` 曾依赖具体类，与同层 `StatsImporter` 风格分裂，已修复

### 2. 接口隔离原则（ISP）

- **一个协议只属于一个领域**。新增领域接口时新建协议文件（`Domain/Protocols/`），禁止往现有协议里追加无关方法
- 数据库能力按领域拆分，范例：
  - `DatabaseService` — 通用连接/查询（`initialize`/`query`/`close`）
  - `HookEventRepository` — Hook 事件领域（写流水/会话/工具调用）
  - `TokenUsageRepository` — Token 用量写入
  - `AppDatabase` = `DatabaseService & HookEventRepository & TokenUsageRepository`（组合根传递用）
- 调用方只依赖自己需要的窄协议；协议中的 `OpaquePointer` 等底层类型泄漏属于设计缺陷，应通过仓储方法封装

### 3. 单一职责原则（SRP）

- **单文件超过约 500 行或 15KB 时必须拆分**，禁止"上帝文件"
- 拆分范式：`DatabaseManager.swift`（连接/迁移/建表） + `DatabaseManager+HookEventRepository.swift`（仓储扩展） + `DatabaseManager+TokenUsageRepository.swift`
- 类扩展按协议组织：`extension DatabaseManager: HookEventRepository`，协议 conformance 声明在扩展文件而非类声明处
- 同模块扩展需访问类内部成员时，把 `private` 放宽为 internal 并注释说明原因（如 `db`/`serialQueue`）

### 4. SPI 扩展原则（可插拔扩展点）

- **新增事件处理逻辑** = 实现 `HookEventHandler`（`handledTypes` 声明事件类型，空集 = 全部）并注册到 `HookEventDispatcher`；**禁止修改** `ReasonixHookMonitor` 核心或 `handleReceivedData`
- **新增监控源/数据源** = 实现对应协议（`NetworkMonitoringService`/`TokenUsageRepository` 等），在组合根组装
- **新增事件类型** = 扩展 `ReasonixHookEventType` 枚举 + 注册新处理器，禁止在分发核心加 if 链
- 处理器按执行顺序注册：先落库 → 再工具调用 → 再通知 → 最后同步 stats

### 5. 基础设施注入原则

- **禁止直读 `UserDefaults.standard`**，必须通过 `KeyValueStorage`（经 `AppContext.shared.storage` 或注入）
- 反例教训：`CurrencyConfig` 曾直读 `UserDefaults.standard` 绕过注入体系，已改为可注入实例（`CurrencyConfig.shared` + `storageOverride`）
- 汇率等可配置项必须支持测试注入，测试不得污染全局 `UserDefaults.standard`

### 6. 事件驱动原则

- **数据变更 → 发布事件，UI 订阅刷新，禁止依赖轮询等待数据**
- 数据落库后调用 `AppEvents.postHookDataChanged()`，UI 通过 `NotificationCenter` 订阅并在主线程刷新（见 `MenuBarManager.observeHookDataChanges`）
- 轮询只用于低频兜底（如 15 秒 stats 刷新），事件到达时应立即刷新并重置节流计时

### 7. 日志规范

- **禁止 `print` 输出日志**（`ConsoleLogger` 实现内部除外）
- 统一通过 `LoggingService` 分级输出：错误 `logger.error`、警告 `logger.warning`、启动/关键信息 `logger.info`、高频调试 `logger.debug`
- 需要日志的组件在 init 注入 `logger: LoggingService = AppContext.shared.logger`

## 推荐语法特性

本项目使用 **Swift 6.3**，支持以下最新特性：

| 特性 | 说明 |
|------|------|
| Swift 6 并发 | 完整的数据竞争安全保证，`@MainActor`、`Sendable` 协议 |
| 非隔离 deinit | `nonisolated deinit` 支持 |
| 增强泛型 | 不透明类型（`some`）、存在类型（`any`） |
| 字符串增强 | 改进的字符串处理、Raw strings |
| 文档注释 | `///` 标记文档注释，支持 Markdown |
| Swift Testing | 新一代测试框架替代 XCTest（如适用） |

# 版本号管理

> ⚠️ **何时阅读：** 当你需要修改版本号或发布新版本时，必须先阅读本文档。

## 版本号格式

本项目采用**语义化版本（Semantic Versioning）** 规范：

```
主版本.次版本.修订号
```

示例：`1.0.0`、`1.2.3`、`2.0.0`

## 变更级别与版本号对应表

| 变更级别 | 版本号变更 | 触发场景 |
|---------|-----------|---------|
| 小改动 | 修订号 +1（如 1.0.0 → 1.0.1） | Bug 修复、微小优化、文档更新 |
| 中等改动 | 次版本 +1（如 1.0.0 → 1.1.0） | 新增功能、非破坏性 API 变更 |
| 大改动 | 主版本 +1（如 1.0.0 → 2.0.0） | 破坏性 API 变更、重大重构 |

## 当前版本号

**当前版本：** 1.1.0

版本号定义在 `Info.plist` 和 `build-app.sh` 的 `CFBundleShortVersionString` 中。

## 版本号管理操作流程

1. **运行全部测试** — 确认所有测试通过
2. **更新版本号** — 在构建文件中更新版本号
3. **编译验证** — 确认版本更新后编译通过
4. **提交代码** — 提交版本变更
5. **打版本标签** — `git tag v1.0.1`

## ✅ 操作前自查清单

在修改版本号或发布新版本前，请逐项确认：
- [ ] 我已确认变更级别（小/中/大）并计算了正确的新版本号
- [ ] 我已运行全部测试并确认通过
- [ ] 我已更新 CHANGELOG（如适用）
- [ ] 我已提交代码并打了版本标签

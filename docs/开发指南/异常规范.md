# 异常规范

> ⚠️ **何时阅读：** 当你需要处理异常、定义新异常或排查异常相关问题时，必须先阅读本文档。

## 核心原则

- **禁止异常混用：** 不同模块、不同层次的异常不得混用
- **禁止直接抛出 RuntimeException：** 必须定义明确的异常类型
- **基础服务 vs 业务应用异常区分：** 基础服务定义独立异常，业务应用统一使用 ServiceException

## 业务应用异常规范

本项目为 macOS 菜单栏应用（业务应用），遵循以下规范：

- 统一使用 `ServiceException` 或 `BusinessException` 处理业务异常
- 错误码应包含清晰的错误分类和描述
- 异常信息应包含足够的上下文用于排查

## 常见反模式

| 反模式 | 说明 | 正确做法 |
|--------|------|---------|
| 直接抛出 Error/String | 使用字符串作为异常 | 定义明确的异常类型 |
| 吞没异常 | catch 后不做任何处理 | 记录日志或重新抛出 |
| 过度细化异常 | 为每种场景定义不同的异常 | 适当归并，通过错误码区分 |

## 异常处理 Checklist

- [ ] 异常是否有明确的类型定义？
- [ ] 异常信息是否包含足够排查上下文？
- [ ] 是否已在文档中记录该异常的触发条件？
- [ ] 调用方是否能够正确处理该异常？

## ✅ 操作前自查清单

在处理异常或定义新异常前，请逐项确认：
- [ ] 我已确认异常类型归属
- [ ] 我没有直接抛出 RuntimeException/Error
- [ ] 我没有跨模块共用异常
- [ ] 业务层正确转换了底层异常

# Reasonix Hook 事件监听与 Token 监控

## 概述

通过 **Unix Domain Socket (UDS)** 接收 Reasonix AI 助手推送的事件，解析后写入本地 SQLite 数据库，并在菜单栏展示 Token 用量与 AI 分析统计。

- **通信方式**：`AF_UNIX + SOCK_DGRAM`，socket 路径 `/tmp/reasonix-hook.sock`
- **数据格式**：UTF-8 JSON（兼容 camelCase / snake_case 字段名）
- **存储位置**：`~/Library/Application Support/macMonitor/monitor.db`
- **货币单位**：金额统一以 **CNY（人民币）** 存储（侧车/stats 数据中的 USD 在写入前转换）

## 上游实现对照（DeepSeek-Reasonix）

上游 Reasonix 的 **token 统计不是通过 hook 实现的**：

- 上游 hook（`internal/hook/`）是 Claude Code 风格的 **shell 命令 hook**：事件触发时执行用户配置的外部命令，payload 通过 **stdin** 传入，退出码决定是否阻塞。**hook payload 中不携带 token/usage 数据**。
- 上游 token 统计走**进程内事件流**：`stats.Recorder`（passthrough 的 event.Sink）在 boot 层拦截 `event.Usage` / `event.TurnDone`，把每次模型调用的 token 用量以 JSONL 追加写入 `<state root>/stats/YYYY-MM-DD.jsonl`（每行一条 `{ts, model, source, prompt, completion, reasoning, cache_hit, cache_miss, total, turn}`）。
- 本地 UDS 监听器需要用户在 Reasonix `settings.json` 中配置 hook 命令把 stdin payload 转发到 socket（见下文「UDS 转发配置」）。

## Token 数据源（按优先级）

| 优先级 | 数据源 | 说明 |
|--------|--------|------|
| 1 | **官方 stats JSONL**（`~/.reasonix/stats/*.jsonl`） | **统计唯一权威来源**。reasonix 每次模型调用写入一条**增量**记录（`total` 为该次调用 token 数），文件按本地日期命名、`ts` 自带时区，SUM 当天文件即当天真实用量，无需任何时区偏移。菜单栏一级 Token、24 小时图、7 日历史、模型排行均由此驱动 |
| 2 | 会话侧车 telemetry（`<sid>.jsonl.telemetry.json`） | 仅用于会话维度展示（项目统计、通知增量），不再作为统计来源 |
| 3 | 事件 JSON 内嵌 `usage` 对象 | hook payload 兼容字段，仅作会话快照展示 |

> **历史数据说明（2026-08-04 清理）**：早期版本把会话**累计值**按事件时间归属日期，跨天会话的整段 token 被重复计入，且 SQL 时区偏移与 UTC 存储错位，导致统计虚高（如菜单栏显示 3180 万 vs 软件 1400 万）。已清空 `hook_events` / `hook_sessions` 历史数据（备份在 `monitor.db.bak-20260804-2230`），统计全部改由 stats JSONL 驱动后与 reasonix 软件口径一致。

## 与 reasonix 软件统计一致性

reasonix 自身统计面板读取同一份 `<state root>/stats/YYYY-MM-DD.jsonl`（`internal/stats` 包），本地菜单栏与之完全同源：

- **今日 Token** = 今日文件所有记录 `total` 之和（排除 `turn:true` 标记行）
- **按模型** = 按 `model` 字段分组求和
- **按小时** = 解析 `ts`（ISO8601 自带时区）取本地小时分组
- **按天历史** = 按文件名（本地日期）逐文件求和
- **花费** = hook 会话 per-session 累计 cost（stats 不记录金额，仅记录 token）

## UDS 转发配置

上游不会主动向 socket 推送数据，需要在 Reasonix 全局配置（`~/.reasonix/settings.json`）中配置 hook 命令，将 stdin payload 转发到 `/tmp/reasonix-hook.sock`。示例（使用 `socat`）：

```json
{
  "hooks": {
    "SessionStart": [{"command": "socat -u STDIN UNIX-SENDTO:/tmp/reasonix-hook.sock"}],
    "SessionEnd":   [{"command": "socat -u STDIN UNIX-SENDTO:/tmp/reasonix-hook.sock"}],
    "Stop":         [{"command": "socat -u STDIN UNIX-SENDTO:/tmp/reasonix-hook.sock"}],
    "StopFailure":  [{"command": "socat -u STDIN UNIX-SENDTO:/tmp/reasonix-hook.sock"}],
    "PreToolUse":   [{"command": "socat -u STDIN UNIX-SENDTO:/tmp/reasonix-hook.sock"}],
    "PostToolUse":  [{"command": "socat -u STDIN UNIX-SENDTO:/tmp/reasonix-hook.sock"}],
    "PostToolUseFailure": [{"command": "socat -u STDIN UNIX-SENDTO:/tmp/reasonix-hook.sock"}],
    "UserPromptSubmit": [{"command": "socat -u STDIN UNIX-SENDTO:/tmp/reasonix-hook.sock"}]
  }
}
```

> 注意：hook 命令的退出码会影响 Reasonix 行为（0=放行、2=阻塞，仅 `PreToolUse` / `UserPromptSubmit` 可阻塞），转发命令必须以 0 退出，避免意外阻塞 agent。

## 事件类型（13 种）

| 事件 | 说明 | 处理 |
|------|------|------|
| `SessionStart` / `SessionEnd` | 会话启动 / 结束 | 写入事件流水 + upsert 会话汇总（结束置 `ended`） |
| `Stop` / `StopFailure` | 轮次完成 / 失败 | 更新会话累计值；失败置 `failed`；弹系统通知 |
| `PreToolUse` | 工具调用前 | 建立 hook_tool_calls 记录 |
| `PostToolUse` / `PostToolUseFailure` | 工具调用后 / 失败 | 更新状态、耗时、结果预览 |
| `UserPromptSubmit` / `PermissionRequest` / `Notification` / `PostLLMCall` / `SubagentStop` / `PreCompact` | 其余事件 | 写入事件流水 |

## 数据表

| 表 | 用途 | 保留策略 |
|----|------|---------|
| `hook_events` | 事件流水（含 token/cost 快照） | 90 天自动清理 |
| `hook_sessions` | 会话汇总（session_id 主键，累计值取 MAX） | 180 天自动清理 |
| `hook_tool_calls` | 工具调用明细（耗时/结果/错误） | 90 天自动清理 |

## 菜单展示（Token 监控区）

- **一级菜单**：`Token: X | 花费: ¥Y`（今日汇总）+ 24 小时迷你柱状图
- **历史用量**（二级菜单）：近 7 日柱状图
- **AI 分析**（二级菜单）：
  - AI 实时动态：最近工具调用（状态/时间/耗时）
  - AI 工具统计：调用次数、成功率、平均耗时
  - AI 模型统计：各模型 Token 与花费排行
  - AI 项目统计：各项目 Token 与会话排行
  - AI 会话统计：活跃会话、今日总数、失败率、推理占比

## 轮次完成通知

`Stop` / `StopFailure` 事件触发系统通知：

- 显示项目名、轮次状态、本轮 Token 增量与花费（CNY）
- 增量 = 本次累计值 − 上次有效 Stop 累计值（内存缓存优先，重启后查库）
- 点击通知跳转会话文件；通知 5 分钟过期，最多保留 5 条

## 健康检查

每 30 秒检测 socket 文件是否存在，丢失时自动重建监听（stop + start）。

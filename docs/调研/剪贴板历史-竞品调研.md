# 剪贴板历史 · macOS 竞品功能调研

> 目的：为 toolbar（Swift 6.3 + AppKit 菜单栏 App）实现「剪贴板历史」提供功能边界、交互取舍与实现坑位依据。调研时间：2026-10；每个关键结论均附来源链接。

## 一、速览结论

1. 主流形态高度收敛：**菜单栏常驻 + 全局热键唤起浮层 + 键盘优先**（输入即搜、↑↓ 选择、⏎ 粘贴）。Paste、Maccy、Raycast、CleanClip、Alfred 无一例外，**没有任何一家用「双击 Shift」**（那是翻译类工具的惯例）。
2. 差异化只剩三处：**浮层位置/形态**（Paste 是"屏幕底部通栏"）、**顺序粘贴 Paste Stack**（Paste/Maccy/Raycast/CleanClip/Pastebot/OneClip 都有）、**OCR 可搜索**（Paste/Raycast/OneClip）。
3. 真正的门槛在**权限与隐私体验**：macOS 15.4 起"程序化读取剪贴板"会触发系统授权弹窗并把 App 加入系统设置面板；自动粘贴需要辅助功能（Accessibility）权限。做不好直接变差评来源。
4. macOS 26 Tahoe 起系统自带 Spotlight 剪贴板历史（Apple 支持文档），基础能力已被系统吃掉，产品必须靠容量、搜索、Stack、OCR 拉开差距。

## 四、「桌面底部浮起」谁在做（C）

- **Paste 是唯一的底部通栏正面案例**：官方帮助明确「The Paste window sits as a bar across the bottom of your screen」，多显示器时在"你正在工作的那块屏"打开且不可固定屏幕，可拖上缘调整高度、窗口变小自动切 Compact Mode。横向时间轴 + 左右方向键浏览是它的标志性交互。
- **鼠标/输入光标处**：CleanClip「Pop up near the input cursor，拒绝上下文切换」、PasteNow「在鼠标光标处展示」、Pastebot 的 quick paste menu 也在指针处、Maccy 可配到 cursor。
- **居中面板**：Raycast、Alfred（与启动器共用肌肉记忆）。
- **可配置派**：Maccy 一次给了 5 个位置（鼠标/菜单栏图标/窗口中心/屏幕中心/上次位置），说明这块没有标准答案。
- **对比**：底部通栏优点是全宽可视、一眼看到多条、不遮挡正在输入的文本区上方、横向时间线符合"最近在最左"的阅读直觉；缺点是占满屏宽、容易和 Dock/输入法候选栏/浏览器底栏打架，多屏与全屏 App 需额外处理。居中面板优点是搜索框大、与启动器一致的视觉语言；缺点是键盘旅程长、直接压在正文上。**建议**：位置做成可配置（默认"鼠标所在屏底部"，同时提供"鼠标光标处"），比一次赌死一个位置更稳。

## 五、实现层关键坑（D）

1. **changeCount 轮询 vs 通知**：macOS 没有公开的剪贴板变更通知 API，只能轮询 changeCount。Maccy 用 Timer 默认 **500ms** 轮询，并提供 defaults 键可调（README「Speed up Clipboard Check Interval」）；其实现里先比较 changeCount 相同即 return，读类型/数据前先做忽略判定，并用一个私有类型标记"这次复制是我自己写的"以避免自激循环。
2. **macOS 15.4+ 的剪贴板隐私弹窗**（最容易翻车）：新增 NSPasteboard.AccessBehavior，**General pasteboard 默认就是"程序化访问时询问"**，其它 pasteboard 默认 alwaysAllow；首次程序化访问触发系统弹窗后，App 才出现在系统设置里，用户可切 ask / alwaysAllow / alwaysDeny；**用户主动发起的粘贴类访问永远放行、不弹窗**。实践含义：把读取尽量收拢到"用户动作驱动"的路径，避免空转轮询造成弹窗风暴（同类事故可参考这个 bug 报告）。另外 macOS 26.4 起 Terminal 粘贴恶意命令也会被拦截并弹窗（Apple 支持文档 / IT之家）。
3. **密码与敏感内容要按 nspasteboard.org 约定过滤**：org.nspasteboard.TransientType / ConcealedType / AutoGeneratedType，以及 com.agilebits.onepassword、com.typeit4me.clipping、com.apple.is-remote-clipboard（通用剪贴板）等标记类型；Maccy 的默认忽略清单就是这么来的。
4. **自动粘贴 = 辅助功能权限**：Maccy 用 AXIsProcessTrustedWithOptions(nil) 检查（Accessibility.swift），粘贴时用 CGEvent 合成 ⌘V 投到 .cgSessionEventTap，并要显式设置 flags、用 setLocalEventsFilterDuringSuppressionState 抑制本地键盘事件，还要处理 Dvorak 等键盘布局与"非合并 flag"细节；无权限时业界标准做法是**降级为"只复制"并用文案引导**（Paste 帮助页明确这么写）。
5. **非激活面板如何拿到键盘焦点**：浮层用 NSPanel + [.borderless, .nonactivatingPanel] + orderFrontRegardless()（不抢 App 激活）；要在浮层里打字搜索就必须 canBecomeKey = true 接管键盘，或 becomesKeyOnlyIfNeeded；首次点击会被面板吞掉去"抬升窗口"，需子类化 NSHostingView 覆盖 acceptsFirstMouse = true；按鼠标锚定时记得 clamp 到 visibleFrame 防越界。**若浮层需要在粘贴期间保持可见，则绝不能成为 key window**，否则合成的 ⌘V 会落回自己的浮层而不是目标 App（这是"看着成功但没粘上"的根因）。
6. **图片内存与去重**：一条历史往往同时含 string/RTF/HTML/PNG/TIFF 多份 Data，应按 (type, data) 存原始字节、缩略图另存缓存；写入时先用"自己写的标记类型"挡住回环；多个 pasteboardItems（BBEdit、Edge 复制会塞 2 项）要合并成一条记录；macOS 15 之前还必须在创建后立刻落库。
7. **全局热键选型**：Carbon RegisterEventHotKey 是唯一**不需要辅助功能权限**的公开全局热键 API，但只支持「修饰键 + 单键」且必须在主线程注册与跑事件循环；CGEventTap 能力更强但要权限、可拦截改写键盘事件。**结论：唤起用 Carbon（Maccy 走 KeyboardShortcuts 库，底层即 Carbon），只有 ⌘V 合成才用 CGEvent**。冲突检测：热键被系统占用时只能在「系统设置 → 键盘 → 键盘快捷键」里关掉旧占用（Maccy FAQ 原文如此）；另外在密码输入框里，产生字符的热键（如 ⌥C）会被系统安全机制屏蔽。

## 六、优先级建议（E）

**MVP（必须有）**：菜单栏常驻 + Carbon 全局热键；changeCount 500ms 轮询 + 自激标记；文本/图片/文件三类落库（SQLite/Core Data）；输入即搜的模糊搜索；↑↓ + ⏎ 复制（先做"复制"，不做自动粘贴）+ ⌘1–9；Pin；单项删除 + 清空；容量上限设置；忽略 Concealed/Transient/AutoGenerated 类型 + App 黑名单；悬浮面板（NSPanel 非激活 + acceptsFirstMouse + 位置 clamp）。
理由：这十条就是 Maccy 的全部价值，也是所有产品的共同交集；不先做这块，后面所有亮点都没有落脚点。

**第二阶段（做完 MVP 再上）**：自动粘贴（⌥⏎）+ 辅助功能权限引导与降级文案；去格式粘贴；缩略图/预览面板；排序（时间/次数）+ 多选批量删除 + 按时间清理；浮层位置可配置（底部通栏 / 鼠标处 / 居中）；按类型过滤；开机自启与深色模式跟随。
理由：这些是"从能用变好用"的分水岭，但都依赖前一步的权限引导与面板基础；权限文案写不好会让首次体验直接崩。

**可选亮点（差异化）**：Paste Stack 顺序粘贴（实现成本低、体感强，Maccy/Raycast/CleanClip 都已验证）；OCR 可搜索 + 二维码解析（Vision 框架成本低，是 Raycast/Paste 的杀手锏）；Snippets 与智能列表；富文本/颜色类型的完整保留与 Paste as 子菜单；iCloud/局域网同步（国产工具的主战场）；AI/MCP 集成（Paste 与 Raycast 的新叙事）。
理由：按"实现成本 ÷ 用户可感知度"排序，Stack 与 OCR 性价比最高；同步与 AI 属于后期叙事，且会引入隐私合规成本。

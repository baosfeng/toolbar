# 剪贴板对标 OneClip 调研结论

> 目的：为「参考 One-Clip/OneClip 优化本项目剪贴板」提供可复核的对标证据；只记录核实过的结论，不做产品决策。
> 基线：OneClip 开源部分 `src/OneClip/`（快照提交 `65926e3`，2026-10-16）；本项目 main @ `1f32383`。
> 配套设计：[剪贴板对标 OneClip 增量设计规格](../设计/剪贴板对标-OneClip-增量设计规格.md)

## 1. OneClip 现状（逐条带证据）

### 1.1 数据模型与存储

- 9 类内容类型枚举 `text / image / file / video / audio / document / code / archive / executable`，**无 color 类型**（`ClipboardItem.swift:3-13`）
- RTF / HTML 不独立成 type：抽纯文本存为 `type = .text`，原文放 `data`（`ClipboardManager.swift:560-590`）
- 字段仅 7 个 `id / content / type / timestamp / data / filePath / isFavorite`（`ClipboardItem.swift:63-70`）；**无来源应用、无 bundleID**（全库无 `frontmostApplication` 取证）
- `content` 上限 10000 字符硬截断（`ClipboardManager.swift:1935-1936`）
- 存储不用 SQLite：`~/Library/Application Support/OneClip/<yyyy-MM-dd>/items.json`（目录与格式化见 `ClipboardStore.swift:31-35, 42-45`，日期目录见 `:54-66`，读写见 `:122-126, 196-218`）
- CoreData 模型 `ClipboardDataModel.xcdatamodeld` 存在，但全库无 `NSPersistentContainer` / `NSManagedObject` 引用 = 未接线的死模型
- 容量口径互相打架：`ClipboardStore.maxItems = 100`（`ClipboardStore.swift:13`）vs `SettingsManager.maxItems = 50`（`SettingsManager.swift:29, 60`）；500MB 上限（`ClipboardStore.swift:17`）对应的 `cleanupLargeStorage` **全库只有定义无调用点**（`ClipboardStore.swift:371`）
- 按天目录清理：每小时一次 timer，按目录创建时间删过期目录（`ClipboardStore.swift:343-369`）
- 落盘在后台任务里，但每次保存都「按日期分组重写整份 `items.json`」（`ClipboardStore.swift:196-218`），写放大且无版本号 / CAS

### 1.2 捕获与去重

- 双通道：`DistributedNotificationCenter` 监听 `com.apple.pasteboard.changed`（`ClipboardManager.swift:132-140`）+ Timer 轮询 `changeCount`（`ClipboardManager.swift:143-145`）
- 间隔按用户活跃度动态切换 0.6s / 2.0s / 5.0s（`ClipboardManager.swift:57-60`，切换实现 `:430-442`）
- `changeCount` 判变 + 200ms 防抖（`ClipboardManager.swift:444-474`，防抖阈值在 `:461`）
- 去重键用 Swift `hashValue`（进程随机种子，**跨会话不稳定**）（`ClipboardManager.swift:2927-2975`，另有 `:978, 1690, 1940, 2003`）
- 结构去重：最新项相同、或前 5 项任一相同即跳过（`ClipboardManager.swift:1723-1745`）
- 重复的时间窗处置：图片 30s 内丢弃、文本 300s 内丢弃，超出则删旧项 + 插到列表头（`ClipboardManager.swift:1939-1975`）
- **隐私过滤完全没有**：全库无 `org.nspasteboard.ConcealedType` / `TransientType` / `AutoGeneratedType` 引用

### 1.3 粘贴链路

- 写回用 `clearContents` → `setString` / `setData`；图片一次写 TIFF + PNG + JPEG 三种格式提兼容（`ClipboardManager.swift:2138-2149`）
- 合成 ⌘V：`CGEvent` keyCode 9 + `.maskCommand` + `.cghidEventTap`（`ContentView.swift:778-803`）
- 自身操作免疫：标志位 `isPerformingCopyOperation` + 2s 时间戳窗口（`ClipboardManager.swift:2062-2081`），外加 restore 后 `lastChangeCount` 对齐（`ClipboardManager.swift:3122`）
- 权限：`AXIsProcessTrusted`（`AccessibilityPermissionManager.swift:49, 67, 113`）
- **栈粘贴不存在**：菜单栏「快速粘贴功能已删除」注释（`OneClipApp.swift:699`），`showQuickPasteSelector` 全库只有定义（`OneClipApp.swift:1495`）无调用点

### 1.4 编辑与再加工

- **无 OCR、无 AI、无脚本**：全库零 `Vision` 引用
- 可低成本借鉴的纯剪贴板侧能力：文件类型分类器（`ClipboardManager.swift:647-740`，分派在 `:720-740`）、图片魔数快速探测（`:1707-1719`）、图片三格式回写（`:2138-2149`）

### 1.5 面板与交互

- 面板是普通 `NSWindow`：`hidesOnDeactivate = false`、`level = .normal`、`collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary]`（`WindowManager.swift:68-70`）——**会抢焦点**，不是 non-activating panel
- 全局热键唯一：Ctrl+Cmd+V（`HotkeyManager.swift:24-31`）
- 键位：Esc 隐藏、⌘1–9 复制第 n 项、Enter 复制选中、⌘Delete 删除（二次确认）、↑↓ 循环导航（`ContentView.swift:566-705, 710-737`）
- 搜索是分词 AND 子串（`ClipboardManager.swift:3034-3048`），无打分；带打分的 `searchItems`（`:3156-3199`）**无调用点**

### 1.6 性能工程

- 图片流水线是这份实现里做得最好的部分：`Semaphore(3)` 并发上限 + QoS 匹配防优先级倒置 + 活跃加载去重（`ClipboardManager.swift:3405-3468`）；`NSCache` 容量与单张计费封顶（`:33-38, 3363-3378`）
- 内存压力双路响应：thermalState + `DispatchSource.makeMemoryPressureSource`（`ClipboardManager.swift:2853-2897`）
- 缓存清理 20 分钟一次、30 分钟不活跃跳过、hash 记录 2 小时清空（`ClipboardManager.swift:2799-2820, 2814, 2830-2835`）

## 2. 对比结论

### 2.1 本项目已领先、保持现状的项

结论与逐项对照口径冻结在[设计规格第 2 节](../设计/剪贴板对标-OneClip-增量设计规格.md)，此处只记 OneClip 侧的缺口证据：

- **隐私过滤缺失**：无 Concealed / Transient / AutoGenerated 任何引用（本项目为五级优先判定，`ClipboardContentHasher.swift:56-67`）
- **去重键不稳定**：`hashValue` 用进程随机种子（本项目为 SHA256，`ClipboardContentHasher.swift:97-151`）
- **存储无 schema 版本**：按日期分目录 JSON 全量重写（本项目为 SQLite + `user_version` 迁移）
- **无栈粘贴**：`showQuickPasteSelector` 无调用点
- **面板抢焦点**：`.normal` 普通窗口
- **搜索无打分**：分词 AND 子串，`searchItems` 为死代码

### 2.2 本项目采用的三项增量（详见[设计规格](../设计/剪贴板对标-OneClip-增量设计规格.md)）

1. **图片磁盘回收（P0）**：本项目 `ClipboardImageStore` 只有写入路径（`ClipboardImageStore.swift:16-101`），删除 / 清空 / 清理都只删 DB 行（`DatabaseManager+ClipboardRepository.swift:182-301`），图片目录只增不减；OneClip 至少有按天目录清理（`ClipboardStore.swift:343-369`）。
2. **采集器动态轮询 + 变更通知（P1）**：对标 `ClipboardManager.swift:57-60, 132-145` 的双通道与动态间隔，降低空闲期功耗、缩短复制到入库的延迟。
3. **文件条目类型细分（P2）**：对标 9 类内容类型枚举（`ClipboardItem.swift:3-13`）与文件分类器（`ClipboardManager.swift:720-740`），提升多文件条目的卡片识别度。

### 2.3 明确不做

多选批量操作、富文本 / HTML / 颜色完整保留、OCR 可搜索、Snippets 片段库、多端同步、复制次数排序、搜索高亮——理由逐条见[设计规格第 4 节](../设计/剪贴板对标-OneClip-增量设计规格.md)。

**结论：真实待处理告警 43 条 + 环境限制 1 条。**其中可修 11 类 / 27 条诊断属零风险机械修复，需决策 16 条（16 类文本）涉及并发语义。

### 为什么 1447 ≠ 43

同一 `file:line:col` 在 debug 日志里被重复打印 10–25 次，是构建数据库对上次诊断的重放，不是独立告警：

- debug 构建复用工作区既有 `.build`（`swift package clean` 之后仍如此），每个 site 重复 10–25 次；
- release 构建用全新 `--scratch-path /tmp/warn-release-build`，**每个 site 恰好出现 1 次**（39 个 site → 39 行诊断头）。

因此统计一律以「`file:line:col` + 文本」去重，不看原始行数。

## 五、修复顺序建议

1. **第一批（零风险，27 条诊断）**：`clipExec` 加 `@discardableResult` → `withCString`/`saveImage` 补 `_ =` → 删 7 处不可达 `return` → 删 4 处多余 `try` → 删死变量 `previous`、`delay` 改判空、`defaults` 改 `let`、删冗余 cast、`TransferMotion` 去掉 2 处 `nonisolated(unsafe)`。这批每步跑 `swift run --disable-sandbox --build-system native TestRunner` 应全绿，对行为零影响。
2. **第二批（deprecated API，2 条）**：`init(cString:)` 两处改成按 `length` 截断再解码——顺带修掉「忽略返回长度」的潜在尾随垃圾问题。
3. **第三批（并发语义，需拍板）**：`SystemMonitor.swift:183` → `ClipboardThumbnailLoader.swift:82` → `SnipFailureNotice.swift:72/73` → `TransferMotion.swift:50`。这 4 处都在后台/回调上下文触碰主 actor 成员，改完必须打包 .app 实测（面板打开速度、贴图动效、提示窗自动关闭）。
4. **第四批（debug-only）**：`TokenRowViews.swift:269` 的 4 条，随 DEBUG 快照自证链路一起改，只需 debug 构建 + 离线快照验证。
5. **第五批（测试基建）**：6 处 `@Sendable` 回调改 `var` 的并发告警，需先定测试隔离方案再动手。

## 六、复跑命令

~~~bash
cd .worktrees/warn-scan/NetworkMonitor
swift package clean
swift build --disable-sandbox --build-system native 2>&1 | tee /tmp/warn-build.log

# release（独立 scratch，避免与 debug 抢 .build）
swift build -c release --scratch-path /tmp/warn-release-build \
  --disable-sandbox --build-system native 2>&1 | tee /tmp/warn-release.log

# 去重统计（权威口径）
grep -E '^[^ |].*:[0-9]+:[0-9]+: warning: ' /tmp/warn-build.log \
  | sed -E 's#^.*/NetworkMonitor/(Sources/[^:]+):([0-9]+):([0-9]+): warning: (.*)$#\1:\2:\3\t\4#' \
  | sort -u
~~~

采集环境：Swift 6.4（swiftlang-6.4.0.34.1）、Target arm64-apple-macosx27.0.0、仅 Command Line Tools；debug 构建 67.37s、release 107.87s。

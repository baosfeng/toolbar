| 项 | 现状 | 判断 |

### 2.4 动效与刷新：一个 Timer 驱动一切，无 displayLink

- `CADisplayLink` / `CVDisplayLink`：**全仓 0 命中**。
- 动画全部是一次性 AppKit 动画：`NSAnimationContext`（MotionKit 4 处 + TransferMotion 3 处 + Snip 2 处 + ClipboardPaster 1 处）、`CABasicAnimation/CAKeyframeAnimation`（TransferMotion 5 处 + BillingRefreshButtonRow 1 处）。`override func draw` 出现在约 50 个视图文件，但都是数据变化触发 `needsDisplay` 重绘，无逐帧推进。
- **两套同口径动效实现并存**：`Motion/MotionKit.swift:13-270`（主用）与 `Transfer/TransferMotion.swift:10-25`（互传存量）。时长表完全一致（state .12 / expand .34 / overlay .22 / close .15 / stagger .024），`isEnabled` 都读 `accessibilityDisplayShouldReduceMotion`。
- **刷新节拍全由单个 Timer 派生**：`MenuBarManager.swift:261-276` `setupTimer(interval:)` 周期来自 `menuBar.refreshInterval`（`MenuBarDisplayPreferences.swift:115-121`，钳 1...10s，默认 1s，钳制逻辑在 `NetworkMonitorUI/MenuBarDisplayLogic.swift:53-56`）。同一个 Timer 调 `MenuPanelController.tick()`（`MenuPanelController+Open.swift:83-99`）：
  - 1 秒：实时速率 + 折线采样（`maxHistory = 60`，`MenuPanelController.swift:88`）
  - 5 秒：中频（`midInterval = 5.0`，`MenuPanelController.swift:90`，判定在 `+Open.swift:96`）今日流量 / 近 6 日柱 / 进程 / 额度
  - 事件驱动：剪贴板（`AppEvents.clipboardChanged`）
  - 打开时：`refreshAll()` 强制全量 + 一次预热（`prewarmPanelIfNeeded`，`+Open.swift:47-69`）
- 另有独立档位：`systemMonitor.sampleInterval`（`SystemMonitorPreferences.swift:26-30`，钳 0.5...5s，默认 1s）。
- **无任何帧率 / 性能档位开关。**

### 2.5 macOS 26/27 新 API：可用、未用

SDK 实测（`xcrun --show-sdk-version` → 27.0，`NSGlassEffectView.h` Copyright 2025）：

| API | 可用版本 | 仓库引用 |
|---|---|---|
| `NSGlassEffectView`（`.regular` / `.clear`、`contentView`、`cornerRadius`、`tintColor`、`style`） | macos(26.0) | 0 |
| `NSGlassEffectView.effectIsInteractive`（交互视觉反馈） | **macos(27.0)** | 0 |

**关键否定结论**：`NSVisualEffectView.h` 是 `Copyright 2014-2024`，material 枚举到 `.underPageBackground` 为止，**26/27 没有新增 material case**。所以「玻璃拟态」只能在 `NSGlassEffectView` 上做，不能在现有 `NSVisualEffectView` 上「换个材质」拿到 Liquid Glass。

`Package.swift:7-9` 现为 `.macOS(.v14)`。`NSGlassEffectView` 需 26.0，直接抬到 26 会砍掉 14/15 用户。

### 2.6 三条会卡住实现的约束

1. **主面板不用材质是用户实测打回的结论**（`MenuPanelView.swift:29-31`）。加玻璃必须给面板底垫不透明基色，否则 10.5pt 文字对比度不足会二次返工。
2. **毛玻璃在离屏快照里不可辨**（`docs/踩坑/运行时/毛玻璃材质离屏不可辨.md:17-33`）：模糊由窗口服务器合成，`cacheDisplay` 只走视图自绘，材质层退化成「近似底色 + 无模糊」，实测像素从 255 变 228 而肉眼无差。验收必须三判据组合：**结构自证（material / blendingMode / state / cornerRadius / 内缩 / hitTest）为主 + 像素旁证 + 真机确认**，不用离屏数值调参。
3. **Core 不能 import AppKit**（编码规范）。色值表留在 Core（可算 WCAG 对比度，`SystemPaletteContrast.swift` 已有能力），`NSColor` 转译留在 UI 层——主题模型必须保持这个分层。

## 三、改造方案

### 3.1 令牌层：Theme 模型

**分层落点**（新增文件）：

| 文件 | 目标 | 内容 |
|---|---|---|
| `NetworkMonitorCore/Appearance/ThemeTokens.swift` | Core | `ThemeID` 枚举、`ThemeRole` 语义角色枚举、每主题 × 浅/深一张 hex 表（复用 `SystemPaletteRGB`） |
| `NetworkMonitorCore/Appearance/ThemeCatalog.swift` | Core | 主题定义 = 色表 + 材质配方 + 几何 + 玻璃强度 |
| `NetworkMonitorCore/Appearance/AppearancePreferences.swift` | Core | 键 `appearance.theme` / `appearance.glass` / `appearance.renderTier`，带钳制与缺键回落 |
| `NetworkMonitorCore/Appearance/ThemeContrast.swift` | Core | 对每个主题 × 外观断言正文/次要文字对比度 ≥ 4.5、图形 ≥ 3.0 |
| `NetworkMonitorUI/RenderTierLogic.swift` | UI 纯逻辑 | 档位 → 全部参数的纯函数（可被 TestRunner 断言） |
| `MenuPanel/ThemeStyle.swift` | UI | `ThemeStyle.color(_ role:)` → `NSColor(name: nil) { appearance in … }`，沿用 `PaneCardStyle.dynamic` 的动态解析写法 |
| `MenuPanel/GlassStyle.swift` | UI | 三层玻璃的材质组合构造器（见 3.2） |
| `MenuPanel/PaneCardStyle.swift` | UI | **改为转发 `ThemeStyle`**，保留全部现有同名成员 —— 331 处调用点零改动 |
| `Settings/SettingsAppearancePane.swift` | UI | 设置页「外观」分类：主题选择 + 玻璃强度 + 帧率档 |
| `Infrastructure/AppEvents.swift` | Core | 新增 `appearanceChanged` / `renderTierChanged` |

**Theme 模型字段**（题目要求的七项）：

```swift
public struct Theme {
    public let id: ThemeID
    public let displayName: String
    /// 语义色：每个角色浅 / 深各一套（Core 里只有 hex，不碰 NSColor）
    public let colors: [ThemeRole: (light: UInt32, dark: UInt32)]
    /// 玻璃配方（三层的材质与强度）
    public let material: MaterialRecipe
    public let cardRadius: CGFloat        // 圆角
    public let cardPaddingX: CGFloat      // 内距
    public let cardPaddingY: CGFloat
    public let strokeWidth: CGFloat       // 描边
    public let strokeRole: ThemeRole      // 描边色角色
    public let shadow: ShadowRecipe       // 阴影 (radius, dy, opacity)
    public let glassStrength: Double      // 玻璃强度 0...1
}
```

**语义角色（`ThemeRole`）建议最小集**：`surface / cardFill / bandFill / track / trackStrong / hairline / grid / textPrimary / textSecondary / textTertiary / accent / ok / warn / danger / family1… family4 / family1Fill… family4Fill`。这样 `PaneCardStyle.cardFill`、`SystemPalette.cpu`、`SettingsStyle.cardBackground` 都能映射到同一张表，五套颜色表收敛成一套「角色 × 主题 × 外观」。

**改造顺序（重要）**：先建 `ThemeStyle` 并把 `PaneCardStyle` 改成转发，**默认主题 = 现值原样**（23 对 dynamic 值与 54×2 hex 原值搬进 `ThemeCatalog`），保证第一步 diff 的渲染结果零变化；之后再逐个主题加色表。

### 3.2 玻璃拟态：三层材质组合

> **推荐组合（一行）**：面板 `NSGlassEffectView(.regular, cornerRadius 12, tintColor <theme.panelTint>)` + 内衬 `NSVisualEffectView(.underWindowBackground, .behindWindow, .active, 圆角 10 / 内缩 1pt / hitTest nil)`；卡片不引入额外合成层，靠 `cardFill@0.72` + 顶部 1pt 高光 + 0.5pt 半透明描边；弹窗 `NSGlassEffectView(.regular, effectIsInteractive: true)`，同屏多个玻璃套 `NSGlassEffectContainerView(spacing: 0)` 批量合并。

| 层 | 载体 | 材质组合 | 关键取舍 |
|---|---|---|---|
| **面板** | `MenuPanelView`（`MenuPanelView.swift:170-173` 现为不透明底）；剪贴板面板已有内衬 `ClipboardPanelInnerMaterialView` | macOS 26+：`NSGlassEffectView(style: .regular, cornerRadius: 12)`，`tintColor` 取主题 panelTint（alpha 由 `glassStrength` 定 0.10 / 0.06 / 0.03），`contentView` 装现有内容栈；**下面垫一层不透明 `theme.surface` 基色**（alpha 0.86~0.92）。macOS <26 回落 `NSVisualEffectView(.hudWindow, .behindWindow, .active)` + 现不透明底 | 大面玻璃强度最高；基色层是 `.popover` 材质打回那次的直接补救，保证 282pt 内宽下 10.5pt 文字 ≥ 4.5:1 |
| **卡片** | `PaneCardBackgroundView.swift:43-47`、`MenuPanelRows.swift:254-259`（两个都在 `draw` 里画实色面） | 不用 `NSGlassEffectView`（一屏十几张卡，pass 成本高）。改画三层：① `cardFill.withAlpha(glassFillAlpha)` 半透明底（1.0 / 0.86 / 0.72）② 顶部 1pt 高光线（浅色 `white@0.55`、深色 `white@0.12`，只画上半 1pt）③ 0.5pt 半透明描边（`labelColor@0.10`），可选内阴影 1pt | 卡片玻璃靠「半透明 + 高光边 + 描边」模拟，零额外合成层 |
| **弹窗** | 设置窗口 `SettingsWindow.swift:40-49`（现为普通 `.titled` 窗口 + `SettingsSurfaceView`）；剪贴板面板窗（`.hudWindow`）；传输 sheet（`TransferScanSheet` / `TransferPairingSheet`） | macOS 26+：`NSGlassEffectView(style: .regular, effectIsInteractive: true)` 包内容；设置窗口 root 的 `SettingsSurfaceView` 换成 `GlassSurfaceView`；同屏多个玻璃用 `NSGlassEffectContainerView(spacing: 0)` | `effectIsInteractive` 只给带交互控件的弹窗（设置页 / 传输 sheet），纯展示面板设 false 省开销 |

**玻璃强度三档**（`glassStrength`）：0（关）= cardFill alpha 1.0 / 高光 0 / 面板走 `.withinWindow`；0.5 = 0.86 / 0.35；1 = 0.72 / 0.55 + `effectIsInteractive`。

**验收方式（必须照 §2.6 约束 2）**：材质改动不以离屏图定论。结构自证探针直接编译真实源文件，断言「`material` / `blendingMode` / `state` / `cornerRadius` / 内缩量 / `hitTest == nil` / 层级顺序」；像素只用来证材质边界存在；真机复核观感与色调差。对比度用 `SystemPaletteTokens.contrastRatio` 算，不靠肉眼。

### 3.3 帧率三档

**口径先说清**：本项目无 displayLink、无逐帧动画（§2.4），所以「帧率档」落成**刷新节拍 + 动画开关 + 玻璃开关 + 图表重采样上限**四件事，不是 vsync 档位。

| 维度（落点） | 标准（默认） | 极致 | 省电 |
|---|---|---|---|
| 状态栏 + 面板 tick 周期（`menuBar.refreshInterval`） | 1.0s（现默认，钳 1...10） | **0.5s** | **2.0s** |
| 面板中频节流（`MenuPanelController.midInterval`） | **5.0s**（现值） | **2.0s** | **15.0s** |
| 系统采样（`systemMonitor.sampleInterval`） | **1.0s**（现默认，钳 0.5...5） | **0.5s** | **3.0s** |
| 折线历史点数（`maxHistory`） | **60**（现值） | **120** | **30** |
| 动效（`MotionKit`） | 全量播放，现时长表 .12 / .34 / .22 / .15 / .024 | 全量播放，`expand` 抬到 .40、`stagger` .024 | **全部落终态**（等价 `isEnabled = false`） |
| 玻璃材质 | 面板玻璃 + 卡片半透明 | 同标准 + `effectIsInteractive = true` | **玻璃关**：卡片回不透明实色、面板走 `.withinWindow`（不做窗口后模糊） |
| 面板预热（`prewarmPanelIfNeeded`） | 做一次 | 做 | **不做**（省一次首帧开销，代价是首次打开回到 ~375ms） |
| 图表重绘上限 | 24 桶 / Top 8 / `sparkWidth 54` | 全量 | 24 桶降 **12 桶**（两桶合一的降采样）/ Top 8 降 **Top 4** / `sparkWidth` 54→40 |
| 面板收起时 | 只刷计费（`tick()` 现状 `+Open.swift:87`） | 同标准 | 面板收起时 tick 全停，计费改 60s 独立定时器 |

**实现要点**：

- 参数表放 `ThemeCatalog` 同目录的 `RenderTier` 结构体，纯函数在 `NetworkMonitorUI/RenderTierLogic.swift`，字段：`tickInterval / midInterval / sampleInterval / historyPoints / motionEnabled / motionDurations / glassEnabled / effectInteractive / prewarm / chartBuckets / rankingLimit / sparkWidth`。
- **档位覆盖用户单旋钮，不叠加**：建议 `RenderTier` 直接给最终值，设置页把「刷新周期」标注为「由帧率档接管」，避免两套旋钮互相打架。合成规则写成纯函数 `RenderTierLogic.resolved(tier:userRefreshInterval:)` 便于断言。
- 生效链路照 `menuBarDisplayChanged` 模式：写存储 → `AppEvents.postRenderTierChanged()` → `MenuBarManager.applyDisplayPreferences()` 重建 Timer（复用 `MenuBarDisplayLogic.needsTimerRebuild`）+ `MenuPanelController` 刷新中频节流 + `MotionKit.apply(tier:)`。
- **必须先改两处 `static let`**：`MenuPanelController.midInterval`（`MenuPanelController.swift:90`）与 `MotionKit.durations`（`MotionKit.swift:36`）都是 `static let`，不改就「切了不生效」——项目已有同类踩坑（设置页切档发事件但消费方没订阅者）。
- 顺手合并 `TransferMotion` → `MotionKit`（口径相同、代码两份），否则互传页不跟随档位。

## 五、需要 lead / 用户裁定的三件事

1. **「主题只做浅色、默认 Apple」这条不在本仓。** AGENTS.md、`.agents/skills/toolbar-coding-standards/SKILL.md`、`docs/` 全文检索都没有这条约定；项目记忆里那条挂在 **android-monitor** 项目下。本仓现状是**浅深双套一等公民**：`PaneCardStyle` 23 对 `dynamic(light:dark:)`、`SystemPaletteTokens` 108 个 hex（浅深各 54）、`Debug/SettingsSnapshot.swift:67-68` 快照按 `.aqua`/`.darkAqua` 各出一份。真按「只做浅色」执行等于**移除深色 + 删 54 个 dark token + 改快照取证**，是一次独立大改造。**建议本轮做「多套主题 × 浅/深」，把现存量表保住**；是否移除深色请用户明确。
2. **`TokenPaneStyle` / `BillingPaneStyle` 不是纯转发**（3 处颜色 + 若干字号尺寸自造，见 §2.1）。主题化前要么把这些补进 `PaneCardStyle`，要么明确声明它们属于「页面私有几何」不进主题。
3. **截图浮层是第五套独立深色体系**（`SnipBarDrawing` 白色图标 + black 半透明底），当前不跟随系统深浅。主题化时它是「跟随主题」还是「继续保持固定深色」需要裁定——覆盖层压在截图内容上，固定深色通常更稳，**建议不纳入主题，仅在文档里标明是有意偏离**。

# 菜单栏标识与单位 / Token 页进入抖动与提示 / 额度页图表首屏缺陷调研

> 调研范围：`NetworkMonitor/Sources`（只读侦察，未改任何源码、未 commit）。行号为落盘当时文件行号。

## 结论摘要

**问题 3（菜单栏标识与单位）**
1. 17 项指标全部由 `MenuBarManager+StatusTitle.swift:53-104` 的白名单分支逐条拼字符串，每一项都带固定标签前缀（`"CPU "` / `"MEM "` / `"Token "` / `"Today "` …），标签是硬编码字面量，数据模型里没有「标签/符号」字段。
2. 没有自定义符号/图标/标签能力：缺 `MenuBarMetric` 的 label/symbol 维度、缺偏好键、缺设置页行；状态项固定 `button.imagePosition = .noImage`（`MenuBarManager.swift:149`）永不显示图标。
3. 单位不统一是真分叉：设置页「数值单位」`NumberUnitStyle{automatic(K/M/B), chinese(万/亿)}`（`NumberUnitPreferences.swift:9-34`，键 `display.numberUnitStyle`）只作用于 Token/额度页的 `NumberUnits.scale`；菜单栏 Token 指标走 `StatusPartContext.speed → formatSpeedShort → ByteFormatting.shortDecimal`（`Core.swift:8-10`），恒 K/M/B，完全绕过 NumberUnits。

**问题 5（Token 页进入闪一下 / 底部字占空间 / 无悬停提示）**
1. 「快速刷新一下」= 每次切到 Token 页：①`MenuPanelController+Actions.swift:93-95` 无条件 `harnessUsage?.refreshIfNeeded()`；②首屏闭包再 `refreshToken()`（`PaneModule.swift:199-201`），而 `refreshToken` 内部又调一次 `refreshIfNeeded()`（`MenuPanelController+DataSources.swift:79`）；③索引把状态刷成 `.indexing` → `AppEvents.postHarnessUsageChanged` → `bindHarnessUsage` 立刻整页重渲（`DataSources.swift:24-34`），且每 500 行进度回调都发一次事件（`HarnessIndexRunner.swift:186-194`）；④页头 meta 被改写成「索引中 n/m · k 行」（`TokenPaneView+State.swift:72-77`），空数据时整屏切 loading（同文件 37-48）。
2. 「下面的字占空间」= 页脚 20pt 状态带（`PaneCardStyle.swift:112`）+ 分布屏卡底单行「口径：…」（`TokenScreenContent+Ranking.swift:59-63,128`）+ 主图 meta 行四个控件挤一行、其中两个是「切：对比」「切：请求数」（`TokenPaneView+Layout.swift:139-143`、`TokenPaneView+Render.swift:46,49`）。385pt 内容预算已填满（`TokenPaneView.swift:154-162`），任何多余一行都在挤数据。
3. 「鼠标放上去没反应」= 主图柱形完全没有 hover 通道：TokenBarsView 无 TrackingArea/mouseMoved/toolTip（`TokenChartViews.swift:12-267` 全文无），Hero、缓存命中条、分族卡、坐标轴同样为零。已有 tooltip 的只有图例行（`TokenLegendViews.swift:70-87`）、分布行（`TokenRowViews.swift:90-92`）、部分迷你图（`TokenMiniChartViews.swift:236`）、页头（`TokenHeaderSection.swift:24`）。

**问题 6（额度页首屏不显示图表 + 直方图丑）**
1. 首屏不画图 = range 口径错配的必然结果：页级初值写死 `.last7Days`（`BillingPaneView.swift:51-52`），而每个 provider 的 usage 初值取 `supportedUsageRanges.first`（`BillingMonitor+Providers.swift:47-50`），Open Design 声明 `[.last24Hours, .last7Days]`（`OpenDesignBillingProvider.swift:27`）→ 首帧 usage.range=24h；聚合严格要求 `$0.range == range`（`BillingChartAggregate.swift:88`）→ 过滤为空 → 柱图与轴隐藏、亮「暂无用量数据」（`BillingChartsSection.swift:157-159`）。切到 24h 两边对齐才有柱；再切回 7d 会真正触发 `selectRange` 重拉（`BillingMonitor.swift:120-162`），故「一次之后就一直正常」。
2. 「直方图丑」可量化：7 根柱、gap 2pt、柱宽均分（`BillingChartRows.swift:45-47`），满高轨道 + 顶部对齐填充、无 y 轴刻度/网格/基线/柱顶值（`BillingChartRows.swift:50-60`），当前柱用文本强调色 `accentText`（:57），悬停文案恒写「X 时 · 值」而 7d/30d 是天粒度（:96-101），柱区高仅 61pt（`BillingChartsSection.swift:42`）。
3. 与 Token 页不共用柱图组件：Token 用 `TokenBarsView`（`TokenChartViews.swift:12`），额度用 `BillingChartBarsView`（`BillingChartRows.swift:13`）；`MenuPanelCharts.swift` 只有网络页的 `MenuPanelBarsView:11` / `MenuPanelSparklineView:232`。

### 问题 5：Token 页每次进入都重扫重渲 / 底部文字占位 / 主图无悬停

- 现象（用户原话要点）：「每次进入 Token 页，这个会话都会快速的刷新一下，然后下面的字又很占空间，鼠标放上去也没任何的反应，也没提示等信息」。配图：页头「DSH ⌄ | 2246 会话 | 今日 近7天 近30天」；主图卡头「近 7 天 · 按天 | 累计 … | 切：对比 | 切：请求数 | 14 天 ›」。

#### 5.1 「快速刷新一下」的调用链

```text
MenuPanelView 切页
  → MenuPanelController.menuPanelViewDidSelectTab         (MenuPanelController+Actions.swift:86)
      ├─ if view.didAssembleCurrentPane { refreshPaneFirstDisplay(tab) }   (:89-91)
```

```swift
// MenuPanelController+Actions.swift:86-101
func menuPanelViewDidSelectTab(_ view: MenuPanelView) {
    if view.didAssembleCurrentPane {
        refreshPaneFirstDisplay(view.currentTab)
    }
    // 切到 Token 页时按需增量刷新（服务内部串行、不重入；数据未变则快速返回）
```

```swift
// MenuPanelController+DataSources.swift:65-79 —— refreshToken 自己还有一次「脏则重算 + 强制高度重算」
func refreshToken() {
    guard let harnessUsage else { return }
    let sequence = tokenRequests.next()
    dataReadQueue.async { [harnessUsage] in
        let snapshot = harnessUsage.snapshot()
        harnessUsage.refreshSnapshotIfDirty()
        Task { @MainActor in
            guard self.tokenRequests.accepts(sequence) else { return }
            self.content.updateToken(snapshot, notifySize: false)
            if self.popover.isShown { self.updateContentSize(force: true) }
        }
    }
    harnessUsage.refreshIfNeeded()
}
```

- 根因（四条叠加）：
  1. `menuPanelViewDidSelectTab` 对 Token 页每次切页都发起索引，没有「数据新鲜就不拉」闸门（:93-95）；首屏又 `refreshToken()`（`PaneModule.swift:199-201`），其内部再 `refreshIfNeeded()`（`DataSources.swift:79`）→ 一次切页排两次请求。
  2. 索引一开跑就把状态推成 `.indexing`（`HarnessIndexRunner.swift:88-93`），而 `setState` 每次进度回调都通知观察者（`reportLinesRead` 每 500 行一次，`HarnessIndexRunner.swift:186-194`；`HarnessUsageService.swift:175-184`）→ 每 500 行一次全页 `render()`。**这是「快速刷新一下」最直接来源**。
  3. 索引期间页头 meta 从「2246 会话」改写成「索引中 n/m · k 行」（`TokenPaneView+State.swift:72-77`），用户看到的正是那一格文字跳变。
  4. 空数据 + `.indexing` 时整屏切 loading（`TokenPaneView+State.swift:37-48`），首帧快照为空时表现为整页白一下。
- 修法建议：①**节流状态事件**：`setState` 仅在状态种类变化时通知（纯进度更新不发或按 ≥500ms 合并）——改 `HarnessUsageService.swift:175-184`（约 10 行），同时顾 `HarnessIndexRunner.swift:186`；②**切页加新鲜度闸门**，判据复用 `MenuBarTokenRefresh`（`NetworkMonitorCore/Domain/Models/MenuBarTokenRefresh.swift`，已有 60s 判据）——改 `MenuPanelController+Actions.swift:93-95`（约 3 行）；③去掉重复路径（`firstDisplay` 与 `refreshIfNeeded` 只留一条，`PaneModule.swift:199-201`）；④页头「索引中」文案改为超 1 秒才替换（`TokenPaneView+State.swift:72-77`）。

#### 5.3 「鼠标放上去没有任何反应」：hover 通道现状与缺口

### 问题 6：额度页首屏不画图（range 口径错配）+ 直方图视觉问题

- 现象（用户原话要点）：「默认进入的额度 tab，下面的图表默认都不显示，只有切换到 24 小时，再切过来又显示图表了，然后图表也不美观，直方图太丑了」。配图：图表区「近 7 天 共 28,503 次 | 24小时 [7天选中] 30天」下方柱图有柱子。

#### 6.1 首帧为什么空：页级默认 7d 与 provider 默认 24h 不匹配

```swift
// ① 页级范围初值 = 7 天（BillingPaneView.swift:51-52）
private(set) var range: BillingRange = .last7Days

// ② provider 的 usage range 初值 = supportedUsageRanges.first（BillingMonitor+Providers.swift:47-50）
supportedRanges: provider.supportedUsageRanges,
...
range: provider.supportedUsageRanges.first ?? .last24Hours,

// ③ Open Design 只声明 [24h, 7d]，first = 24h（OpenDesignBillingProvider.swift:27）
public let supportedUsageRanges: [BillingRange] = [.last24Hours, .last7Days]

// ④ 聚合严格要求 usage.range == 页级 range（BillingChartAggregate.swift:85-91）
let matching = usages.filter { $0.range == range && !$0.buckets.isEmpty }
guard !matching.isEmpty else {
    return ChartSeries(metric: .requests, points: [], total: 0, peak: 0)
}

// ⑤ 空序列 → 柱图与轴隐藏、亮空态（BillingChartsSection.swift:157-159）
barsView.isHidden = series.isEmpty
axisRow.isHidden = series.isEmpty
emptyLabel.isHidden = !series.isEmpty
```

- 根因：首帧页级要 7d，而数据侧只有 24h（provider 默认第一个支持范围），严格相等过滤把数据全滤掉 → 首屏「暂无用量数据」。
- 为什么「再切回来就显示了」：切回 7d 时 `applyRange` → `onRangeChange` → `BillingMonitor.selectRange(7d, providerID:)` 真的发了一次 7d 用量请求（`BillingPaneView.swift:197-209` → `PaneModule.swift:163-165` → `BillingMonitor.swift:120-162`），此后有 7d 数据。
- 首进缺的那一步：首屏闭包只 `renderBillingSnapshot()`（`PaneModule.swift:177-179`），只是把最后一帧 states 推给视图（`MenuPanelController+Actions.swift:120-128`），**不把 provider 拉到页级 range**。
- 修法建议（推荐 ①）：①`BillingPaneView` 首次 `update` 里对 range 不匹配的 provider 逐个 `onRangeChange(range, id)`（`BillingPaneView.swift:152-191`，约 +8 行，等价于把 `applyRange` 的「逐家通知」在首帧复用一次）；②改 `supportedUsageRanges` 顺序（`OpenDesignBillingProvider.swift:27`，影响全 provider，风险大）；③放宽聚合过滤（`BillingChartAggregate.swift:88`）——该函数注释明确反对，会画错口径，**不建议**。
- 附带：`selectRange` 有「同 range 直接 return」闸门（`BillingMonitor.swift:121-124`），所以切到 24h 时 provider 其实没重拉，靠的是它本来就有 24h 数据 —— 印证问题不是「数据没到」而是「口径没对齐」。

#### 6.2 三档切换的重画路径与首进差异

- 触发重画的两处路径：①`BillingChartsSectionView.onRangeChange` → `applyRange` → `chartsView.update(states:range:)` 立即用当前 states 重算（`BillingChartsSection.swift:50`、`BillingPaneView.swift:197-202`）；②`selectRange` 成功 → `emit()` → `onUpdate` → `updateBilling` → `BillingPaneView.update` → `chartsView.update`（`BillingMonitor.swift:147-161` → `DataSources.swift:16-20` → `BillingPaneView.swift:171`）。
- 首进缺第 ②，只剩 ① 的「用不匹配的旧数据重算」→ 必然空。

#### 6.3 直方图「丑」的可量化原因

```swift
// BillingChartRows.swift:43-61
override func draw(_ dirtyRect: NSRect) {
    guard !points.isEmpty else { return }
    let gap: CGFloat = 2
    let count = CGFloat(points.count)
    let columnWidth = max(1, (bounds.width - gap * (count - 1)) / count)
    let peak = max(points.map(\.value).max() ?? 0, 1)
    for (index, point) in points.enumerated() {
        let x = bounds.minX + CGFloat(index) * (columnWidth + gap)
        let column = NSRect(x: x, y: bounds.minY, width: columnWidth, height: bounds.height)
        DrawnInk.fill(column, radius: 2, color: PaneCardStyle.trackColor)
        guard point.value > 0 else { continue }
        let height = max(1, bounds.height * CGFloat(point.value / peak))
        let rect = NSRect(x: x, y: bounds.maxY - height, width: columnWidth, height: height)
        let base = point.isCurrent ? PaneCardStyle.accentText : fillColor
        let color = index == hoveredIndex ? base : base.withAlphaComponent(0.92)
        DrawnInk.fill(rect, radius: 2, color: color)
    }
}
```

可量化的「丑」：
1. **柱区过矮**：`barHeight = 61`（`BillingChartsSection.swift:42`），卡内还要塞卡头行 + 轴行 + emptyLabel（同文件 67-82，间距 3pt × 3）→ 实际绘图高约 40pt；7 根柱在 296pt 内容宽里每根 ≈ 39pt 宽、40pt 高，接近正方形甚至更扁。
2. **满高轨道 + 顶部对齐填充**：每根柱先画满高 `trackColor`（:53）再叠填充 → 视觉是「7 个灰框 + 顶部一小截色」，低值柱悬空，**没有基线**（`isFlipped = true`，:30）→ 读作「进度条」而非柱状图。
3. **无 y 轴刻度 / 网格 / 柱顶数值**：全文件无刻度绘制（对比 Token 主图有 `drawScale`，`TokenChartViews.swift:107`）→ 柱间无法比较绝对量。
4. **当前柱用文本强调色**：`PaneCardStyle.accentText`（:57），不是图表语义色，与其余柱的 `fillColor`（uncachedColor / okColor，`BillingChartsSection.swift:207-212`）不同色系。
5. **悬停文案恒写「时」**：`caption` 固定 `point.label + " 时 · " + text`（:96-101），而 7d/30d 是天粒度（`BillingChartAggregate.granularity`，`BillingChartAggregate.swift:59-61`）→ 悬停「16 时 · 1204」是错的。
6. **柱数不固定**：24h 8 根 / 7d 7 根 / 30d 10 根（`BillingChartAggregate.swift:64-70`）而柱宽随宽度均分、gap 恒 2pt → 30d 时 10 根又细又密。
- 修法建议：①去掉满高轨道，改「基线 + 柱」（`BillingChartRows.swift:50-60`，约 10 行），最小柱高 2pt；②当前柱改语义色（:57，1 行）；③`caption` 按 granularity 出「时/日」（:96-101，需把 range/granularity 传进 view，+5 行）；④补 2–3 条水平网格 + 左侧峰值刻度（复用 `TokenBarsView.drawScale` 思路，+30 行），柱高 61 → 72…80（`BillingChartsSection.swift:42`，额度页本就允许纵向滚动）。

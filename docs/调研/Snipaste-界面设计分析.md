## 1. 设计语言总览

### 1.1 整体观感

- 一句话观感：**一张朴素的 Windows 原生工具面板**——浅灰底、1px 描边、单色几何图标，几乎不置入阴影或渐变，信息密度高、装饰成分近乎零。（截图可见）
- 界面里唯一"有颜色"的地方就是**主题色**：选中格填充、激活窗口阴影、快捷键状态点、列表选中行。其余全是无彩色。（截图可见 + 文档明写）
- 没有任何圆角化或拟物化：工具条与首选项都是直角矩形、1px 边线，靠**边框与分组线**而不是阴影划分区域。这一取向让它在"覆盖在别人界面上"的场景里不会抢夺注意力。（推断：依据是覆盖层几乎全直角、无阴影，且官网强调「截图后贴回屏幕」的工作流）

### 1.2 色彩策略

- **主色（主题色）**：像素实测为 `#2080F0`（RGB 32,128,240；TNqoS229 里该色共 2544 px 且首选项主题色块与工具条选中格取样完全一致），比 Windows 10 默认强调色略亮的中性蓝。（截图可见）
- **主题色可换**：官方把「主题颜色」直接做成首选项里一个可点的色块，工具条选中格与贴图激活阴影跟着变色；同一张官方图里摆了四行不同主题色（蓝 / 黑 / 橙 / 粉）的工具条预览。（截图可见 + 文档明写「主题色跟随系统主题」）
- **中性色阶**（像素实测，截图可见）：工具条底 `#F2F2F2`；对话框底 `#F0F0F0`；内容区 `#FFFFFF`；分隔线 `#E6E6E6`/`#D8D8D8`；深色浮层（尺寸标签、放大镜信息条）`#1E1E1E` 近黑 + 白字。
- **强调色用得极克制**：只有"当前选中"和危险/成功状态用饱和色；撤销/重做不可用时直接灰到接近背景——放大裁切里两个箭头明显比其它图标淡。（截图可见）
- **深色与浅色**：官方没做全局深色主题，只在系统层面做适配——文档写 Linux「适配深色模式」、macOS「修复首选项窗口在深色模式下的样式错误」；所有官方截图都是浅色。（文档明写 + 推断：说明它是"跟随系统做小范围适配"，不是"提供一套深色皮肤"）

### 1.3 圆角与描边

- **圆角几乎为零**：工具条、按钮格、调色板色块、首选项窗口、菜单全部直角；唯一例外是尺寸标签那个很小的胶囊圆角。（截图可见）
- **描边是主要分隔手段**：工具条外框 1px；格与格之间不画线，靠留白 + 选中态反白区分；只有组与组之间才加一条 1px 竖分隔线。首选项用「凹陷分组框 + 组标题」的经典 Win32 手法（如「调色板」分组框）。（截图可见）
- 贴图窗口**没有 chrome**：无标题栏、无边框线，只有一圈系统投影；窗口激活时投影变成主题色（文档明写「当前激活的贴图窗口的阴影将使用主题色」）。（截图可见 + 文档明写）

### 1.4 图标风格（逐条读 svg 源码后描述）

三个站点图标与工具条图标同一族：

- `copy16.svg`：`viewBox="0 0 16 16"`，两条 path 各是一个 10×13 左右的**空心矩形框**，两框错位叠放表示"复制到剪贴板"。线宽由矩形内缩产生（外框 15→3.25、内框 11.5→4.75，视觉线宽约 1.25 单位）。（截图可见：直接读了源码）
- `save16.svg`：单条 path，**实心软盘**——外层是 16×16、圆角半径 0.96 的实心方块（`M.96 0 … V3.84 … L12.39.09` 把右上角斜切），内部再"挖"出三个留白区域（写保护滑片、标签纸、拉手）。是**实心 + 负空间挖洞**的画法，不是线性描边。（截图可见：源码）
- `pin16.svg`：两条 path 混用——第一条是**实心斜置的短粗斜杠**（`M9.34 1.34 L10.76 -.075 L16 5.16 …`，一个 45° 实心平行四边形），第二条是**描边的折线**（图钉的杆与尖）。图钉本体在工具条放大裁切里是**实心黑三角**。（截图可见：源码 + 裁切）
- 归纳：**16×16 viewBox、纯单色、无渐变无阴影、无统一线宽约束**——是「实心块 + 负空间 + 少量粗描边」的混合体，与 Feather / Lucide 那类等线宽线性图标集不是一路。工具条上矩形/椭圆是空心描边、折线/箭头是粗折线、画笔是实心笔杆、马赛克是 3×3 棋盘格、文字是带衬线的「I」形、橡皮是斜置实心块——**同一条工具条里描边与实心混排也毫不回避**。（截图可见）

### 1.5 字号与密度

- 首选项里一行 = 一个中文标签（左对齐、带冒号）+ 一个控件，行距约 40px（TNqoS229 中「显示语言 / 界面字体 / 主题颜色 / 通知栏图标 / 开机启动」五行占满一页），**行高宽松但控件贴边**，没有分组卡片。（截图可见）
- 标注工具条是**相反的极端**：单格约 24–27px 见方（马赛克选中格实测 24px 宽；行 1 整条 x 391–738 ≈ 348px）、行高约 26px，两行合计约 55px，几乎无内边距——因为它是覆盖层，每一像素都压在别人界面之上。（截图可见：像素测量）
- 界面字体可配：首选项明写「界面字体：微软雅黑，9」，字体与字号都能改。（截图可见）
- 菜单是原生 Win32 密度：菜单项行高约 22–24px、助记键单字母右对齐、分组之间用横线。（截图可见）

## 2. 截图覆盖层

### 2.1 选区外观

- **未选区被压暗**：选区外覆盖半透明暗色遮罩。证据取 N3038l46.png——该图整幅被压暗（全图众数 `#737373` 即 `(115,115,115)`，占 289 837 px），选区内部保持原亮度。（截图可见）
- **边线是蚂蚁线**：选区边界不是实线，而是黑白交替的虚线；vu1nkxdD.png 选区上边缘 y=184 实测为 `1111 0000` 的**4 on / 4 off、周期 8px** 交替，这是屏幕取色类工具的通行做法——保证在任意底图上都能看清边界。（截图可见：逐像素扫描）
- **锚点是空心小方框**：八个角/边中点各一个方形空心标记，边框细、内部透出底图；选区宽或高小于阈值时锚点自动隐藏（默认阈值 80×DPI）。（截图可见 + 文档明写 `Snip/anchors_threshold`）
- **尺寸标签**：近黑底、白字、小圆角的深色胶囊，格式 `宽 x 高`（如 `548 x 286`、`72 x 22`），挂在选区外上方，带一个向上的小三角指向选区；拖拽时实时刷新。（截图可见）
- **辅助线**：按住 `Alt` 出现两条贯穿屏幕的中央辅助线，用于居中构图；另有「禁用辅助线」选项。（文档明写 + 推断：截图未取到 Alt 按住态，辅助线的具体颜色与线型为推断）

### 2.2 放大镜

- 结构是**上下两块**：上方形取景框（显示放大后的像素与网格），下方深色信息条。（截图可见）
- 信息条**两行**：第一行是坐标 `(1161 , 282)`（圆括号 + 逗号两侧留空格），第二行是取色块 + 色值 `234, 198, 72`——即"位置在上、颜色在下"，先定位再取值。（截图可见：6× 放大读取）
- 取景框内可见**网格线**；网格、屏幕坐标、操作提示三项在「界面 → 常规 → 放大镜」页里各自可勾，像素大小可配（默认 9）。（截图可见 + 文档明写）
- 放大镜会在"合理时机"自动出现/隐藏，`Alt` 强制唤出；它还会**根据当前屏幕 DPI 自动调整缩放**。（文档明写）

### 2.3 提示气泡与光标

- 进入截图后会出现**操作提示**（可在首选项关闭）；属于"第一次用也能上手"的引导层。（文档明写 + 推断：更新日志写「增加截图操作提示（可在首选项中关闭）」，截图中未抓到底层气泡，其具体形态为推断）
- **光标即状态**：画笔/橡皮/文字各有专属光标图案，且图案会体现当前画笔粗细（更新日志：「更新部分标注的光标图案，以体现画笔粗细」）；截图时还能把系统光标"拍进"图里（`` ` `` 切换）。（文档明写）
- 光标移动支持 `WASD` 单像素步进 + **按住自动加速**，配合放大镜实现像素级定位。（文档明写）

### 2.4 多屏与冻结画面

- 覆盖层覆盖**所有屏幕**合成后的画面：进入截图即冻结当前屏幕内容（白板模式改用纯色填充；「透明白板」则不冻结）。（文档明写 + 推断：由 `transparent-whiteboard`「屏幕内容不会冻住」反推普通截图是冻结的）
- **跨屏不同 DPI 时工具条保持统一视觉大小**（更新日志明写「在多屏不同 DPI 的环境下，标注工具栏等界面会保持统一的视觉大小」）——这是覆盖层在混合 DPI 下最容易崩的地方，被单独当成一条特性来写。（文档明写）

## 3. 标注工具条（重点）

### 3.1 位置与形态

- **两行结构**，浮在选区外侧（常见位置是右下角），随选区移动重新摆放；选区贴边时工具条翻到另一侧避让。（截图可见 + 文档明写「截屏时工具条的位置调整策略」）
- 行 1 是**工具 + 动作**，行 2 是**当前工具的参数**（笔尖 / 纹理 / 颜色）。（截图可见）
- 外观：浅灰 `#F2F2F2` 底、1px 边框、直角、格与格之间无描边；**空格键可整体隐藏/唤出**，编辑状态下也有效。（截图可见 + 文档明写）

### 3.2 一级 / 二级分层

- **一级（常驻行 1）**：矩形、椭圆、折线、箭头、画笔、记号笔、马赛克、文字、橡皮擦 ‖ 撤销、重做 ‖ 保存、复制、完成（✓）。（截图可见）
- **二级（点开才出现）**：
  - 大色块 → 颜色面板（含 Alpha 通道 0–255）。官方 FAQ 直接把大色块当入口：「画板里没有我想要的颜色，请点击那个大的颜色按钮」。（截图可见 + 文档明写）
  - 行 2 的笔尖/纹理/调色板 → 参数档位切换，不弹面板。（截图可见）
  - 直线/箭头 → `Tab` 就地互转，不弹菜单；矩形/椭圆同理（更新日志「合并了工具条上的矩形和椭圆标注」）。（文档明写）
  - 输出选项 → 工具条右侧独立的竖排小控件（三个小色点 + 三条虚线段 + 一张缩略图），点开是「输出选项」弹出菜单，可用 `Interface/hide_output_options` 整块隐藏。（截图可见 + 文档明写）
- 分层策略很清楚：**画什么（一级 9 个）→ 用什么参数（二级行 2）→ 输出到哪（二级右侧浮层）**，三个层级在视觉上各自成块、互不干扰。（截图可见）

### 3.3 按钮分组与分隔

这张图是官方截图里的截图态全景：暗色遮罩压住桌面、选区内部保持原亮度，右下角浮着两行工具条，右侧还有一块竖排的「输出选项」小控件与缩略预览。

![](https://i.v2ex.co/N3QEb3VA.png)

按工具条放大裁切后的实际排列：

```
[矩形][椭圆][折线][箭头][画笔][记号笔][马赛克] │ [文字][橡皮擦] │ [撤销][重做] │ [保存][复制][✓]
```

- 分隔线是 **1px 深色竖线**，高约 17px（约占行高 26px 的 65%）；实测真分隔线只落在 x=610 与 x=663（左右两侧均为底色），而 x 536–559 那段深色不是线，是**马赛克工具的选中格**被主题蓝整格填充。（截图可见：像素测量）
- 有一条**不写字的隐性分组**：前 7 个是"画图形"，文字与橡皮擦一组，撤销重做一组，输出动作一组——即**从"创作"到"修正"到"收尾"的从左到右顺序**。（截图可见 + 推断：分组边界由分隔线位置与功能语义共同确定）
- 文字与橡皮擦之间**没有分隔线**（放大裁切里紧邻），说明作者把「文字也算画上去的东西」与图形同域；真正的分界在「撤销/重做」之前。（截图可见）

### 3.4 按钮尺寸与命中区

- 单格约 24–27px 见方（实测马赛克选中格 x 536–559 即 24px 宽；行 1 整条 x 391–738 ≈ 348px），16px 图标居中，四周留约 4–5px 空白；行高 26px（y 543–568，569 为 1px 间隙）；两行之间无缝拼接。（截图可见：像素测量）
- 命中区就是整格：选中时**整格填充主题色**、图标反白——"反白整格"是它唯一表达选中的手法，没有边框加粗、没有下划线。（截图可见）
- 行 2 的笔尖三档是**实心圆点由小到大**（直径约 5 / 8 / 11px），选中那档底色提亮成浅灰（不是主题色），与行 1 的选中表达刻意区分：「工具用主题色实心、参数用浅底高亮」。（截图可见）

### 3.5 当前颜色与线宽的表达

- **颜色**：行 2 有一个明显比其它格更大的"大色块"，直接显示当前色；色块左下角有个**彩色三角**，暗示"可展开取色"。颜色不靠文字、不靠弹窗，就是一块颜色本身。（截图可见）
- **线宽**：由行 2 的笔尖三档 + 一条滑块共同表达；轨道浅灰、当前值是一个蓝色小方块（thumb），左侧还有一个**实时笔触预览圆点**（模糊渐变圆）。（截图可见）
- 透明度不在工具条上显示数值，只在颜色面板里以 Alpha 0–255 呈现；但可以在大色块上滚轮直接改。（文档明写）

### 3.6 悬停与选中反馈

- 选中：整格主题色实心 + 图标反白。（截图可见）
- 悬停：从 gif 抽帧可见鼠标移到某格时该格出现**浅色底**（比底色略深的灰），没有描边、没有缩放。（截图可见）
- 不可用：撤销/重做在栈空时图标降到浅灰，与可用态形成约 30% 的明度差。（截图可见）
- 参数联动：`Shift` 按下时工具条图标会跟着变形（更新日志曾修过「画矩形/椭圆时按下 Shift，工具条的图标有时没有同步变化」）——即**同一个图标承担"矩形/正方形"两种语义，靠图标自身比例变化提示**。（文档明写 + 推断：图标变形的具体画法为推断）

### 3.7 撤销重做与输出动作的摆放

- **撤销/重做在中间偏右、与工具组用分隔线隔开**；`Ctrl+Shift+Z`（移除所有标注）没有独立按钮，只走快捷键。（截图可见 + 文档明写）
- **输出三个动作固定在行 1 最右端**：保存（软盘）、复制（双层套框）、完成（粗对勾 ✓）。"完成"用一条粗折线画的对勾，比其它图标视觉更重——这是整条工具条里唯一被"加粗"的图标，明确指向"这是终点"。（截图可见）
- 保存图标与 `save16.svg` 同族（实心软盘 + 负空间挖洞），复制图标与 `copy16.svg` 同族（双层空心套框）——**工具条与官网用的是同一套图形语汇**。（截图可见）
- `Ctrl` + 点这三个按钮 = 带阴影输出；`Shift` + 点保存 = 快捷保存。同一个按钮承载多档语义，靠修饰键区分，不加按钮。（文档明写）

### 3.8 文字工具与字号

- 文字工具是行 1 里唯一"非图形"图标——一根带上下衬线的竖线加两端横杠，近似「I」形。（截图可见）

- 官方截图里同一段文字以三档明显不同的字重/字号并排出现（`文字0 / 文字1 / 文字2`，字重与描边依次加重），用来展示「更小字号 + 描边粗细 + 背景填充」的组合差异。（截图可见）

### 3.9 调色板与笔尖体系

- 工具条上的调色板是 **大色块 + 8 列 × 2 行 = 16 色**（色块 12×12、间距恒 16px），紧贴大色块右侧，中间一条竖分隔线；纯色方块、无圆角、无间隙。（截图可见：像素测量，TNqoS229 / vu1nkxdD）
- 首选项「界面 → 工具条」页的调色板格数更多：**大色块（约 28px）+ 10 列 × 2 行 = 20 格**（起点 x 138 / 170 / 186 / 202 / 218 / 234 / 250 / 266 / 282 / 298 / 314），说明可自定义颜色数量后两处不再等宽。（截图可见：pmoi988T.png）
- 配色顺序是「无彩色在前（黑、深灰、浅灰、白）、有彩色在后」，且**两行按明度配对**：上一行饱和、下一行同色系更浅。（截图可见）
- 调色板可自定义颜色数量、可拖拽重排、可导出到剪贴板分享（首选项里「从剪贴板导入 / 导出到剪贴板」两个按钮），并为不同标注形状分别记忆颜色。（文档明写 + 截图可见：导入导出按钮）
- **笔尖体系**：行 2 左侧三档圆点 = 三个可保存的笔尖尺寸（1–5 个可配），每档可单独滚轮调粗细——即「先选笔再调粗细」的两级模型，而不是一个全局滑块。（截图可见 + 文档明写）

- **缩略图**：固定尺寸小窗（首选项「快速缩略图大小」默认 50×50），`Shift`+双击进入；缩略图与普通贴图在外观上**没有额外 chrome**，靠尺寸本身区分；另有"右键框选生成自由尺寸缩略图"。（文档明写 + 截图可见：首选项里的 50×50）

### 4.4 四种背景模式的视觉差异

- 子菜单四项：**透明 / 伪透明 / 暗色棋盘 / 亮色棋盘**，勾选当前项。（截图可见）

- 归纳：这是**"视觉透明"与"命中测试透明"解耦**的设计——把通常藏在代码里的 hit-test 语义做成用户可选项，是一个值得学的取舍。（推断：依据是官方对四者的说明只差在"鼠标能不能点到"，画面表现只有两档）

### 5.3 「高级设置全部藏进 config.ini」对 UI 的影响

- 官方原文：「这些是**没有提供用户界面**的高级设置，请小心设置。」——`[General] [Snip] [Paste] [Hotkey2] [Annotate] [Interface] [Output] [Misc] [Log]` 九组、二十多个键全部只在 `config.ini` 里存在。（文档明写）
- 对 UI 的三个直接后果：
  1. **首选项能保持"一页装得下"**：像 `process_priority`、`crashes`、`exclude_from_detection` 这种"每千人才有一个用"的排障型开关不占版面，首选项里只留"人人都会碰"的项。（推断：依据是这些键都是平台特例/兼容性补丁性质）
  2. **代价是"发现性断层"**：用户必须知道 `首选项 - 常规 - 配置文件存储位置 - 打开` 这条四级路径才能改；而且流程还要求"退出 → 保存 → 重启"，不是实时生效。（文档明写）
  3. **补偿手段是"悬停提示 + 提示图标"**：官方 FAQ 明说「几乎每个选项都有悬停提示」「如果哪个选项看不明白，你很可能并不需要改动它」——用文案把"看不懂就别改"变成一种设计纪律。（文档明写 + 截图可见：多个页签标题旁有 ⓘ 图标）
- 值得注意：**有两项被明确标成"仅专业版可改变"**（`Interface/hide_output_options`、`Misc/software_metadata`）——即配置文件这个"后门"也做了权限分级，UI 层看不到这个差异。（文档明写）

## 7. 交互设计

### 7.1 快捷键节奏

- **`F1` 截图 → `F3` 贴图**：两个单键、相邻排布、语义对称（一个"取"、一个"放"），官网首屏就用这句话做卖点。（文档明写）
- 功能键全是**单键**：`F1` 截图、`Ctrl+F1` 截图并复制、`Shift+F1` 自定义截图、`F3` 贴图、`Shift+F3` 隐藏全部、`Ctrl+F3` 换组、`F4` 穿透开关。**同一个 F 键用修饰键横向扩展**，记忆成本极低。（文档明写 + 截图可见）
- 会话内快捷键是**单字母/数字**：`1`–`6` 管贴图变换、`WASD` 管像素移动、`C` 取色、`R` 上次区域、`V` 复制尺寸、`,` `.` 翻历史、`[` `]` 调粗细。**用"手上的键位地形"代替菜单**。（文档明写）
- 允许把**任意命令行**绑到全局快捷键（可带忽略程序列表），把快捷键体系从"固定功能表"变成"可编程宏"。（文档明写）

### 7.2 中键与双击语义

- **中键 = "复位"**：托盘图标上中键 = 贴图；贴图上中键 = 恢复 100% 尺寸与不透明度。**同一个键在"图标"与"内容"上都是"回到默认"**。（文档明写）
- **左键双击 = "收起"**：双击贴图关闭窗口；`Shift`+双击 = 缩略图——双击是"折叠"，修饰键的双击是"换成小窗"。（文档明写）
- `Esc` = 取消/关闭，`Shift+Esc` = 销毁（不可恢复）——**`Esc` 家族按"可恢复性"分档**：关闭还能贴回来、销毁不能。（文档明写）
- 共同点：**同一个物理动作在不同对象上保持同一心理模型**（中键=复位、双击=收起、Esc=退出），而不是每个对象各定义一套。（推断：依据是上述三组映射在文档中高度一致）

### 7.3 无模式化与一次操作闭环

- 截图态没有"工具模式"和"浏览模式"的切换：**一进截图就能标注，标注完直接点复制/保存/贴图退出**，不存在"先确认再编辑"的二段式。（截图可见 + 文档明写「成功的截图」定义）
- 「成功的截图」被定义成**四种出口**（复制 / 存文件 / 贴图 / 快捷保存），任何一个出口都算闭环；没走出口就 `Esc` 放弃。**没有"保存草稿"这种状态**。（文档明写）
- 贴图侧同样无模式：缩放、旋转、透明度、穿透、标注全靠直接手势 + 快捷键，没有工具栏。（截图可见：贴图零 chrome）
- 代价是**功能必须能被"手势 + 单键"表达**，所以复杂能力（多选、分组、背景模式）全被推到了右键菜单里。（推断：依据是右键菜单承担了 18 项操作）

### 7.4 可发现性做法

- **三层引导**：
  1. **常驻**：托盘菜单顶部写死 `F1`/`F3`；工具条最右端的 ✓ 是视觉最重的图标；大色块带彩色三角暗示可展开。
  2. **悬停**：几乎每个首选项都有 tooltip；选项窗口多处布 ⓘ 图标；贴图右键菜单显示助记键。
  3. **触发后**：截图操作提示气泡、穿透开关切换时的文本提示、首次双击关闭贴图的提示、复制颜色成功时放大镜闪一下、快捷键设置失败时提示原因。
- **帮助窗口内置**：首选项「热键」页有「内置快捷键」按钮，打开一张带「复制」按钮的三段式快捷键表——**把"说明书"做成了一张可复制的数据表**。（文档明写 + 截图可见「内置快捷键」按钮）
- **诊断入口 API 化**：`docs` 打开帮助、`open-preferences` 打开首选项、`show-tray-menu` 弹托盘菜单——UI 的每个角落都能被命令行触达。（文档明写）

## 8. 可借鉴 / 不建议照搬

### 8.1 值得借鉴（5 条）

1. **用"整格反白"表达选中，而不是描边/下划线**——格子里除了图标什么都没有，选中是唯一必须被看见的状态；反白面积最大、辨识最快，也不额外占用像素。（截图可见）
2. **参数区独立成第二行，且用"不同的选中语言"**——行 1 工具用主题色实心、行 2 参数用浅底高亮，用户一眼能分清"我在用哪个工具"和"这个工具的哪个档"，这是两层选择并存时最容易混淆的地方。（截图可见）
3. **输出动作固定在末端、终点图标加重**——保存/复制/完成三件事永远在行 1 最右、位置不变；完成键用粗对勾。**肌肉记忆靠位置，不靠文案。**（截图可见）
4. **把只读信息做成可操作菜单项**——右键菜单底部的 `152 x 100` 既是当前尺寸又是改尺寸入口，色值复制项把当前值写进菜单文本。信息与操作合一，省一次跳转。（截图可见）
5. **"视觉透明"与"命中测试透明"解耦**——背景模式把"看不看得见"和"点不点得到"拆成两个可选项（透明 vs 伪透明），解决半透明贴图"看得见却拖不动"的常见抱怨。（文档明写 + 推断：四模式说明只差在可否点击）

### 8.2 不建议照搬（4 条）

1. **高级设置全走 config.ini + 要求重启**——把二十多个键彻底移出 UI，代价是"发现性断层"与"改一次重启一次"。除非产品明确面向愿意读文档的极客，否则至少应给一个"高级"折叠区。（文档明写「这些是没有提供用户界面的高级设置」）
2. **一格约 24–27px 的点击目标**——鼠标上够用，但触控板/高分屏/手抖场景偏小（对比 macOS 工具条常见的 28–32px）。桌面鼠标工具可以接受，跨端产品不宜照搬。（截图可见：像素测量）
3. **同一条工具条里混用实心与描边图标**——`save16` 是实心软盘、`copy16` 是空心套框、折线是粗描边，风格不统一是为了"每个图标各自最像它代表的东西"。这种"功能性优先于系统性"的做法在图标少时有效，图标一多就会显得杂。（截图可见：源码 + 放大裁切）
4. **主题色只作用于"选中填充"，不作用于图标本身**——好处是图标永远高对比；坏处是换主题时变化面积极小，用户会觉得"换了跟没换一样"。若要主题有存在感，需要给主题色更多承载面（如分组标题、强调描边）。（截图可见：四行主题预览里只有第一格变色）

## 9. 一句话总结

Snipaste 的 UI 是**"把复杂度压进手势与配置文件"**的典型：界面上只留高频动作，用整格反白与单字母助记键维持极低学习成本；所有低频能力（分组、背景模式、多选、排障型配置）一律退到右键菜单或 `config.ini`，再用"悬停提示 + 帮助窗口 + 操作气泡"三件套兜底可发现性。（推断：由上述截图与文档综合得出）

# 改名影响面清单（App 中文重品牌）

> **何时阅读：** 把应用从「网络监控 / NetworkMonitor」重品牌成中文名之前。
> **调研方式：** 只读。代码点位用 codebase-memory 知识图谱（`list_projects` / `search_code` / `search_graph` / `get_code_snippet`）定位，文档正文用 grep 取行号（`docs/` 被索引排除，`check_index_coverage` 显示 `docs` 为 `not_indexed_dir`）。
> **本机实测证据**（2026-11-14，`/Applications/NetworkMonitor.app` 与用户目录现状）见各节标注。

## 一、结论速览

1. **只改「显示名」= 零权限风险、零数据风险。** 显示名取 `Info.plist` 的 `CFBundleDisplayName`（缺省回落 `CFBundleName`），与 bundle id / 签名身份 / 数据目录解耦。当前 `Info.plist` 里两者都是 `NetworkMonitor`，且**没有** `CFBundleDisplayName`。
2. **风险全部集中在「改标识」与「改路径」两类动作**：bundle id（=`UserDefaults` 域主键）、签名身份（=TCC 的 designated requirement）、`Application Support` 数据目录、`.app` 目录名（=SMAppService 登录项注册路径）。这四项各有独立证据链，见第四节。
3. **落地方案推荐两段式命名**：`APP_NAME`（构建产物 / 可执行 / 安装路径 / CI 资产）保持 `NetworkMonitor`，新增 `APP_DISPLAY_NAME`（中文）只写进 `Info.plist` 显示字段与 UI 文案。代价是 Finder 里 `.app` 文件名仍是英文——量取舍见第五节方案 A/B。

## 二、风险分级

| 级别 | 含义 | 可回退性 |
|---|---|---|
| **L0** | 纯显示文案（界面字面量、Info.plist 显示字段、文档） | 改回一个字即可 |
| **L1** | 内部标识但用户几乎不可见（OSLog subsystem、CI 资产名、Release 标题） | 改回即可，影响诊断习惯 / 下载链接 |
| **L2** | 用户可见路径（`.app` 目录名、截图目录、互传目录） | 需要一次性迁移或回装旧包 |
| **L3** | 数据路径（`Application Support` 目录、数据库文件名、密钥文件） | **需要迁移脚本 + 校验**，漏项即数据不可见 |
| **L4** | 身份标识（`CFBundleIdentifier`、签名证书名、凭据派生 salt） | **不可逆**：授权重授、偏好与凭据作废 |

## 四、会丢数据 / 失效权限的点位（逐条）

### 4.1 `CFBundleIdentifier` → UserDefaults 域变更，偏好与凭据全丢

- **机制**：偏好域 = bundle id。实测 `~/Library/Preferences/com.example.NetworkMonitor.plist` 有 **187 条键**，含 `billing.credential.ollama` / `billing.credential.open-design`（`enc:v1:` 密文）、`clipboard.hotkey.*`、`snip.hotKey.*`、`dailyTrafficLog`（按日流量历史）、面板分页与菜单栏布局偏好。
- **旁证**：同目录还存在一个旧域 `~/Library/Preferences/NetworkMonitor.plist`（`totalRx` / `dayStartRx` 等旧键），说明历史上域已经漂移过一次，旧数据就此成为孤儿——正是本次要避免的。
- **规避**：不动 bundle id。改名后自检 `defaults read com.example.NetworkMonitor | wc -l` 仍为原数量级；凭据、快捷键、流量历史全部照常。

### 4.2 签名身份 `NetworkMonitor Local Signing` → TCC 授权全部失效

- **机制**：TCC（屏幕录制 / 辅助功能 / 输入监控 / 本地网络 / 通知）按「bundle id + designated requirement」授权；换证书名或换身份 → csreq 变 → 系统视为另一个应用。build-app.sh:101-112 已有 `assert_stable_signature` 把 ad-hoc（cdhash 型 requirement）判为失败，同一条纪律适用于「换证书名」。
- **规避**：证书名与 `--identifier` 都保持；改名前用 `codesign -d -r- /Applications/NetworkMonitor.app` 存一份 requirement 文本，改名打包后逐字对比。
- **数据侧**：证书名变化还会让 `EncryptedSecretStore` 的机器绑定材料（`gethostuuid`）不受影响，所以凭据不会因此丢——但钥匙串实现（非默认）会因 ACL 弹框阻塞主线程（见 docs/踩坑/运行时/自签名App读钥匙串卡死.md）。

### 4.3 数据目录 `~/Library/Application Support/macMonitor` → 数据库 / 图片 / 密钥三件套

- **实测规模**：目录 198 MB；`monitor.db` 81 MB + `monitor.db-wal` 2.6 MB、`clipboard/images` 65 MB、`credentials.key` 32 B（0600）、另有 `monitor.db.bak-*` 手工备份与 `reports/`。
- **规避（推荐）**：目录名保持不变，只改显示名 → 零迁移。
- **必须改名时**：**整目录 mv**（不要新建目录后逐文件拷）。好消息是 `credentials.key` 与密文同在一个目录，且 KDF 的 salt 是常量字符串（`com.example.NetworkMonitor.credentials`，不含路径），所以整目录搬走后凭据仍可解密。逐项漏搬的后果：漏 `credentials.key` → 凭据永久不可解，需用户重填。

### 4.4 数据库文件名 `monitor.db` / WAL / 备份

- 改名会导致「新库从零开始」：今日流量、剪贴板历史、Token 索引全部显示为空，但旧库仍在磁盘上——用户视角是「数据没了」。**保持不变**（文件名与产品名无关）。

### 4.5 `/Applications/NetworkMonitor.app` 目录名与 SMAppService 登录项

- **机制**：`LaunchAtStartupService.setEnabled` 走 `SMAppService.mainApp.register()`（LaunchAtStartupService.swift:31-46），注册对象是当前 bundle 的**路径 + id**；安装路径变了，登录项失效。而服务里「用户意图」是本地偏好键 `ClipboardPreferences.launchAtStartupKey`——注册已失效但键仍为 `true`，界面会显示「已开启」而实际不开机启动（静默失真，:9-10 注释已警告过同类问题）。
- **规避**：把 `.app` 目录名保持 `NetworkMonitor.app`（方案 A），或改名后做一次「关→开」重置：设置页关掉自启动、重新打开（或在迁移脚本里把偏好键写回 `false` 并提示用户重开）。

### 4.6 TCC 与 `.app` 路径的灰色地带（诚实标注）

- `.app` 目录改名后，屏幕录制等授权**大概率**保留（bundle id + csreq 未变），但本机无法直接验证：`~/Library/Application Support/com.apple.TCC/` 不存在，系统 `/Library/Application Support/com.apple.TCC/TCC.db` 需「完全磁盘访问」。**结论按机制推导，未取到库内证据。**
- **建议实践**：若真改 `.app` 名，先做一次权限快照（系统设置里逐项截图 / `tccutil` 不做重置），改名后逐项点验；任何一项失效即回装旧名包（`dist` 里保留上一版），恢复路径明确。

### 4.7 截图目录 `~/Pictures/NetworkMonitor Snips`

- 实测已有用户截图 904 KB（`Snipaste_2026-11-09_*.png` 等）。改目录名而不迁移 = 历史截图在 Finder「最近」里指向旧路径、设置页「存储」占用显示 0。**迁移时 mv 旧目录内容并入新目录，保留文件名。**

### 4.8 互传接收目录 `~/Downloads/局域网互传`

- 已是中文且实测为空；但设置里可能存着用户自定义的接收目录偏好（`TransferPreferences.resolvedReceiveDirectory`，:180-183）。**默认不动**。

## 七、一次性迁移脚本（批次 5 专用，草案，未执行）

原则：只做 `mv`、先失败后成功、幂等、可回滚、失败时把旧目录留在原处并打印路径。

```bash
#!/bin/bash
# 数据目录迁移：macMonitor → <中文名>（幂等；失败不动旧目录）
set -euo pipefail
OLD="$HOME/Library/Application Support/macMonitor"
NEW="$HOME/Library/Application Support/<中文名>"
APP="/Applications/NetworkMonitor.app"   # 迁移前先确认新包已就位
[ -d "$APP" ] || { echo "❌ 新包不在 $APP，中止"; exit 1; }
if [ ! -d "$OLD" ]; then echo "ℹ️ 无旧目录，跳过"; exit 0; fi
if [ -d "$NEW" ] && [ -n "$(ls -A "$NEW" 2>/dev/null)" ]; then
  echo "❌ 目标目录已存在且非空：$NEW"; exit 1; fi
# 先判应用没在跑，避免 WAL 写到一半被搬
pgrep -f "^$APP/Contents/MacOS/" >/dev/null && { echo "❌ 应用仍在运行"; exit 1; }
mv "$OLD" "$NEW"
# 校验三件套：库 / 密钥 / 图片
for f in monitor.db credentials.key clipboard/images; do
  [ -e "$NEW/$f" ] || { echo "❌ 迁移后缺少 $f，回滚"; mv "$NEW" "$OLD"; exit 1; }
done
codesign -v "$APP" 2>/dev/null || echo "⚠️ 签名校验异常，请复核"
echo "✅ 已迁移到 $NEW（旧路径：$OLD）"
```

配套改动（同一次提交内完成，否则新库在旧目录重建，等于双写）：
1. DatabaseManager.swift:37、EncryptedSecretStore.swift:135、ClipboardImageStore.swift:40 三处常量改为新目录名；
2. README.md:145-146、189 三处数据路径说明；
3. `docs/踩坑/运行时/凭据加密存储.md:12`、`docs/设计/剪贴板历史-设计规格.md:101`、`docs/设计/剪贴板对标-OneClip-增量设计规格.md:34`、`docs/设计/全项目体检报告.md:50` 里的路径说明；
4. 迁移脚本**只由用户手动执行一次**，不接入打包流程（自动迁移在异常时会变成两台设备各写一个库）。

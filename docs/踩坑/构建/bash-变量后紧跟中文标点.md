# bash 变量后紧跟中文标点导致 unbound variable

> **何时阅读：** 脚本报 `变量名）: unbound variable` 而变量明明已定义；或脚本莫名提前退出、但下游检查仍然是绿的。

## 问题描述

在 `set -u` 下，变量后面紧跟全角标点时，bash 会把全角标点的字节一并吃进变量名，于是报：

```
VAR）: unbound variable
```

配合 `set -e`，脚本会在这里直接中断。

更隐蔽的是**假绿**：脚本中断之后，后续的 `codesign -dv` 仍会对 linker 自带的签名返回 `exit 0`，于是整条流水线看起来一切正常——实际上脚本后半部分根本没执行，校验的也只是 linker 的临时签名。

## 触发条件

- 脚本使用 `set -u`（本仓库脚本普遍带 `set -e`，两者叠加时表现为直接中断）
- 变量后**紧挨着**中文 / 全角标点：`（`、`）`、`，`、`。`、`、`、`：` 等（全角字符是多字节 UTF-8，bash 不会把它当作变量名分隔符）
- 变量虽写在双引号内，但没有用花括号包裹

## 解决方案

```bash
# ❌ 错误：全角左括号被吃进变量名
echo "$APP_NAME（release）"

# ❌ 错误：多写一层反斜杠，会把反斜杠当字面量输出
echo "\${APP_NAME}（release）"

# ✅ 正确：一律用 ${} 包裹
echo "${APP_NAME}（release）"
```

**规则：凡变量后紧跟中文 / 全角标点，一律写 `${VAR}`。** 也不要用反斜杠去转义（那会输出一个字面量的反斜杠）。

## 如何识别

典型特征是「**脚本提前退出，但下游检查仍然是绿的**」——尤其是脚本没有明显报错、或者报错被后续 `echo` 冲掉的时候。`bash -n` 查不出来（语法本身完全合法），需要人工扫一遍脚本里 `"$VAR` 后面紧跟非 ASCII 字符的位置。

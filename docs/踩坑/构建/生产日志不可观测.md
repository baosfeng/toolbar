# 生产日志不可观测

> **何时阅读：** 应用已经启动、行为却查不到任何日志；或终端里能看到日志、双击 / `open` 启动后什么都没有。

## 问题描述

经 LaunchServices（Finder 双击、`open Foo.app`）启动的 .app **没有连接到终端**，进程的 stdout/stderr 被丢弃到系统黑洞。因此只要默认 logger 是 `ConsoleLogger`（内部是 `print`），生产环境就是**零日志可观测**——不是没打日志，是打出来的东西没人接得住。

本项目默认值正是如此：`AppContext.shared.logger` 初始化为 `ConsoleLogger()`；`OSLogLogger` 只有在组合根显式调用 `AppContext.shared.configure(logger:)` 之后才生效（`configure` 是唯一注入点，没有默认分支会走到 OSLog）。

## 触发条件

- 从 Finder / `open` / LaunchServices 启动，而非在终端里跑 `swift run`
- `AppContext.shared.configure(logger:)` 未被调用（缺这一步就仍是 `ConsoleLogger`）
- 注入点晚于第一句日志：`AppCoordinator.init()` 里就有 `logger.info`，`configure` 必须比它更早

## 解决方案

在组合根、**第一句日志之前**注入 OSLogLogger（`AppDelegate.applicationDidFinishLaunching` 首行）：

```swift
AppContext.shared.configure(logger: OSLogLogger(category: "App"))
```

查看日志（必须带 `--info`，info 级默认不显示；`--debug` 用于 debug 级）：

```bash
log show --last 3m --info --debug --predicate 'subsystem == "com.networkmonitor"'
```

**规则：任何 .app 形态交付物的日志一律走 OSLog（`subsystem == "com.networkmonitor"`），不要依赖 stdout。**

## 如何识别

终端里跑正常、装到 `/Applications` 后「一条日志都没有」——先怀疑 logger 没注入，而不是逻辑没执行；反向确认是 `log show` 对该 subsystem 查不到任何记录。

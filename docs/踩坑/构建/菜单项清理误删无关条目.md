# 菜单项清理误删无关条目

> **何时阅读：** 菜单入口代码里建了却永远看不到；或菜单里只剩一条孤零零的分隔线。

## 症状

- 入口代码写了、启动不报错，用户却从来看不到（如剪贴板历史 / 剪贴板设置）
- 菜单里残留**孤立分隔线**：两侧本该有条目，却只剩分隔线

## 根因

清理动态条目的判据被写成了**无界阈值扫描**：`if item.tag >= tokenHourBaseTag { menu.removeItem(item) }`。

NSMenu 的 tag 是**跨模块共享的扁平命名空间**（4200+ 每小时条目、5100 AI 分析、7001/7002 剪贴板入口挂在同一个菜单上）。「阈值以上」没有上界，别的模块后来新增的高位 tag 就落进清理范围，在 `menuWillOpen`（菜单显示前）被静默 `removeItem`——不崩、不报错，只是入口永远不出现。这类缺陷只在「别的模块新增 tag」时才显形，模块自身测试发现不了。

## 正确写法

共享 tag 命名空间必须用**有界区间** `[base, base + span)`，判定收敛到 Core 的单一纯函数，App 层与测试共用同一份规则：

```swift
// ✅ 有界：只清理自己区间内的条目
public enum MenuTagRange {
    public static let hourlyBaseTag = 4200
    public static let hourlySpan = 100
    public static func isDynamicHourlyTag(_ tag: Int) -> Bool {
        tag >= hourlyBaseTag && tag < hourlyBaseTag + hourlySpan
    }
}
```

- 移除 / 清理类判据**禁止**「`tag >= 阈值`」这种「阈值以上全部」的无界扫描
- 区间跨度显式声明（`span`），给其他模块的高位 tag 留出明确空隙
- 判定放 Core 纯函数（TestRunner 拿不到 AppKit 类型），并反向断言外部 tag（7001/7002/5100）不该被清理

## 诊断线索

菜单里出现**孤立分隔线**（两侧本应有条目却只剩分隔线），即高度怀疑被同类无界扫描误删：分隔线 tag=0 不在扫描范围所以留下，两侧条目的 tag 落进了扫描范围。在清理处断点或打日志，确认被 `removeItem` 的 tag 是否属于本模块。

# 菜单栏与系统页的三个死开关（2026-11 处置）

> 症状：设置页上有控件，改了却完全没有反应 —— 不是「慢一拍」，是**永远不生效**。

## 现场与成因

| 设置项 | 写的键 | 消费方 | 为什么是死的 |
|---|---|---|---|
| 通用 → 菜单栏显示方式 → **间隔**（1/2/5 s） | `menuBar.refreshInterval` | 无 | `MenuBarManager.applyDisplayPreferences` 只读**渲染档**的 `tickInterval`（`RenderTierProfile`）。渲染档引入后节拍被它接管，这个键从此没有读者 |
| 系统 → **采样周期**（0.5/1/2/5 s） | `systemMonitor.sampleInterval` | `SystemMonitor(interval:)` | 该值只喂构造器，而 `SystemMonitor.start()` **从未被调用**（采样由 `MenuBarManager` 的 1 秒轮询链按 `systemSampleInterval` 节流，后者取自渲染档）。行副标题「重启应用后生效」也是错的 |
| 通用 → **超限告警**（alertsEnabled + CPU/内存阈值） | `menuBar.alertsEnabled` / `cpuAlert` / `memoryAlert` | `MenuBarManager.update()` | 消费端写好了（超阈给标题加 ⚠️），但**从来没有任何控件写过这三个键** —— 永远是 false |

前两个是「同一维度上有两个旋钮」：渲染档接管了节拍，但旧旋钮仍留在 UI 上装作可调。
`darkMode` 之类「迁移到新机制」时最容易漏的正是这种**旧控件没下线**。

第三个是反过来的：**业务逻辑写完了、UI 没接**，功能实际从未上线过（`alertsEnabled` 全仓只有读写键与消费端，设置页零引用）。

## 实测证据

```bash
# 1) 间隔：写 5 秒后定时器周期仍是 1 秒
#    当时靠已移除的 NM_DISPLAY_EVIDENCE 探针逐项写偏好并回读状态栏文本：
#    NM_DISPLAY_EVIDENCE=1 NM_EVIDENCE_SUITE=nm-probe /Applications/一览.app/Contents/MacOS/一览
#    grep 'twoLine+full+5s' /tmp/nm-display-evidence.txt  → interval=1.0s（期望 5.0s）
#    该探针与 /tmp/nm-display-evidence.txt 链路已随 Debug/ 删除；今天改完设置要人眼点一次「外观」页确认即时生效

# 2) 超限告警：手写键后确实生效（证明只差 UI）
defaults write com.bsfeng.yilan menuBar.metrics -string "downSpeed,cpu,memory"
defaults write com.bsfeng.yilan menuBar.alertsEnabled -bool true
defaults write com.bsfeng.yilan menuBar.cpuAlert -float 0.01
nmcli menubar 一览
# → title=⚠️ ↓21K  CPU 14%  MEM 62%
```

## 做法

- **间隔**：删行 + 删动作 + 删回灌，卡片说明改成「刷新节拍由外观 → 渲染帧率决定」。
  保留两个旋钮只会让用户选完发现没变。
- **采样周期**：删行，系统页页头胶囊改显示渲染档的真实采样秒数（显示真值，不显示用户填过的值）。
- **超限告警**：补一张自包含卡片 `SettingsMenuBarAlertCard`（开关 + 两个阈值下拉，50%…95%），
  写偏好后发 `AppEvents.postMenuBarDisplayChanged()`。

## 复跑

```bash
# 告警链路端到端（含还原）
defaults write com.bsfeng.yilan menuBar.metrics -string "downSpeed,cpu,memory"
defaults write com.bsfeng.yilan menuBar.alertsEnabled -bool true
defaults write com.bsfeng.yilan menuBar.cpuAlert -float 0.01
sleep 3 && nmcli menubar 一览 | sed -n '2p'   # 期望带 ⚠️ 前缀
```

## 一条自查口径

设置页的每一行都要能回答「我写的键，谁在读」。
`grep -rn 'menuBar.refreshInterval\|systemMonitor.sampleInterval\|menuBar.alertsEnabled' NetworkMonitor/Sources`
命中的如果只有「定义 + 写入口」，那它就是死开关。

# 抓屏路径拿不到图会让进程直接崩

> **何时阅读：** 按截图热键后应用直接消失（无覆盖层、无提示音）；崩溃报告里是
> `Unexpectedly found nil while implicitly unwrapping an Optional value`，线程是 `com.apple.root.user-initiated-qos`。

## 问题描述

`SCScreenshotManager.captureImage(in:)`（macOS 15.2 的「按矩形抓」）导入到 Swift 的签名是
`async throws -> CGImage`（**非可选**）。系统内部在拿不到图时（锁屏、屏幕休眠、捕获会话失败）
返回 nil，Swift 的 checked completion handler 桥接立刻触发
`_diagnoseUnexpectedNilOptional` 断言：

- 崩溃发生在**系统回调线程**，不是调用方的线程；
- 因此调用方那套 `do/catch` 的多路径降级**完全救不回来**——错误根本不会作为 throw 抛出来；
- 本机实测（macOS 27.0.1，锁屏状态）：按一次截图热键，进程立刻消失，崩溃栈顶是
  `checked @objc completion handler block ... with result type CGImageRef`。

同样的锁屏状态下 `screencapture -x` 会产出纯黑图（实测 3024×1964、平均亮度 0.0）——
这是判断「是不是锁屏导致的」最快的旁证。

## 解决方案

- **把这条路径从降级链里彻底移除**，不要用 try/catch 包围：它崩在回调线程，包不住。
- 首选留 `SCScreenshotManager.captureScreenshot(rect:configuration:)`（macOS 26+）：
  它返回 `SCScreenshotOutput`，`sdrImage` 是可选值，拿不到图只是 nil，可以正常降级。
- 兜底留 `SCContentFilter` 路径：它自带完整的 throw 语义（`displayUnavailable` 等）。
- 判断要不要保留一条抓屏路径的**唯一标准**：Swift 侧签名是不是可选返回值。
  非可选的 Objective-C 回调 API 一旦系统返回 nil 就是进程级崩溃。

## 如何识别

- 崩溃报告里出现 `_diagnoseUnexpectedNilOptional` + `checked @objc completion handler` → 就是这类。
- 同一次会话里 `screencapture -x` 出纯黑图 → 先怀疑锁屏 / 息屏，再怀疑权限。
- 权限本身正常（`CGPreflightScreenCaptureAccess() == true`）却拿不到图 → 不是 TCC 问题。

# 截图工具条按钮被前序分支挡住

> **何时阅读：** 工具条上的按钮点了没反应，或按 ⌘S / ⌘A 结果选区挪了一格。

## 问题描述

两处「分发顺序」问题，都表现为「按钮按了没反应」：

1. **键位分支顺序**：覆盖层的键位判断里，裸字母分支（微调选区）写在带 ⌘ 的分支之前，
   而 `case "a"` / `case "s"` 会把按键先吃掉 —— ⌘A 全选与 ⌘S 保存从来没触发过，
   用户按 ⌘S 只看到选区挪了 1 点。
2. **工具条宽度与布局各算一遍**：`preferredWidth` 与逐组摆放按钮是两份独立的累加式，
   前者多算了一段组间宽度、后者末尾多算了一个组内间隙，整条工具条右侧比左侧多出 17pt 空白，
   观感像按钮被挤向左边、右边缘发虚（869 × 40 的画布里左侧 8pt、右侧 25pt）。

## 解决方案

- 键位：解析抽成 `SnipKeyCommandResolver.resolve`（纯函数）。带 ⌘ 的组合先走字母分支，
  其余键码才查表；`resolve` 返回 `.none` 表示「不归覆盖层管」，直接交回系统。
- 布局：宽度与按钮位置由 `SnipToolBarLayout.plan` 一次算出（同一份 plan 同时给出
  `width` 与四组 `rects`），左内边距与右内边距必然相等；空组不占位也不发分隔线。
- 保存链路：`didRequestSave` 早期走「纯裁剪 + 把标注当参数传下去、下游却没消费」，
  画了矩形箭头再保存，文件里干干净净。统一改为 `composedImage`，与复制 / 贴图同一份产物。

## 如何识别

- 按 ⌘S 时选区动了 → 键位分支被裸字母遮蔽。
- 工具条右侧留白明显比左侧宽 → 宽度与布局是两份累加式。
- 存下来的 PNG 没有标注、复制粘贴的却有 → 保存链路没走合成。

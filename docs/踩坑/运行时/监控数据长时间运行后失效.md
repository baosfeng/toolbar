# 监控数据在长时间运行后失效

> **何时阅读：** 排查「额度页整页空白」「今日流量恒为 0 KB」「面板有网速但数据不更新」时。

## 两个独立故障，症状容易混为一谈

| 症状 | 根因 | 触发条件 |
|------|------|----------|
| 额度页只剩页头云图标与「—」，无 provider 名、无凭据输入框、无错误条 | `BillingMonitor.refresh()` 在 `isPaused` 时直接 `return`，从不 `emit()`，面板停留在从未更新的初始态 | 启动时屏幕锁定 → `pause()`；解锁通知丢失 → 永久暂停 |
| 今日下行/上行恒 0 KB，近 6 日柱状图今天柱为 0 | `TrafficTracker` 的当日基准 `dayStartRx` 大于当前累计 `totalRx`，`todayRx` 走 `max(0, …)` 分支恒为 0 | 崩溃或被强杀后重启，`totalRx` 从更旧的持久化值恢复 |

## 故障 1：通知丢失导致额度页永久暂停

`ScreenActivityMonitor` 原先只依赖 `NSWorkspace` 与 `DistributedNotificationCenter` 的休眠/锁屏通知。
收到 `screensDidSleep` 后若丢失对应的 `screensDidWake`（合盖唤醒、外接显示器、系统版本通知行为变化），`isPaused` 会一直为 `true`。
此时 `refresh()` 静默返回，`lsof -p <pid> -i` 看不到任何对外连接 —— 这是「不发请求」而非「请求失败」的判别特征。

**修复三件套：**

1. `BillingMonitor.refresh()` 暂停时仍回报一次快照（`didReportWhilePaused` 去重，避免每秒 emit 触发布局），面板至少显示已有数据或凭据配置态。
2. `ScreenActivityMonitor` 每 30 秒自检 `CGSessionCopyCurrentDictionary`（锁屏）+ `CGDisplayIsAsleep`（显示器休眠），与事件通知互为兜底。
3. 判别口诀：面板空白 + 无对外连接 = 暂停态短路；面板有错误条 = 真的请求失败。

## 故障 2：累计流量回退让今日统计恒 0

`totalRx` / `totalTx` 原先只在 `applicationWillTerminate` 落盘。崩溃、`kill -9`、部署脚本强杀都会绕过它，
重启后读到的是更旧的较小值；而当日基准 `dayStartRx` 是零点日切时写入的较大值，两者一起就锁死了 `todayRx = 0`。

实机证据（2026-10-24）：`dayStartRx = 112462691328`，`totalRx = 106273455104`，差额 5.8 GB 需真实流量才能追平。

**修复两件套：**

1. `TrafficTracker.resolveBaseline(currentRx:currentTx:storedRx:storedTx:)`：检测累计回退时以当前累计重建基准并落盘，正常增长时沿用原基准（纯函数，可直接单测）。
2. `AppCoordinator` 每 60 秒落盘一次 `totalRx` / `totalTx`，把崩溃丢失窗口从「一整天」压到「1 分钟」。

## 验证方式

```bash
# 基准是否已重建（两值应相等，或基准小于累计）
defaults read com.example.NetworkMonitor | grep -E 'dayStartRx|totalRx'

# 暂停态自检：投递一次假锁屏通知，面板应仍有数据；30 秒后时间戳应自动更新
/tmp/postnotif com.apple.screenIsLocked   # 见下方说明
```

自检是否生效的判据是额度页右上角时间戳：暂停期间停住，30 秒内自动跳动即说明 watchdog 生效。

## 教训

- 事件驱动 + 无兜底的轮询暂停开关，一旦丢事件就是永久静默；凡是「暂停」都必须配自检与可观测的 UI 状态。
- 累计计数器落盘周期决定了统计口径的鲁棒性；只在退出时保存等于把正确性押在「进程一定能优雅退出」上。

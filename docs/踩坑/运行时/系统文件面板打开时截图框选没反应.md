# 系统文件面板打开时截图框选没反应

> **何时阅读：** 在「选择目录 / 另存为」这类系统文件面板打开时按截图热键，覆盖层出来了，
> 但鼠标拖拽选区毫无反应（回车也没用）；关掉面板再截就正常。

## 问题描述

用户口径：「打开系统文件浏览器，比如选择目录的时候，这个时候无法截图」。

实测（macOS 27，设置页「截图与贴图 → 快速保存目录 → 选择…」开着 NSOpenPanel）：

| 操作 | 结果 |
|------|------|
| ⌥⌘A 触发截图 | 覆盖层正常上屏（layer 1000、全屏 1512×982），日志「截图覆盖层已就绪」 |
| ⌘A → 回车 | **成功**：「已复制选区 1512×982」 |
| 鼠标拖拽 500×400 → 回车 | **失败**：没有任何「已复制选区」日志，覆盖层只能 Esc 收掉 |

## 根因

App 内存在 **app-modal session**（`NSOpenPanel.runModal()` / `NSSavePanel.runModal()` / `NSAlert.runModal()`）时，
AppKit 的事件路由是**不对称**的：

- **键盘**仍然派给 key window → 覆盖层（`.nonactivatingPanel`）拿得到 ⌘A / 回车 / Esc；
- **鼠标**只派给模态窗口及其子窗口 → 覆盖层的 `mouseDown` / `mouseDragged` 全被模态窗口吃掉。

于是表现为「覆盖层看得见、键盘能用、鼠标没反应」。这一条不对称也是最快的识别判据。

为什么不能靠 `childWindow` 绕：macOS 的 child window 会被裁剪到父窗口可见区域，
880×448 的文件面板做父窗口时，全屏覆盖层根本铺不开。

## 解决方案

`Snip/SnipForegroundPolicy.swift` 新增 `dismissAppModalIfNeeded()`（与抢前台同一个策略出口）：

```swift
@discardableResult
static func dismissAppModalIfNeeded() -> Bool {
    guard let modal = NSApp.modalWindow else { return false }
    NSApp.stopModal(withCode: .cancel)
    modal.orderOut(nil)
    return true
}
```

`SnipController.beginSnip()` 的异步抓屏 Task 在**抓屏之前**调用它，返回 true 时再等 80 ms
（等面板真的从屏幕撤走，否则文件面板会被一起拍进截图）。

代价：用户正在做的「选目录 / 另存为」会被取消，需要重新点一次；面板以 `.cancel` 返回，
不写任何偏好、不丢已确认的选择。这比「按了截图完全不响应」可接受。

## 如何识别

```bash
# 1) 有 app-modal 时打这行日志（新增）
log show --predicate 'subsystem == "com.networkmonitor"' --last 2m --info \
  | grep '截图前结束 App 模态会话'

# 2) 复现脚本：文件面板打开时注入 ⌥⌘A + 鼠标拖拽 + 回车，看有没有「已复制选区」
#    （拖拽后无该日志 = 鼠标事件被模态窗口吃掉）
```

排查顺序：先确认「键盘能用、鼠标不能用」这条不对称，再去看 `NSApp.modalWindow`，
不要先怀疑覆盖层没拿到焦点（`isKeyWindow` 在这个场景下是 true）。

# 竖直 NSStackView 不设 distribution 会散开空白

> **何时阅读：** 界面里同一列内容「上半截在这一头、下半截在那一头，中间空一大块」；
> 或某个页面第一次打开有空白、再来一次就正常。

## 问题描述

`NSStackView` 的 `distribution` 默认是 `.gravityAreas`（不是 `.fill`）。
容器比内容高时，它会把这些多余高度**均分到 gravity 区之间**——看上去就是
「标题贴顶、卡片掉到底、中间一整段是空的」。

本项目实测：统一设置窗口首次打开时，页头在 y≈30、第一张卡在 y≈250，
中间空了 200pt+；关掉再打开就正常。

## 为什么「第二次就好了」

第一次打开时，内容容器高度先按视口被撑满（约束里是
`heightAnchor >= scrollView.contentView.heightAnchor`），正好命中
「容器比内容高」这个条件；第二次进入时高度已经被上一轮算准，不再多余。

## 解决方案

竖直栈一律显式声明分配方式，并在尾部放一个弹性空白把多余高度吸到底：

```swift
stack.orientation = .vertical
stack.alignment = .leading
stack.distribution = .fill          // 关键：默认是 .gravityAreas

let tail = NSView()
tail.setContentHuggingPriority(NSLayoutConstraint.Priority(1), for: .vertical)
stack.addArrangedSubview(tail)      // 多余高度全给它
```

本仓库已按此修正：`SettingsPageStack`、其 `contentStack`、`SettingsCardView.rows`、
剪贴板「忽略的应用」列表栈。

## 如何识别

- 同一次会话里「第一次打开异常、再打开正常」——先怀疑布局时序，而不是数据；
- 用 `sample` 看不到卡顿、日志也没有错误，但版式明显不对；
- 用「不做任何显式布局」的离屏渲染能稳定复现：
  `SettingsSnapshot.captureFirstOpen` 就是为此加的（原 `capture` 会先
  `layoutSubtreeIfNeeded()`，所以它一直没暴露这个问题）。

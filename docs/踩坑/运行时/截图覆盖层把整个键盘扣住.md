# 截图覆盖层把整个键盘扣住

> **何时阅读：** 截图覆盖层出现后，⌘Tab / ⌘Q / ⌘空格 失灵，或者文字标注输入框里打不进字。

## 问题描述

为了让「菜单栏 App 不是前台时也能接住 Esc」，覆盖层装了一条 `CGEventTap`。
早期实现里 tap 的回调写的是：

```swift
return bridge.shouldSwallow() ? nil : Unmanaged.passUnretained(event)
```

而 `shouldSwallow()` 只看「tap 装着 + 不在编辑文字」，等于覆盖层期间**所有按键都被吞掉**。
后果有两个方向：

- 系统快捷键全部失效：⌘Tab 切不了窗口、⌘Q 退不掉 App、⌘空格调不出输入法。
- 文字标注打不进字：输入框里的字母先被 tap 吞掉，然后在接收端又被 `hasActiveTextInput` 忽略，
  等于既吞了又没人消费。

## 解决方案

拦截判定改为显式白名单，并抽成 `NetworkMonitorUI` 里的纯函数（可单测）：

- `SnipKeyboardInterception.shouldIntercept` —— 只有覆盖层真有语义的键才接管
  （Esc / 回车 / 空格 / Tab / 方向键 / 逗号 / 句号 / 反引号，以及 ⌘C ⌘S ⌘⇧S ⌘A ⌘T ⌘R ⌘Z ⌘⇧Z）。
- `SnipKeyboardRouting.decision` —— 三态：无覆盖层 `.ignore`、正在输入文字 `.passThrough`、
  命中白名单 `.swallow`。
- 带 ⌘ 的组合先于键码表判定：否则 ⌘Tab（键码 48 正好是覆盖层的「切窗口检测」）和
  裸字母（⌘S 键码 1 正好是「选区下移」）都会被吃掉。
- 字符由系统解码（`CGEvent.keyboardGetUnicodeString`）后带过主线程，不再用硬编码键码表，
  否则 Dvorak / 非美式布局下 ⌘C 之类的组合会解析错。

## 如何识别

- 覆盖层在屏时按 ⌘Tab 没反应、按 ⌘Q 退不掉 → 拦截判定写宽了。
- 文字标注点了没反应、输入框里敲字不出现 → 拦截判定没给编辑态放行。
- 单测 `runSnipKeyboardInterceptionTests` / `runSnipKeyboardRoutingTests` 会直接报出来。

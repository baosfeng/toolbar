# 截图复制了却不在剪贴板历史里

> **何时阅读：** 截图后点了复制（或回车），剪贴板里能粘贴，但「一览」的剪贴板历史里找不到这张图；
> 小图（几百像素）正常，全屏 / 大区域截图才丢。

## 问题描述

用户口径：「我们自己的截图复制了，但是没有到我们自己的剪贴板里面」。

实测（macOS 27 / 3024×1964 全屏 Retina）：

| 观察点 | 结果 |
|--------|------|
| 系统剪贴板 | `changeCount` 从 317 → 318，内容确实是刚截的图 |
| 系统剪贴板表示 | 只有 `public.tiff`，**23,762,458 字节（22.7 MB）** |
| 剪贴板历史 | 没有新增条目；OCR / 缩略图都不触发（等于采集端整条没接住） |
| 小图（499×384） | 正常入库 |

## 根因

两个缺陷叠在一起：

1. **写入侧只写未压缩 TIFF**：`SnipController.copyToPasteboard` 与 `PinWindowController.copyImage`
   都用 `pasteboard.writeObjects([NSImage])`。NSImage 作为剪贴板载体只提供 `public.tiff`，
   而 TIFF 是未压缩位图（字节 ≈ 像素数 × 4），全屏 Retina 就是 22.7 MB。
2. **采集侧超限即静默丢弃**：`ClipboardLimit.maxImageBytes` 是 20 MB，`PasteboardWatcher`
   的图片解析对超限候选直接 `continue`；没有更小的候选时整条返回 nil，
   只在 **debug** 级日志留一句「图片为空或超过压缩字节上限，跳过落库」——
   生产 `OSLogLogger` 的 `minLevel` 是 `.info`，这句根本不落盘，所以现场完全无迹可查。

结论：**全屏截图（约 2600×900 点以上）必然超过 20 MB**，所以「大的截不进去、小的正常」。

## 解决方案

写入侧（`Snip/SnipPasteboardImageWriter.swift`，截图与贴图复制共用的唯一出口）：

- 优先写 `public.png`（同尺寸实测 40 ms、体积小两个数量级）；
- 小图（≤ 400 万像素）额外补一份 `public.tiff`，兼容只认 TIFF 的老 App；
- 大图**不写** TIFF——未压缩位图塞进系统剪贴板既超采集上限，也让其它 App 粘贴时解一张巨图。

采集侧（`ClipboardImageCandidateSelection` + `PasteboardWatcher+Images`）：

- 候选顺序不变（PNG 在 TIFF 前），先取不超过上限的第一个；
- **全部超限时不再丢弃**：取第一个超限候选并标 `isOversized`，后台只读头部尺寸，
  产出一条占位记录「图片 3024×1964（原图超过 20MB 上限，未保存）」；
- 这条判定是纯函数（Core `ClipboardImageCandidateSelection` / UI `SnipPasteboardRepresentationPlan`），
  TestRunner 直接断言，不必构造 22 MB 的位图。

## 如何识别

```bash
# 1) 当前剪贴板里有什么、多大（NSImage 写出的会是 public.tiff 且体积巨大）
cat > /tmp/pbsize.swift <<'SWIFT'
import AppKit
let pb = NSPasteboard.general
for (i, item) in (pb.pasteboardItems ?? []).enumerated() {
    for t in item.types { if let d = item.data(forType: t) {
        print("item\(i) \(t.rawValue) = \(d.count) bytes") } }
}
SWIFT
swift /tmp/pbsize.swift

# 2) 历史里有没有落库（image_path 为 NULL 且 preview 写「未保存」= 占位降级）
sqlite3 "file:$HOME/Library/Application Support/macMonitor/monitor.db?mode=ro" \
  "select kind, datetime(created_at,'unixepoch','localtime'), preview, image_path from clipboard_items order by created_at desc limit 3;"

# 3) 采集是否被拒绝（只有超限 / 像素守卫拒绝才会写占位，其余静默跳过都是 debug 级）
log show --predicate 'subsystem == "com.networkmonitor"' --last 5m --info | grep -E '剪贴板图片|超过单图'
```

判据不对称：**能粘贴到别的 App，但历史里没有** → 优先查写入侧的表示与体积，不要先怀疑采集器没启动
（采集器正常时日志里有「剪贴板采集运行中」）。

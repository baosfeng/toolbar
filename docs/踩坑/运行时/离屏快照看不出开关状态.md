# 离屏快照看不出开关状态与布局分叉

> **何时阅读：** 用 `NM_SNAPSHOT_DIR` / `NM_SNIP_TOOLBAR_SNAPSHOT_DIR` 做离屏取证时，图看着没问题但真实行为不对；
> 或者改了布局算法，快照里按钮位置和宽度对不上。

## 问题描述

本轮做截图工具条的文字提示与自定义时遇到三类「图看不出、但确实是 bug」的情况：

1. **`NSSwitch` 的 on/off 在离屏渲染里几乎不可辨。** 设置页快照上「工具条显示」四行
   的开关全画成了浅灰关态，肉眼看不出是「偏好没灌进去」还是「开关就是这么渲染」。
   实测把控件勾选态与偏好真值并排落盘才判清：状态其实是对的（`groups: tools=true/on ...`）。
2. **首次进入设置页不刷新。** 控件只在 `SettingsPaneView.refresh()` 里灌状态，而
   首次进页与离屏快照都不走 refresh 的「切页」分支（`select()` 时才调），
   于是首帧一片关态。修法：`buildToolBarCard()` 末尾自己再灌一次 `refreshToolBar()`。
3. **条宽按老顺序算、按钮按新顺序摆。** 布局曾把「整条宽度」与「逐组摆放」各写一遍累加式，
   加入组顺序 / 组显隐后两处必然分叉（表现是右侧多出空白，或按钮越出条边界）。
   修法：宽度与按钮矩形都由同一个 `plan(config:)` 产出，右内边距恒等由测试断言。

## 解决方案

- 离屏取证要**同时落一份文本状态**：把关键控件的勾选态与偏好真值写成一行写进快照目录
  （`settings-toolbar-states.txt` / `settings-clipboard-states.txt`），图只用于看版式，状态判定以文本为准。
  两者写成 `偏好真值/控件勾选态` 并附「一致=」判定：
  剪贴板页「操作音效 / 触觉反馈」实测输出 `sound=false/off haptics=true/on 一致=true`，
  图上两个开关都像关态，但触觉的偏好与控件都是开 —— 结论是 NSSwitch 离屏渲染不可辨，不是 refresh 时序 bug。
- 首次进页自己灌一次状态，不依赖「切页」触发的 refresh。
- 布局一律走「一个 plan 产出全部矩形 + 宽度」，禁止宽度与摆放两处各算一遍。
- 视觉档位变化（条高 40 → 50）要单独出一张快照，别用「默认档看着对」推断另一档也对：
  常驻标签档此前图标按按钮全宽绘制，图标被撑成 46pt 方块，标签还压住图标底部。

## 如何识别

- 快照图里开关「看着都是关的」→ 先落一份状态文本，再判断是不是真没灌进去。
- 首次打开 vs 再进一次表现不同 → 查控件状态是不是只在 `refresh()` 里灌。
- 改了布局后右边缘发虚 / 按钮越界 → 查宽度与摆放是否两份算法。

# NSPopover 顶端三角只画在窗口中心

> 症状：面板顶端那个小三角（beak）不指向菜单栏上被点的图标，而是指在状态项文字的偏左位置；
> 用户原话「详情页能不能对着我画的这个地方」，截图里用红框圈出「三角」和「面板右边缘」两处。

## 现场

用户截图（1512pt 逻辑宽、Retina 2x）逐像素量：

| 对象 | 位置 |
|---|---|

三角中心 **362.4px**、面板水平中心 **362.5px** —— 差 0.1px，说明**三角恒在窗口水平中心**，
与锚点矩形的位置、状态项的位置都无关。

再看状态项本身：面板右对齐到状态项右边缘（改造前的口径）时，窗口中心落在 956pt，
而状态项中心在 1038pt —— **三角偏左 82pt**，正指在「↓36K」那个字上。

换成 nmcli 现读的实时几何复算（面板 783,33 346x350 / 状态项 947,4.5 183x24）：

```text
状态项：947.0..1130.0，中心 1038.0
面板（右对齐口径）：783..1129，窗口中心 956.0
三角 = 窗口中心 = 956.0
错位 = 82.0 pt
```

## 试过但不成立的三种做法

| 做法 | 结果 |
|---|---|
| `popover.setValue(true, forKey: "shouldHideAnchor")` | 私有 KVC，show 前后设都返回 1，但**三角照画**（截图逐张比对一致） |
| 给 `_borderView` 的 `_maskImage` 设自定义蒙版 | 遮不住：三角由窗口合成层画，不在 borderView 的绘制路径上 |
| 在 borderView 上叠加自绘三角 | 能画出来，但要先把系统三角藏掉——上一条已证明藏不掉，两个三角会重叠 |

另有两条**看起来该生效但没生效**的：

- `positioningRect` 改成大幅左移的矩形：窗口确实跟着左移，但三角跟着窗口一起动（它本来就锁窗口中心）；
- `hasFullSizeContent = true`：只是去掉内容区四周 13pt 边距，三角位置不变。

结论：**三角位置不可控**。能控的只有窗口位置，所以让它对准的唯一办法是「让窗口中心落在状态项中心」。

## 做法

横向口径从「右对齐状态项右边缘」改成「**以状态项中心居中**」：

- `PanelAnchor.rect(for:)`：锚点 1pt 窄矩形改为 `x = bounds.midX - 0.5`（原来贴 `maxX`）；
- `PanelAnchor.pinnedX(panelWidth:statusItemCenterX:visibleMinX:visibleMaxX:)`：
  目标 x = 状态项中心 − 面板宽/2（原来 = 状态项右边缘 − 面板宽）；
- `PanelWindowPin`：展开时冻结的是**状态项中心**（原来冻结右边缘），其余时机与自愈逻辑不变。

宽度 1pt 这条不能丢：实测把 `button.bounds` 整个交进去，锚点矩形随状态项宽度变化，
面板 x 会跳 26pt；用 1pt 窄矩形时锚点中心 = `bounds.midX`，与宽度彻底无关。
三种宽度（120 / 175 / 220）下实测窗口中心与状态项中心残差都在 0.5pt 内。

## 验收（可复跑）

```bash
cd NetworkMonitor && SKIP_INSTALL=1 ./Scripts/build-app.sh
osascript -e 'quit app "一览"'; sleep 2
open -n dist/一览.app; sleep 5
./.build/debug/nmcli run 'click 一览 --role AXMenuBarItem --index 0; wait-window 一览 --layer 25; wait 900; menubar 一览; windows 一览 --layer 25'
```

判据：`windows` 给出的面板 `x + 宽/2` 等于 `menubar` 给出的状态项中心（残差 < 2pt）。
实测改后：面板 865,33 346x425（中心 1038）、状态项 949,4.5 181x24（中心 1039.5）——
三角中心像素实测 1037.7pt，与状态项中心差 1.8pt（含状态项文字在两次采样间变了 2pt）。

切页时位置恒定仍走进程内探针（这条与横向口径无关，但改完要一起复验）：

```bash
NM_PANEL_PIN_PROBE=1 dist/一览.app/Contents/MacOS/一览 2>&1 | grep PROBE_
```

判据：`PROBE_CORNERS` 只有一个取值。实测 `1212.0,949.0` 恒定、高度随分页变化。

## 取舍

「中心对齐」意味着面板右边缘会越出状态项右边缘（实测 865..1211，状态项右边缘 1130，
即向右多出 81pt）。这段区域是菜单栏右侧系统图标的**下方空白**，被面板盖住不影响点击，
且换来了三角真正指向被点的图标。

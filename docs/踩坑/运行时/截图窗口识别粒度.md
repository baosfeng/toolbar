# 截图窗口识别粒度：层级白名单与整屏容器

> **何时阅读：** 截图时只能框到普通窗口，菜单栏 / 程序坞 / 状态栏图标点不到；或者自家面板窗口识别不到。

## 问题描述

`ScreenCaptureService.windowInfos()` 原本只取 `kCGWindowLayer == 0`（普通窗口），
并把自家进程的窗口全部排除。两个后果：

1. 菜单栏、程序坞、状态栏项都识别不到 —— 用户口径是「没有像 Snipaste 一样能识别到菜单栏或者 dock 栏的图标」。
2. **自家面板窗口识别不到** —— 自家 `NSPopover` 在层级 25（statusItem 层），被「排除自家进程」一并干掉。

本机实测层级分布：普通窗口 0、程序坞 20、菜单栏整条 24、状态栏项 25、覆盖层 screenSaver 1000。

## 解决方案

- **白名单**：`SnipWindowLayer` 显式列举 0 / 20 / 24 / 25，`isSupported(layer)` 是唯一判据
  （调用方与测试共用）。新增层级要显式加一行，不会因为别处冒出别的数值被静默收进结果集。
- **自家进程分档**：只有层级 ≥ 1000（覆盖层量级）的自家窗口排除；普通窗口与 popover 照常保留。
- **尺寸豁免**：系统层级（20/24/25）不受 `minimumSide` 限制，否则 30×24 的状态栏项会被当成「太小」丢掉。
- **整屏容器的贴边带**：程序坞在 CGWindowList 里是**一个** 1512×982 的整屏窗口、不含图标位置信息。
  直接让它参与命中，屏幕任何位置都会命中程序坞。改为只在屏幕左 / 右 / 下三边的 96 点带内算命中，
  单击选窗时也只取那条带子（`selectionFrame`），否则点 Dock 图标会截出满屏。

## 已知局限

- 逐个 Dock 图标、逐个菜单栏菜单项**没有做**：CGWindowList 只给整条/整屏容器，
  逐图标要 Accessibility API（`AXUIElement` 遍历），是另一件事。
- 程序坞贴边带是几何一阶近似：Dock 停底部时，屏幕左右两侧的窄条也会被判成程序坞。

## 如何识别

- 点状态栏图标/菜单栏框不到 → 查层级白名单是否收进了 24 / 25。
- 自家面板框不到 → 查是不是「排除自家进程」写在尺寸过滤之前、且没有按层级分档。
- 屏幕任意位置都高亮程序坞 → 缺少贴边带判据。

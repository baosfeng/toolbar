# 截图覆盖层拿不到键盘与首帧绘制

> **何时阅读：** 截图键按下后覆盖层要么根本不出现，要么出现在屏上但 Esc / 回车 / ⌘C 毫无反应。

## 问题描述

截图链路上有三处彼此独立的故障，症状都表现为「按了截图键没反应」：

1. **覆盖层窗口不是 key window**：菜单栏 App 是 `LSUIElement`（`.accessory`），
   `NSApp.activate(ignoringOtherApps:)` 在 macOS 14 之后被标记废弃，且实测返回后
   `NSApp.isActive == true`、`overlay.isKeyWindow == true`，但系统 frontmost 仍是原 App，
   键盘事件继续投给原前台 → Esc / 回车时灵时不灵（实测 5 轮里 1~2 轮首下失效）。
2. **首帧拿不到 NSGraphicsContext**：`orderFrontRegardless` 之后 WindowServer 侧 back store
   还没建好，这一轮 `draw` 里 `NSGraphicsContext.current` 是 nil；早期实现直接 return，
   而 `needsDisplay` 已被清掉，没人再要求重绘 → 覆盖层永久留白。
3. **抓屏是异步的**：`captureAllDisplays()` 要几百毫秒，这段空档里重复按热键会各开一套覆盖层，
   按 Esc 只关掉一层，看起来像「Esc 时灵时不灵」（实测连按叠出两层）。

## 解决方案

- 窗口：`SnipOverlayWindow` 从 `NSWindow` 改为 `NSPanel` + `.nonactivatingPanel`，
  `becomesKeyOnlyIfNeeded = false`；截图开始前先 `setActivationPolicy(.regular)` + `activate`，
  并在抓屏期间轮询 `NSWorkspace.frontmostApplication.pid` 确认拿到前台；截图结束立刻切回 `.accessory`。
- 键盘：装一条 `CGEventTap`（系统层取键，不要求本 App 当前台），无「输入监控」权限时回落
  `NSEvent.addLocalMonitorForEvents`。拦截必须走白名单（见「截图覆盖层把整个键盘扣住」），
  否则整个键盘会被扣住。
- 首帧：`draw` 里无 context 时把重绘排到下一轮主循环（上限 6 次），不要静默早退。
- 重入：`beginSnip` 用一个「进行中」标志挡住重复触发；已有覆盖层时再按热键改成
  `refocusOverlays()`，把焦点抢回来而不是静默 return。

## 如何识别

- 覆盖层在屏但按键无反应 → 日志里找 `覆盖层未能成为键盘焦点` / `截图前未能在…取得前台`。
- 覆盖层一片黑或干脆看不见 → 看自证截图 `/tmp/nm-overlay-visible.png`（`NM_SNIP_VISIBLE_PROBE=1`），
  空图基本就是首帧没画。
- 连按热键叠出多层 → 日志里 `截图覆盖层已就绪，共 N 屏` 短时间内出现多次。

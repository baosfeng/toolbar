# 取色与马赛克的颜色偏移

> **何时阅读：** 截图取到的颜色和屏幕实际颜色不一样；或马赛克块是纯黑/纯白而不是平均色。

## 问题描述

把任意格式的 `CGImage` 重绘到固定格式的缓冲区后逐像素读取，颜色与源图对不上。表现为三种偏移：

1. 纯红 `(255,0,0)` 读出来是 `(255,38,0)` —— 肉眼可辨的偏色
2. 红蓝互换 —— 取到的颜色整体错位
3. 上下颠倒 —— 取到的是对称位置的颜色

三个原因各不相同，都会各自造成「看起来只是有点怪」的结果。

## 触发条件

- 用 `CGContext.draw(image:in:)` 把源图重绘到自建缓冲区再采样
- 没有显式指定 `bitmapInfo` 的字节序
- 缩小时用 `interpolationQuality = .none`

## 解决方案

三处都要改：

1. **色彩空间跟随源图**，不要固定 `CGColorSpaceCreateDeviceRGB()`。`CGColor(red:green:blue:)` 默认是 sRGB，画进 deviceRGB 上下文会做 ICC 转换，纯色被弄脏：

   ```swift
   let colorSpace = image.colorSpace ?? CGColorSpaceCreateDeviceRGB()
   ```

2. **显式大端字节序**，否则小端机器上 `premultipliedLast` 被解释成 BGRA，红蓝互换：

   ```swift
   let bitmapInfo = CGBitmapInfo.byteOrder32Big.rawValue | CGImageAlphaInfo.premultipliedLast.rawValue
   ```

3. **行序不需要翻转**。`CGContext` 绘制原点在左下，但缓冲区第 0 行实测就是图像顶行；按「左下原点」再翻一次会得到上下颠倒的采样。

马赛克另有独立坑：缩小时 `.none` 插值取的是最近邻单个像素，条纹图会变成纯黑/纯白。缩小时用 `.high` 得到块内平均色，放大时才用 `.none` 保持方块边缘。

## 如何识别

单测里断言「块内颜色一致」会**假绿** —— 整块都是纯白也一致。要同时断言「颜色既不是纯黑也不是纯白」，或者直接比对已知纯色图。

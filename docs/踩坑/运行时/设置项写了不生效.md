# 设置项写了却不生效：三个同源故障

> **何时阅读：** 在设置窗口里改了开关/下拉，界面没反应；或者过一会儿再打开设置，值又回退了。

## 问题描述

用户口径是「通用设置里面的设置几乎没有任何反应」「禁止了某个功能，详情页展开之后没有消失」
「自定义了快捷键，下次还是不会出现，又被还原了」。查下来是三个互不相干的故障：

1. **存储实例不同源**：`MenuPanelController` 里用 `MenuPanelView()` 默认构造，
   面板自己 new 了一份 `PanelTabPreferences()`，和设置页读写的是两个不同的存储实例。
   设置页把「系统」分页关掉，存进了另一份存储，面板永远读不到 → 完全没反应。
2. **只在 init 读一次**：即便存储同源，`MenuPanelView` 也只在初始化时读一次分页偏好，
   运行中改可见性不会重排分段条；当前页被隐藏时连二级详情页都不会收起。
3. **偏好没有消费方**：`MenuBarDisplayPreferences` 的 layout / unitStyle / refreshInterval
   三个只在设置页自己读写，`MenuBarManager` 从来没读过——定时器写死 1 秒、状态栏写死单行紧凑写法。
4. **把合法值当成「未设置」**：`SnipHotKeyPreferences.combo(for:)` 用 `guard code > 0` 判断
   「存过没有」，但 **A 键的 keyCode 就是 0**。于是 ⌘⌥A 被读成「未设置」→ 回落默认 ⌃⇧S →
   注册成功后 `setCombo` 又把默认值写回存储 → 用户的自定义被永久覆写。

## 解决方案

- **存储同源**：`MenuPanelView(storage:)` / `MenuBarManager(storage:)` 一律从构造器注入，
  整条链路共用组合根那一个实例；默认参数仍回落到 `AppContext.shared.storage`，老调用点零改动。
- **事件驱动**：新增 `AppEvents.panelTabsChanged` 与 `AppEvents.menuBarDisplayChanged`，
  设置页写存储后发事件；面板重排分段条（当前页被隐藏就切到第一个可见页并收起详情页），
  菜单栏重建定时器 / 换布局 / 换单位写法。
- **消费方必须存在**：判断「这个设置生效了吗」不看「写进存储了」，要看一次真实链路取证
  （写偏好 → 发事件 → 读状态栏文本与定时器周期），见 `Debug/DisplayPreferenceEvidence.swift`。
- **存在性判据**：用 `storage.object(forKey:) != nil` 判断键存过没有，绝不用值域判断
  （keyCode 0 是 A 键的合法值）；读路径缺键时回落默认但**不回写**，只有迁移与「注册成功后的真实生效值」才回写。

## 如何识别

- 设置全无反应 → 先查该偏好类的实例是不是在多处各自 `new` 了一份。
- 改完过一会回退 → 查读路径有没有在「缺键/非法值」时回写默认值。
- 只有部分开关生效 → 查 `AppEvents` 里有没有对应事件，以及谁在订阅。

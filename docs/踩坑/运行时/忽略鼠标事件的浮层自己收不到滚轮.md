# 忽略鼠标事件的浮层自己收不到滚轮

> **何时阅读：** 做了一个「悬停提示 / 只读预览」类浮层，既要求它不拦鼠标点击，又要求超长内容能在浮层内部滚动；
> 或者发现浮层弹出后滚轮完全没反应，事件被底下的列表吃掉。

## 问题描述

剪贴板卡片的全文浮层（悬停 0.45s 弹出）有两条硬性要求同时成立：

1. 浮层**不能拦鼠标**——用户还要能点卡片、点右键菜单，浮层只是「看一眼」的提示，
   因此面板设了 `ignoresMouseEvents = true`（`ClipboardCardFullTextOverlay.swift:171`）；
2. 正文超过 9 行时**要在浮层内部滚动**（`NSScrollView`）。

这两条直接冲突：`ignoresMouseEvents = true` 的窗口收不到任何鼠标事件，
`NSScrollView` 的滚动条与滚轮处理全在事件链路里，于是「滚动」这条需求天然落空——
浮层里能看到滚动条，却拖不动、滚不动。

## 解决方案

**滚轮由父视图转发，浮层只暴露一个纯函数入口。**

- 浮层提供 `scroll(by deltaY:) -> Bool`：只有浮层可见、内容确实超长（`maxY > 0`）时才消费这次滚动，
  自己改 `clipView.bounds.origin` 并 `reflectScrolledClipView`，返回 `true` 表示「已消费」；
- 卡片流在 `scrollWheel(with:)` 里先问浮层，消费掉就 `return`，否则走 `super` 交回列表：

```swift
// ClipboardCardFlowView.swift:241
override func scrollWheel(with event: NSEvent) {
    if ClipboardCardFullTextOverlay.shared.scroll(by: event.scrollingDeltaY) { return }
    super.scrollWheel(with: event)
}
```

- 判定「消费与否」必须是浮层的返回值，不能在外面按「浮层可见」猜：可见但内容不超长时
  仍要让滚轮落回卡片列表，否则列表在浮层展开期间会莫名滚不动。

## 如何识别

- 浮层里能看到滚动条、滚轮却没反应 → 先查浮层窗口是不是 `ignoresMouseEvents = true`；
- 浮层展开时列表也滚不动 → 查转发函数的「是否消费」判断是不是写成了「浮层可见即消费」；
- 浮层用 `.nonactivatingPanel` 且没收键盘事件时，同理：键盘处理要走面板的本地事件监听转发，
  别指望浮层自己拿到 `keyDown`。

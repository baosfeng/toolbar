# 系统通知音效与音频解码

> **何时阅读：** 做通知提示音、自定义音效上传、`UNNotificationSound` 取不到声音、`AVAudioFile` 转码报错时。

## 一、UNNotificationSound 只认两个目录，且不认子目录

`UNNotificationSound(named:)` 按**文件名**在下面两处查找，路径里带目录名就找不到：

1. App bundle 的 `Resources`；
2. `~/Library/Sounds`（非沙盒 App 的容器 Sounds 目录）。

把用户上传的音效存在 App Support 目录里直接引用**必然静默失败**——通知照发，但没有声音，也不报错。
做法（见 `NotificationSoundInstaller`）：

- 发通知前把被引用的音效**复制**一份进 `~/Library/Sounds`，文件名带本模块前缀（`NetworkMonitor-sys-*` / `NetworkMonitor-custom-*`）；
- `content.sound = UNNotificationSound(named: UNNotificationSoundName(副本文件名))`；
- 副本清理由前缀界定：每次 sync 只删「本前缀且不在当前引用集」的文件，不碰用户自己的音效（有界判据，参照「菜单项清理误删无关条目」）。

实测（`NM_NOTIFY_SELFCHECK` 探针，macOS 27）：

```
notify.billingAlert plan=named:NetworkMonitor-custom-<name>.aiff copy=present
deliver.item event=billingAlert soundPlan=named:NetworkMonitor-custom-<name>.aiff soundSet=true
```

## 二、AVAudioFile 读完再 read 会抛 -39 eofErr

按「读到 0 帧就 break」的写法转码，第二轮循环就炸：

```
Error Domain=NSOSStatusErrorDomain Code=-39 "eofErr: End of file"
```

改用帧位置判结束：

```swift
while input.framePosition < input.length {
    let remaining = AVAudioFrameCount(min(Int64(chunk), input.length - input.framePosition))
    let buffer = AVAudioPCMBuffer(pcmFormat: input.processingFormat, frameCapacity: remaining)!
    try input.read(into: buffer, frameCount: remaining)
    guard buffer.frameLength > 0 else { break }
    try output.write(from: buffer)
}
```

## 三、AVAudioFile 写句柄不关，读回来是空文件

`AVAudioFile(forWriting:)` 在析构时才 flush。同一函数里写完立刻用另一个 `AVAudioFile` 读同一个文件，
读到 0 帧（随后被上层判成「不支持 / 已损坏」）。生成测试音频时把写入放进独立作用域（嵌套函数）即可。

## 四、NSSound(contentsOf:) 的 name 恒为 nil

自证「到底播了哪个声音」时不能用 `sound.name`：`NSSound(named:)` 有名字，`NSSound(contentsOf:byReference:)` 没有。
记录解析出来的目标（`system:Tink` / `custom:foo.aiff`）而不是 `sound.name`。

## 五、通知授权不是 TCC，且首个弹窗必须人手点

- 全新 bundle id 的 App 在 `/Applications` 之外跑，`requestAuthorization` 直接回
  `Notifications are not allowed for this application`（`authorizationStatus` 仍是 0）；
- 放进 `/Applications` 并用 `open` 通过 LaunchServices 启动，系统才弹授权框；
- 探针里等不到人点，就只能拿到 `notDetermined`。**系统通知的听感无法由脚本自证**，
  能自证的是：授权状态、`content.sound` 的名字、`~/Library/Sounds` 副本存在、
  `getDeliveredNotifications` 里这条通知的 `userInfo.soundPlan`。

## 六、自检探针的收尾纪律

自检会真的发通知、真的写 `~/Library/Sounds`、真的往音效目录导入文件。收尾必须：
还原偏好 → 删自测音效 → `syncInstalledSounds()` 清副本 → `removeAllDeliveredNotifications()` 清通知中心，
否则用户的通知中心与音效目录会被探针垃圾塞满（本仓库的 `NotificationSelfCheck` 已按此实现）。

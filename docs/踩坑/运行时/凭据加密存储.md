# 凭据加密存储：只存本机、密文落盘

> **何时阅读：** 改凭据读写、排查「填了 key 却显示未配置」、或考虑要不要用钥匙串时。

## 现状

`EncryptedSecretStore`（`NetworkMonitorCore/Billing/`）是凭据的唯一落点：

- 值以 **AES-GCM** 加密后写进偏好存储，密文形如 `enc:v1:<base64>`（含 nonce 与 tag）；
- 密钥由**两段材料** HKDF-SHA256 派生，缺一不可：
  1. 本机硬件 UUID（`gethostuuid`）——换机器即失效；
  2. `~/Library/Application Support/macMonitor/credentials.key`（32 字节随机，权限 0600，
     首次使用时生成）——与偏好 plist 分开放。
- 历史明文（老版本写进去的）在**读取时就地加密回写**，值不变，不会要求用户重填。

## 为什么不用钥匙串

自签名 / ad-hoc 构建每次重建都会变签名身份，而钥匙串 ACL 按签名绑定：
身份一变，`SecItemCopyMatching` 就弹「想要使用钥匙串中的机密信息」并**阻塞调用线程**，
实测把菜单栏 App 卡死在启动阶段（`sample` 里主线程停在 `SecItemCopyMatching`）。
详见 [自签名 App 读钥匙串会卡死](自签名App读钥匙串卡死.md)。

## 能力边界（别高估）

挡的是**明文外泄**：随手 `plutil -p`、备份/同步被带走、误发文件、日志与截图里出现完整 key。
**挡不住**以同一用户身份运行的恶意进程——它既能读 plist 也能读密钥文件。
要防这一层只能用钥匙串（需稳定签名身份）或用户口令（需每次输入）。

## 如何识别

- 偏好里出现 `enc:v1:` 前缀 = 正常；出现 `sk-` / `__Secure-better-auth` 原文 = 加密没生效；
- 「填了 key 却显示未配置」→ 先看日志有没有「凭据解密失败（密钥材料可能已变）」，
  通常是换了机器 / 删了 `credentials.key`；
- 密文长度比原文长（base64 + 16 字节 tag + 12 字节 nonce）是正常的。

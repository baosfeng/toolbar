# NSPopover 面板随菜单栏宽度漂移

> 症状：菜单栏 app 的详情面板（NSPopover）打开后左右慢慢挪，用户描述为「详情页动来动去」。

## 现场

状态项文字每秒随网速刷新（`↓51K  ↑8K` → `↓6K  ↑1K`），按钮宽度实测在 79…112pt 之间变。
nmcli 连采同一进程（`nmcli windows 一览 --layer 25` 与 `nmcli menubar 一览` 成对取）：

| 状态项 x / 宽度 | 面板 x |
|---|---|
| 1041 / 89 | 912 |
| 1024 / 106 | 891 |
| 1039 / 91 | 914 |
| 1049 / 81 | 917 |

面板宽度恒定 346、高度随分页变，**只有 x 在 26pt 范围内跳**。注意状态项 `maxX` 恒定
（右侧系统图标位置固定，宽度只向左生长）。

## 三次试错（都做过，都只收窄不消灭）

| 做法 | 实测残留 |
|---|---|
| 直接把 `button.bounds` 交给 `popover.show(relativeTo:of:)` | 漂 26pt（891…917） |
| 锚点换成「宽 320、贴右边缘」的大矩形 | 漂 10pt（904…914）——越出按钮 bounds，被 AppKit 按视图边界处理后中心仍带宽度分量 |
| 锚点换成「宽 1pt、贴右边缘」+ 每次 contentSize 变化后补钉一次 | 漂 7pt（950/955/957）——AppKit 每拍按锚点重排，钉一次顶不住 |
| 每拍 `update()` 末尾钉一次（宽度就变在那一行） | 仍漂 5pt（950/951/955）——同轮改完会被系统覆盖一次 |
| **展开时记住右边缘 + 只听 `NSWindow.didMoveNotification` 纠正** | **x 恒定**（连采 10 次全 767，跨 3 次开合也 767） |

## 结论

两层一起才成立：

1. **锚点矩形**（`PanelAnchor.rect`）：1pt 窄矩形贴状态项右边缘 —— 让首次定位的中心与按钮宽度解耦；
2. **位置自愈**（`PanelWindowPin`）：展开那一刻把右边缘**记下来并冻结整次展开**，
   之后只监听 `NSWindow.didMoveNotification`，被系统挪走就按回 `记住的右边缘 − 面板宽度`。

第 2 条里「记住而不是跟着最新右边缘走」是关键：跟着最新值等于永远追着跑，
而冻结后系统怎么挪都会被按回同一个 x，用户看到的是位置恒定。

## 复跑命令

```bash
cd NetworkMonitor
./.build/debug/nmcli windows 一览 --layer 25 | grep 'alpha=1.00' | grep -q onscreen=true \
  || ./.build/debug/nmcli click 一览 --role AXMenuBarItem --index 0
sleep 4
for i in $(seq 1 10); do
  ./.build/debug/nmcli windows 一览 --layer 25 | grep 'alpha=1.00' | grep 'onscreen=true' | awk '{print $5}'
  sleep 0.8
done | sort | uniq -c
```

判据：**只出现一个 x 值**。

## 采样口径的坑

`nmcli windows` 会列出收起的残留窗口（`alpha=0.00`、`1x1`、临时宽 313）。
不过滤 `alpha=1.00` 与面板真实宽度，会把过渡帧当面板，得出「还在漂」的假结论。

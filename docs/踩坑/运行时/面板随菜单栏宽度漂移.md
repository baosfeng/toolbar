# NSPopover 面板随菜单栏宽度漂移

> 症状：菜单栏 app 的详情面板（NSPopover）打开后左右慢慢挪，用户描述为「详情页动来动去」。

## 现场

状态项文字每秒随网速刷新（`↓51K  ↑8K` → `↓6K  ↑1K`），按钮宽度实测在 79…112pt 之间变。
nmcli 连采同一进程（`nmcli windows 一览 --layer 25` 与 `nmcli menubar 一览` 成对取）：

| 状态项 x / 宽度 | 面板 x |
|---|---|
| 1041 / 89 | 912 |
| 1024 / 106 | 891 |
| 1039 / 91 | 914 |
| 1049 / 81 | 917 |

面板宽度恒定 346、高度随分页变，**只有 x 在 26pt 范围内跳**。注意状态项 `maxX` 恒定
（右侧系统图标位置固定，宽度只向左生长）。

## 三次试错（都做过，都只收窄不消灭）

| 做法 | 实测残留 |
|---|---|
| 直接把 `button.bounds` 交给 `popover.show(relativeTo:of:)` | 漂 26pt（891…917） |
| 锚点换成「宽 320、贴右边缘」的大矩形 | 漂 10pt（904…914）——越出按钮 bounds，被 AppKit 按视图边界处理后中心仍带宽度分量 |
| 锚点换成「宽 1pt、贴右边缘」+ 每次 contentSize 变化后补钉一次 | 漂 7pt（950/955/957）——AppKit 每拍按锚点重排，钉一次顶不住 |
| 每拍 `update()` 末尾钉一次（宽度就变在那一行） | 仍漂 5pt（950/951/955）——同轮改完会被系统覆盖一次 |
| **展开时记住右边缘 + 只听 `NSWindow.didMoveNotification` 纠正** | **x 恒定**（连采 10 次全 767，跨 3 次开合也 767） |

## 结论

两层一起才成立：

1. **锚点矩形**（`PanelAnchor.rect`）：1pt 窄矩形贴状态项右边缘 —— 让首次定位的中心与按钮宽度解耦；
2. **位置自愈**（`PanelWindowPin`）：展开那一刻把右边缘**记下来并冻结整次展开**，
   之后只监听 `NSWindow.didMoveNotification`，被系统挪走就按回 `记住的右边缘 − 面板宽度`。

第 2 条里「记住而不是跟着最新右边缘走」是关键：跟着最新值等于永远追着跑，
而冻结后系统怎么挪都会被按回同一个 x，用户看到的是位置恒定。

## 复跑命令

```bash
cd NetworkMonitor
./.build/debug/nmcli windows 一览 --layer 25 | grep 'alpha=1.00' | grep -q onscreen=true \
  || ./.build/debug/nmcli click 一览 --role AXMenuBarItem --index 0
sleep 4
for i in $(seq 1 10); do
  ./.build/debug/nmcli windows 一览 --layer 25 | grep 'alpha=1.00' | grep 'onscreen=true' | awk '{print $5}'
  sleep 0.8
done | sort | uniq -c
```

判据：**只出现一个 x 值**。

## 采样口径的坑

`nmcli windows` 会列出收起的残留窗口（`alpha=0.00`、`1x1`、临时宽 313）。
不过滤 `alpha=1.00` 与面板真实宽度，会把过渡帧当面板，得出「还在漂」的假结论。
## 纵向也会漂（同一处毛病的另一半）

症状：点「额度」tab 时面板跳到屏幕中下部，切回去又落回菜单栏下面 —— 用户描述为「详情页的位置时刻在变」。

原因是 **NSPopover 在内容尺寸变化时保持底边不动、顶边随高度跑**。nmcli 连采同一进程切页：

| 分页 | 面板高度 | 面板 y（顶边屏幕坐标，翻转后） | 底边 |
|---|---|---|---|
| 额度 | 350 | 229 | 579 |
| 网络 | 537 | 42 | 579 |
| 系统 | 506 | 73 | 579 |
| Token | 546 | 33 | 579 |

底边恒为 579，顶边在 33…229 之间跳 —— 高度小 196pt，面板就往下掉 196pt。

修法与横向同构，但有两个**必须**的细节（都踩过）：

1. **顶边不能按按钮算，也不能在出场动画里取**。按状态项下沿算是错的（菜单栏状态项下沿在屏幕顶部 28pt，面板顶边也确实是 28pt，但 popover 的 visibleFrame 夹取会让它再低 5pt）；按「show 之后立刻读窗口 frame」也是错的 —— 出场动画期间窗口位置与尺寸都在变，实测取到的顶边比稳定值低 50pt，面板被钉到屏幕中下部。
   正确做法：**动画结束后（0.25s）从窗口真实 frame 锁一次顶边**，之后整次展开不再变。
2. **纠正只能改原点，不能改尺寸**。用 `setFrame` 在动画中途改框会把动画的中间态尺寸冻住（实测宽度 346 → 312、高度跟着错）。用 `setFrameOrigin`，尺寸归 popover 自己管。

## 在进程内验收（唯一可信口径）

跨进程重启时每个分页都是一次**全新展开**，顶边本来就该重新锁 —— 「切页时位置恒定」只有同一进程连续切页才验得出来。
所以加了 DEBUG 探针 `NM_PANEL_PIN_PROBE=1`（`Debug/PanelPinProbe.swift`）：同一次展开里逐页切过去，打印每页 frame 与**右上角**。

```bash
pkill -f '/Applications/一览.app/Contents/MacOS/一览'; sleep 1.5
NM_PANEL_PIN_PROBE=1 /Applications/一览.app/Contents/MacOS/一览 2>&1 | grep PROBE_
```

判据：`PROBE_CORNERS` 只有一个取值、且高度随分页变化。实测输出：

```text
PROBE_TAB network x=783.0 y=524.0 w=346.0 h=425.0 corner=1129.0,949.0
PROBE_TAB credits x=783.0 y=604.0 w=346.0 h=345.0 corner=1129.0,949.0
PROBE_TAB token   x=783.0 y=403.0 w=346.0 h=546.0 corner=1129.0,949.0
PROBE_TAB system  x=783.0 y=443.0 w=346.0 h=506.0 corner=1129.0,949.0
PROBE_CORNERS 1129.0,949.0
PROBE_OK 右上角恒定
```

注意高度变了、y 也变了，但 `y + h`（右上角）恒定 —— 这就是「高度只向下长」。

## 顺带：屏幕锁定时截图取不到内容

验收时 `screencapture` 拿到全黑（`CGDisplayIsAsleep == 1`）、`nmcli shot` 报 "could not create image from window"，都不是本缺陷：
锁屏 / 显示器休眠状态下窗口服务器不合成内容。先 `caffeinate -u -t 3` 唤醒再截，或直接用上面的进程内探针（不依赖截图）。

# 截图坐标偏移、闪屏与截到背景

> **何时阅读：** 截图结果与框选位置对不上（「框选 A，截到的是 B」）、按完快捷键屏幕闪一下、
> 或者对着自家面板截图却发现截到的是面板背后的桌面。

## 问题描述

三处现象，根因互不相同，但都落在同一条「热键 → 抓屏 → 上屏覆盖层」链路上：

1. **选区偏移**：本机（macOS 27、1512×982 点、2x 屏、单屏）实测
   `CGDisplayPixelsWide(displayID)` 返回 **1512（点数而非像素数）**，
   `SnipDisplay.pixelSize` 因此等于点尺寸，由此推出的 `backingScale` 是 **1**。
   选区随后按 1x 换算成像素矩形去 `CGImage.cropping`，等于把点坐标当像素用，
   截出来的内容整体偏向左上（用户口径「往左偏了几百」）。
2. **屏幕闪一下**：`beginSnip` 原本先 `claimForegroundForCapture()` 抢前台再抓屏。
   抢前台会让原 App 的窗口全部退场、只留下桌面，覆盖层随后上屏的第一帧又是空白的
   （back store 未建好），用户看到的就是「闪一下」。
3. **截到背景**：同一次抢前台还会把自家 `NSPopover`（`.transient`）一并收起，
   于是「点开面板对着详情页截图」抓到的就是面板背后的桌面。

## 解决方案

- **坐标**：缩放比一律取「捕获图实际像素 ÷ 屏幕点尺寸」，不采信 `SnipDisplay.pixelSize`。
  `SelectionGeometry.pixelRect` 以调用方传入的 `imageSize` 为唯一权威，
  `SnipController.composedImage` 的标注 scale 同理；`ScreenCaptureService.screens()`
  改用 `CGDisplayCopyDisplayMode(displayID).pixelWidth / pixelHeight`（本机给 3024×1964）。
  Core 层不许 import AppKit，因此不能靠 `convertRectToBacking` 兜底——只能让图像自己说话。
- **顺序**：改成「抓屏 → 抢前台 → 上屏覆盖层」。抓屏发生在原画面前台还在位的时候，
  画面内容（含自家 popover）都能拍到；抢前台只发生在拿到图之后。
- **闪屏**：覆盖层以 `alphaValue = 0` 上屏（照样拿得到 key window 与键盘），
  首帧真正画进窗口后由 `SnipOverlayView.onFirstFrameRendered` 回调淡入 80ms；
  另有一条 400ms 超时兜底，首帧画不出来也要让窗口可见。

## 如何识别

- 偏移 → 跑 `NM_SNIP_CROP_PROBE=1`（打包后的 .app 内可执行文件），看
  `probe: pixelSize=` 与 `探测图` 是否 2x；`/tmp/nm-crop-probe.png` 若拍到左上区域即中招。
- 闪屏 / 截到背景 → `NM_PANEL_CAPTURE_PROBE=1`（配合 `NM_SHOW_PANEL=1`）拍面板，
  `/tmp/nm-panel-capture.png` 里看不到面板即说明抓屏发生在抢前台之后。
- 二级面板定位错 → `NM_SNIP_OVERLAY_DEMO=1` 的 `/tmp/nm-snip-overlay.png`；
  面板飘到左上角通常是没有先跑 `layoutToolBar()`，工具条 frame 还是零尺寸。

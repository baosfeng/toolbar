# 统一设置窗口设计规格

> **何时阅读：** 修改设置窗口（`SettingsWindow`）、新增设置分类页，或调整额度 provider 的启用 / 凭据管理时。

## 背景

原状态下设置散在四处：齿轮菜单只有「传送设置 / 开机自启动 / 退出」，剪贴板、截图、互传各自是独立小窗口，额度 provider 的凭据输入藏在额度 tab 的未配置块里。
用户反馈三点：①凭据应该能在设置里配置；②现有设置页不好看；③以后可能下线某个 provider，不应该要求改代码或删凭据。

原型：`.open-design/settings-proto/08-prototype.html`（4 套风格候选 → 选定 application；3 版骨架 → 选定「经典偏好卡片」）。

## 设计决定

### 1. 一个窗口、六个分类

`SettingsWindow`（760×540，可缩放，最小 720×460）＝ 左侧分类栏 + 右侧滚动内容区。分类：

| 分类 | 内容 |
|------|------|
| 通用 | 开机自启动、额度阈值提醒开关 |
| 额度 Provider | provider 列表：启用开关、状态点、最近刷新、行内凭据编辑、刷新节奏（只读） |
| 剪贴板 | 唤起热键、面板位置/高度、采集模式、条数上限、保留天数、忽略应用、⌘1–⌘9、剪贴板访问与辅助功能权限 |
| 截图与贴图 | 标注默认色与线宽、贴图不透明度、复制后自动保存与快速保存目录 |
| 局域网互传 | 接收目录占用/打开/清理、免配对窗口（时长 + 倒计时 + 重新计时）、体积阈值、提示音 |
| 关于 | 版本、构建号、项目地址、退出 |

页面按需创建、切走即释放：设置项都是「保存即持久化」，重建不丢数据，也避免多页同时观察外部状态（设备清单、权限）。

### 2. provider 的「下线」＝ 行内启用开关

新增 `BillingProviderPreferences`（Core，键 `billing.enabled.<providerID>`，未写过视为启用）：

- 关掉开关 → `BillingMonitor` 重建 states 时排除该 provider：**不请求接口、额度页不显示该块**；
- **不删凭据**：重新打开开关，`isConfigured` 仍由凭据存储决定，余额从零开始拉；
- 停用时递增该 provider 的请求代次，作废在途响应；节流基准一并清掉，重新启用立即查询。

注册表仍持有全部 provider —— 设置页要从 `monitor.registry.all` 读全量才能把停用的再打开。

### 3. 凭据配置搬到设置页

- 额度 tab 的未配置块不再内嵌输入框，改为「未配置凭据，无法查询额度」+「去设置配置」（跳设置窗口的额度 Provider 页）；
- 设置页行内编辑：已配置显示「替换 / 清除」，替换展开安全输入框（占位带掩码 `sk-…9f2a`）+「保存并查询 / 取消」；清除走行内二次确认；
- 未配置行直接展开输入框；保存空输入 = 用现有 Key 重新查询。

### 4. 旧窗口全部下线

`ClipboardSettingsWindow` / `SnipSettingsWindow` / `TransferSettingsWindow` 删除，内容迁入对应分类页。
迁移时抽出的共享定义：

- `ClipboardSettingsDelegate`（协议）→ `Clipboard/ClipboardSettingsDelegate.swift`
- `SnipPreferenceKey`（偏好键）→ `Snip/SnipPreferenceKey.swift`（键值不变，老设置继续生效）

齿轮菜单改为「设置…」(⌘,) + 开机自启动 + 退出；互传面板与截图菜单的「打开设置」统一落到对应分类页。

### 5. 数据与依赖注入

| 组件 | 职责 |
|------|------|
| `SettingsWindow` | 容器与切页；只依赖工厂字典，不碰业务 |
| `SettingsPaneView` | 页基类（`buildContent()` / `refresh()`），持有 `SettingsPageStack` |
| `SettingsPageStack` | 页头 + 卡片序列 + 页尾说明 |
| `SettingsCardView` / `SettingsRowView` | 卡片（draw 绘圆角与分隔线）与「左标题 + 右控件」行 |
| `LaunchAtStartupService` | SMAppService 注册与回滚，菜单与设置页共用 |
| `BillingAlertPreferences` | 阈值提醒开关（默认开） |

组合根：`AppCoordinator+Settings.swift` 提供六个工厂（`[weak self]` 捕获，避免环）；互传页需要 `TransferService`，由 `AppCoordinator+Transfer` 存入 `transferService` 供装配。

## 快照自证

`NM_SNAPSHOT_DIR=<目录>` 启动即渲染 `settings-<分类>-{light,dark}.png`（760×540），复用菜单面板的离屏渲染通道。
实现要点（踩过的坑）：

- 渲染会把视图借进离屏容器再归还，根视图必须重新挂回 `window.contentView`，否则第二页开始拿到 nil；
- 滚动视图的 `documentView` 必须是 flipped 容器，否则内容从底部起排、一屏放不下时页头被顶出视口；
- 卡片用 `draw` 绘圆角与描边（layer 静态色在换外观后会残留浅色底）。

## 验收

- `swift build --disable-sandbox --build-system native` 通过；`TestRunner` 全绿；`Scripts/check-file-size.sh` 通过；
- 六页 × 深浅快照齐全（`settings-*.png`）；
- 关闭某 provider 开关后：额度页不再出现该块、日志无该 provider 的查询；重新打开立即查询；
- 额度 tab 未配置块点「去设置配置」落到设置窗口额度 Provider 页。

## 已知待办

1. 两处「选择目录」未实现（快速保存目录、接收目录）：Core 侧路径是固定函数与不可变配置，需要同时改落盘链路与目录迁移；
2. 剪贴板权限状态映射（`NSPasteboard.accessBehavior` → 文案/语义色）仍在 App 层内联，可下沉 Core 成纯枚举补断言；
3. 深色下 `NSSwitch` 在离屏快照里不显示开态配色（AppKit 渲染限制），真实窗口正常；
4. provider 数量继续增长后额度页会滚动，需要折叠或分组。

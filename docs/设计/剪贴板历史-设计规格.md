## 1. 目标与范围

需求：① 全局快捷键在屏幕底部浮起面板；② 支持图片与文本；③ 搜索 + 方向键 + 回车；④ 收藏；⑤ 卡片视图；⑥ 额外功能。本期包含三项额外能力：「自动粘贴」「Paste Stack」「全部快捷键可自定义」。数据仅存本机。

## 3. 数据模型

`ClipboardItem`（struct，Equatable + Sendable）字段：
`id: UUID`、`kind: ClipboardItemKind`、`text: String?`、`preview: String`、`imagePath: String?`、
`imageWidth: Int?`、`imageHeight: Int?`、`contentHash: String`、`sourceBundleID: String?`、
`sourceAppName: String?`、`copyCount: Int`、`isPinned: Bool`、`createdAt: Date`、`pinnedAt: Date?`、`stackPosition: Int?`。

`ClipboardItemKind`：`text` / `image` / `file` / `rtf`（String raw value；file 记录文件 URL 摘要文本）。

## 4. 存储

```sql
CREATE TABLE IF NOT EXISTS clipboard_items (
  id               TEXT PRIMARY KEY,
  kind             TEXT NOT NULL,
  text             TEXT,
  preview          TEXT NOT NULL DEFAULT '',
  image_path       TEXT,
  image_width      INTEGER,
  image_height     INTEGER,
  content_hash     TEXT NOT NULL,
  source_bundle_id TEXT,
  source_app_name  TEXT,
  copy_count       INTEGER NOT NULL DEFAULT 1,
  is_pinned        INTEGER NOT NULL DEFAULT 0,
  created_at       REAL NOT NULL,
  pinned_at        REAL,
  stack_position   INTEGER
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_clipboard_content_hash ON clipboard_items(content_hash);
CREATE INDEX IF NOT EXISTS idx_clipboard_order ON clipboard_items(is_pinned DESC, created_at DESC);
```

**去重策略**：插入用**单条原子语句**完成，不做「先查后插」两步：

```sql
INSERT INTO clipboard_items
  (id, kind, text, preview, image_path, image_width, image_height,
   content_hash, source_bundle_id, source_app_name, copy_count, created_at)
VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, 1, ?)
ON CONFLICT(content_hash) DO UPDATE SET
  copy_count = copy_count + 1, created_at = excluded.created_at,
  source_bundle_id = excluded.source_bundle_id, source_app_name = excluded.source_app_name;
```

命中冲突时**保留原 id，不新建行**，copy_count 自增 1；未命中时 copy_count 从 1 起。
**content_hash 口径**：文本取「换行统一为 \n + 去首尾空白」后的 UTF-8 字节 SHA256；图片取**被选中表示的原始字节** SHA256，同一次复制只选一种表示（PNG 优先、TIFF 兜底，见第 5 节第 5 步），不得对同一张图分别用两种表示各算一次哈希。
**图片落盘**：`~/Library/Application Support/macMonitor/clipboard/images/<hash>.png` 存原图，`<hash>_thumb.png` 存缩略图（最长边 320，等比缩放）；DB 只存路径与尺寸。
**迁移与清理**：`PRAGMA user_version` 由 1 迁到 2，在 migrateIfNeeded() 内用 `CREATE TABLE IF NOT EXISTS` 与 `IF NOT EXISTS` 索引保证幂等，重复执行无副作用。
**超限清理**：条数超过上限（默认 500）或早于保留天数（默认 30）时删除，`is_pinned = 1` 豁免。
写入复用 DatabaseManager 既有串行队列，WAL 与现有 PRAGMA 不变。

## 5. 采集流程时序

1. Timer 每 500ms 触发（加入 RunLoop common modes）。
2. 读 `NSPasteboard.general.changeCount`，与上次相同则**立即 return，不读任何数据**。
3. 读 `accessBehavior`（NSPasteboard.accessBehavior，新系统）：为 `alwaysDeny` 时停采并提示用户去系统设置开启。
4. 忽略判定命中即 return：`org.nspasteboard.ConcealedType` / `TransientType` / `AutoGeneratedType`、自激标记 `com.bsfeng.macmonitor.clipboard.internal`、用户黑名单 App（按 bundleID）。
5. 读数据，优先级：文件 URL > 图片 > RTF > 纯文本。图片表示在 PNG 与 TIFF 中**只取其一**：PNG 优先，缺失或不合法时兜底 TIFF；该表示同时用于哈希与落盘。
6. 计算内容哈希并按第 4 节去重落库（含图片落盘与缩略图）。
7. `AppEvents.postClipboardChanged()` 通知面板刷新。
8. 判断是否超限并清理。
多个 pasteboardItems **合并为一条记录**：文本按换行拼接，图片取首个可解码项。

## 6. 采集器分支决策

**判定依据**：探针 `NetworkMonitor/Scripts/clipboard-permission-probe.swift` 的输出——记录 `accessBehavior` 取值随调用次数的变化，并统计「真实读取次数 vs 系统弹窗次数」。两种结果对应两套实现。**尚未验证的前提**：**changeCount 的读取本身是否会触发系统弹窗，目前未验证**。若读取 changeCount 也会弹窗，则分支 A 同样不成立，必须改为「仅在用户动作路径（打开面板 / 点采集按钮）读取 changeCount」。此点是探针**必须覆盖的观察点**（与「读取数据是否弹窗」分开计数）。**该前提已由下方结论闭环**（结论为：不弹窗）。

**探针结论（2026-10-12 已运行，日志 /tmp/clipboard-probe.log）**：`accessBehavior` 起止均为 `alwaysAllow`，全程未进入 `.default` / `.ask`；90 秒内真实读取 6 次、单次耗时 0–3ms、被判「疑似被弹窗阻塞」0 次；`changeCount` 每 500ms 读取（约 180 次）亦未触发弹窗 —— 故「读取 changeCount 本身是否会弹窗」这一前提**证伪**，实现维持默认**分支 B**（`ClipboardPreferences.captureMode` 默认 `.polling`），分支 A（`.onDemand`）保留为设置项可选降级路径。**残余不确定性**：本次起点即 `alwaysAllow`，无法区分这是系统全局策略还是按 bundle id 的历史授权记忆，因此「全新安装的应用首次后台读取是否弹窗」未能证伪；兜底依赖运行时 `PasteboardWatcher.checkAccessBehavior()` —— 系统一旦置为 `.alwaysDeny` 即停采，并在面板与设置窗提示前往系统设置。复现方式：`cd NetworkMonitor && ./Scripts/clipboard-probe.sh --seconds 90`，期间用 `pbcopy` 制造剪贴板变更即可，无需人工复制。

### 分支 A：每次后台读取都弹窗（弹窗次数 == 读取次数）

放弃后台轮询采集，退化为**「打开面板时读取一次 + 面板内手动『采集当前剪贴板』」**。
- 交互：面板打开瞬间读一次 changeCount 并抓取；changeCount 未变则直接渲染库里已有数据，不重复读；面板顶部常驻「采集当前剪贴板」按钮（Tab 可达，Enter 触发）。
- 损失：面板未打开期间复制的条目不会被记录，历史连续性依赖用户主动打开面板；不做变更角标提示；「自动粘贴」仍可用，因为粘贴路径是一次性前台读取。

### 分支 B：首次弹一次、之后记住（弹窗次数在首次后不再增长）

按第 5 节主方案实现后台 Timer 轮询，并在首次启动做**一次性权限引导**：说明页 → 触发一次真实读取以唤起系统授权 → 在 KeyValueStorage 写入已引导标记，之后不再打扰。

## 7. 面板

窗口：`NSPanel`，`styleMask = [.borderless, .nonactivatingPanel]`，`level = .statusBar`，`collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary]`，`canBecomeKey = true`；`acceptsFirstMouse` 只声明在 **NSView** 上（NSWindow 无此成员），故应在面板的**内容视图**（NSView 子类）重写 `acceptsFirstMouse(for:) -> Bool` 返回 true，保证非激活态首次点击即生效；NSPanel 子类只保留 `canBecomeKey` / `keyDown` / `performKeyEquivalent`。
定位：取鼠标所在屏的 `visibleFrame`，宽度 = visibleFrame.width - 40，高度 260（设置项可调），底边距 12pt。
动画：0.18s easeOut 从底部滑入；Esc 或再次按热键收起；失焦自动收起。

**核心矛盾与解法**：面板要能打字就必须是 key window，而此状态下合成的 ⌘V 会落回面板自身，粘贴不到目标 App。
解法（粘贴流程）：**在面板唤起（show）的那一刻记录 frontmost app** —— 此刻面板尚未成为 key window，frontmost 仍是用户的真实目标 App，记为「目标 App」并持久化到 KeyValueStorage；**按回车时不再取 frontmost**。
边界：若唤起时 frontmost 就是本 App（例如从菜单栏图标打开面板），则回退到「最近一次非本 App 的 frontmost bundleID」缓存，读不到缓存时只做「写入剪贴板 + 提示用户手动粘贴」，不合成按键。
后续时序：收起面板让出 key → 写系统剪贴板（先打自激标记）→ **延迟 80ms** → CGEvent 合成 ⌘V；自激标记**不主动清除** —— 用户下一次复制会由系统整体替换剪贴板内容，标记自然消失，而主动改写现存剪贴板反而可能破坏用户数据。

- **回退缓存的存活校验**：唤起时 frontmost 为本 App、需回退缓存的 bundleID 时，先用 `NSRunningApplication(bundleIdentifier:)` 校验该 App 仍存活（非 nil 且未被终止，`isTerminated == false`）；不存活则按「无缓存」处理 —— 只写入剪贴板 + 提示用户手动粘贴，不合成按键。
- **取 frontmost 的调用顺序（时序敏感）**：取值必须是 show 流程中的**同步**调用，且**早于** `makeKeyAndOrderFront` / `makeKey`；触发条件是把取值放进动画完成回调、`DispatchQueue.main.async` 或 `NSAnimationContext` 的 completionHandler（此时面板已是 key window，取到的 frontmost 只能是本 App）。实现处须以中文注释固化「先取值、后 makeKeyAndOrderFront」的顺序，禁止后移到任何异步路径。

## 8. 快捷键表（全部可自定义）

| 按键 | 行为 |
|------|------|
| ⌥⌘V | 唤起 / 收起面板 |
| ← → ↑ ↓ | 在卡片间移动选中 |
| ↵ | 粘贴（按原类型） |
| ⌥↵ | 以纯文本粘贴 |
| ⌘↵ | 仅复制，不粘贴 |
| ⌘1–⌘9 | 快速粘贴第 N 张卡片 |
| ⌘D | 收藏 / 取消收藏 |
| ⌫ | 删除选中条目 |
| ⌘⇧⌫ | 清空（收藏项保留） |
| Tab | 切换过滤（全部 / 文本 / 图片 / ⭐） |
| Esc | 收起面板 |

**按键拦截层（必须有，否则交互失效）**：搜索框获得焦点后，⌫、⌘D、⌘1–⌘9、Tab 会被 NSTextField 的字段编辑器吃掉，因此面板内快捷键统一在 **NSWindow 的 `keyDown` / `performKeyEquivalent` 层拦截**，拦截层先于 responder chain 处理：
- 搜索框文本**非空**时：⌫ 优先删字符，其余组合键（⌘D、⌘1–⌘9、Tab、方向键）仍走面板动作。
- 搜索框文本**为空**时：⌫ 删除选中卡片，不删字符。
- Tab 只切换过滤，**不进入搜索框焦点环**（搜索框的 `nextKeyView` 置空，避免 Tab 落进文本控件）。

冲突处理：Carbon 注册失败（`RegisterEventHotKey` 返回非 noErr 或引用为空）时不静默失败，弹提示引导用户去「系统设置 → 键盘 → 键盘快捷键」关闭旧占用后重试；设置窗内该组合标记为冲突态。

## 10. Paste Stack

字段 `clipboard_items.stack_position`（NULL = 不在栈）；栈的入栈 / 出栈 / 推进 / 清空由 `PasteStackController` 状态机统一持有，视图只读状态。
面板内 `⌘S` 将选中项入栈（追加到队尾并重新编号），`⌘⇧S` 清空整栈；卡片右上角按 stack_position 显示 ①②③ 角标。
后续在任意 App 按 `⌘V`：贴出队首并弹出队列，其余项整体前移。
监听：用 `NSEvent.addGlobalMonitorForEvents(matching: .keyDown)` 监听 ⌘V，**不用 CGEventTap** —— CGEventTap 回调超时（`kCGEventTapDisabledByTimeout`）会**阻塞全系统的键盘输入**，风险过高；全局 monitor 不阻塞、不改写事件。两者同样需要辅助功能权限（本需求只需监听，无需拦截改写，全局 monitor 够用），复用既有权限，不额外申请。
面板底部显示栈进度（如「栈 2 / 5」）。

- **辅助功能权限静默失败**：触发条件 —— 未授权时调用 `NSEvent.addGlobalMonitorForEvents` 不报错也不回调，Paste Stack 的 ⌘V 毫无反应且无任何提示。处置 —— 启动时与设置窗打开时用 `AXIsProcessTrustedWithOptions` 检测；无权限则在设置窗与面板底部显示权限状态 + 「前往系统设置」跳转，并禁用 Paste Stack 入栈动作且给出文案，不得静默失败。
- **长按 ⌘V 的 key repeat 过滤**：触发条件 —— 全局 monitor 收到的 keyDown 会因按键长按而被重复投递。处置 —— 回调内过滤 `event.isARepeat == true` 的事件，只有非 repeat 的首次 keyDown 才推进粘贴栈。
- **回调线程归属**：触发条件 —— NSEvent 全局 monitor 的回调在非主线程交付，而「弹出队首 + 重写系统剪贴板 + 刷新面板」涉及 AppKit UI 与 DatabaseManager 串行队列。处置 —— 回调内一律先 `Task { @MainActor in }` hop 回主线程，再操作 UI 与栈状态；写库走 DatabaseManager 串行队列，禁止跨线程直接读写栈状态。
- **无法拦截改写 ⌘V（已知取舍）**：触发条件 —— 放弃 CGEventTap 后无法拦下目标 App 的原生粘贴行为。处置 —— 本期明确不做拦截改写，只做监听，登记为已知取舍而非缺陷，详见第 14 节。

- 相对时间格式化：刚刚 / 分钟 / 小时 / 天
- 数据库：建表、user_version 1→2 迁移幂等、插入、ON CONFLICT 去重置顶且 copy_count+1 且 id 不变、收藏、删除、清空保留收藏、超限清理
- PasteStackController 状态机：入栈编号、推进、清空
- Mock 协议（ClipboardRepository / ClipboardCaptureService / ClipboardWriter）驱动面板数据流
手动验收清单：中文搜索命中、四种回车行为、图片粘贴到目标 App、收藏跨重启持久化、黑名单生效、权限被拒时的降级路径。
开发顺序遵循项目规范：**先实现跑通 → 冒烟验证 → 再补测试**。

## 13. 明确不做

iCloud 同步、OCR 文字识别、Snippets 片段库、标签分类、AI 集成。

## 14. 风险与缓解

- 剪贴板授权弹窗：见第 6 节，按探针结果走分支 A 或 B；changeCount 读取是否弹窗同为探针观察点。辅助功能权限被拒时合成粘贴不可用，降级为「仅复制」并在面板内提示前往系统设置。
- 非激活面板与合成粘贴冲突：按第 7 节「唤起时记目标 App → 让出 key → 延迟 80ms → 合成」时序执行；唤起时 frontmost 即本 App 时回退最近一次非本 App 的 bundleID 缓存，无缓存则降级为仅复制。
- 底部浮层与 Dock 冲突：定位基于 visibleFrame 并留 12pt 边距，高度不超过 visibleFrame 的 1/3。
- 大图片内存：落盘后只持有缩略图引用，原图按需懒加载。
- 放弃 CGEventTap 的已知取舍：无法拦截改写 ⌘V（目标 App 的原生粘贴行为不受控），本期明确不做拦截改写，不作为缺陷跟踪，见第 10 节。

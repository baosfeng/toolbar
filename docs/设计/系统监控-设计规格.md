# 系统监控设计规格

> 何时阅读：维护菜单面板「系统」分段、改动取数口径（`SystemMetrics/*`）或系统页 / 网络页 Wi-Fi 链路条 UI 时。
> 本文以**代码现状为准**（v6：版2 紧凑首屏 + 五张面板内二级详情页 + 四段状态带 + 网络页 Wi-Fi 链路条）。实测证据见 [系统监控 CPU/GPU 可行性调研](../调研/系统监控-CPU-GPU-可行性调研.md) 与 [第二批指标可行性调研](../调研/系统监控-第二批指标-可行性调研.md)；定稿原型 [原型.html](系统页-v2-配色与二级页/原型.html) 与 [设计决策.md](系统页-v2-配色与二级页/设计决策.md)（色板、取舍、详情页清单、有意偏离）；v4 时代的结构契约仍见 `.open-design/system-monitor-prototype/07-contract.md`（过程稿，不入库）。

## 目标

菜单面板第 6 个分段「系统」（`MenuPanelTab.system`，`MenuTabBarView.swift:12`），只读、免 root、默认 1 s 采样：

- **顶部四联**：CPU / GPU / 内存 / 负载 四个 hero 小格（行高 54pt，四格等分约 71pt，底色 `--surface`）。
- **五张卡（版2 紧凑形态）**：CPU / GPU / **压力** / 内存 / 磁盘，一卡一族语义色（CPU 蓝 / GPU 靛 / 内存 青绿 / 压力 橙 / 磁盘 石墨），卡底为各族 4.5%（浅）/ 6%（深）wash；装配顺序见 `SystemPaneView+Cards.swift`。
- **五张面板内二级详情页**：CPU / GPU / 内存 / 磁盘 / 压力（进程），整卡可点进入，顶部「‹ 系统」返回条回到首屏；**不弹新窗口、不新增 tab**（`SystemDetailPaneView.swift` 与四个 `SystemDetailPaneView+*.swift`）。
- **底部 20pt 状态带**：SoC 温度 · 电池环 · **Wi-Fi** · 估功耗，一行**四段**横跨面板（`SystemPaneView+StateBand.swift`）。
- 界面只留数值、单位、≤4 字标签，口径说明全部进卡片 `toolTip`（集中在 `SystemPaneView+Tips.swift`）；采样周期 0.5–5 s（默认 1 s），面板按 5 s 节流渲染，曲线保留 60 点历史。
- **网络页新增 Wi-Fi 链路条**：今日流量卡与活跃进程之间一条 20pt（`NetworkPaneView.swift:89`、`NetworkPaneView+WiFi.swift:15`），形态 `Wi-Fi  −65 dBm  ch36 5G  103 Mbps  ·`（末尾圆点表档位；版式见 `NetworkPaneView+WiFi.swift:6-14` 的文件头说明）。它**不是第二套采样**——值与系统页状态带同源，都取 `SystemMetricsSnapshot.wifi`（`MenuPanelController+SystemMetrics.swift:43`），详见下文「关键决策」第 11 条。

**温度卡已下线**：v1/v2 的 `thermal-card` / `thermal-gauges` 锚点废弃，温度降为状态带上的单读数。设置页原「温度卡开关」语义随之变为「状态带里的温度是否显示」（`SettingsSystemPane.swift:18-19`、`SystemPaneView+Cards.swift:167-169`）。实现时不要再去找 `thermal-card`。

## 版面与首屏预算

面板硬上限 `MenuPanelStyle.maxHeight = 520pt`（`MenuPanelStyle.swift:15`），内容超出后由内部 `NSScrollView` 垂直滚动，**不裁切**（`MenuPanelView.swift:32`）。版2 实现态总高 **495pt**（真机快照，含状态带），首屏不需要滚动；滚动容器保留作兜底（字体放大 / 本地化 / 超高内容），判据仍是「520pt 首屏里看到什么」而不是「能否塞进一屏」。

**版2 的目标是「一屏看全六块」**：实现态实测 **495pt ≤ 520pt**（真机快照，含状态带），靠四处信息下沉换来（CPU 每核柱阵 / GPU 显存条 / 内存四段数值行 / 磁盘读写曲线）。首屏结构自下而上：

| 区块 | 版2 形态 | 下沉去向 |
|---|---|---|
| 四联 `hero-row` | 54pt，四格等分 | — |
| CPU 卡 | 卡头图例 + 23pt 总利用率 + 60 秒堆叠面积 | 每核柱阵 → CPU 详情热力格 |
| GPU 卡 | 环 + 60 秒折线 + 已用显存一行 | 显存条 → GPU 详情 |
| 压力卡 | 负载三线 + 进程 Top-2 + 卡头「全部 ›」 | Top-3 → Top-2；Top-10 与榜单切换 → 压力详情 |
| 内存卡 | 四段堆叠条 + 压力徽标 + 卡头容量 | 四段数值 / 占比 / 堆叠趋势 → 内存详情 |
| 磁盘卡 | **单行**：忙% + 微条 + 容量 + › | 读写曲线 / IOPS / 可用容量 → 磁盘详情 |
| 状态带 | 20pt 四段 | — |

**实现态 520pt 首屏以快照为准**（见「验收命令」的 `menu-system-light/dark.png`）：版2 余量约 25pt，字体或本地化一改仍可能溢出，故守住「磁盘单行 + 状态带」是硬预算。**压力卡仍排在 GPU 之后、内存之前**：任何新增区块插到内存卡之前都会把压力卡顶出首屏。

**网络页**（`NetworkPaneView.swift`）加入 Wi-Fi 链路条后实测 **516pt**，距 520pt 上限只剩 4pt。这条余量是靠把链路条前后间距从默认 10pt 收到 4pt 换来的（`NetworkPaneView.swift:56,97-98` 有原注释）；**再往网络页加任何区块都会立刻出滚动条**。

## 色板与二级详情页（v6 定稿）

### 色板：一卡一族，写死 sRGB 双外观

色值**唯一来源**是 Core 的 `SystemPaletteTokens`（纯值表：49 个语义 token × 浅/深），UI 的 `SystemPalette` 只做「token → 动态 `NSColor`」转译。**禁止再用 `controlAccentColor` 混色**：v3 在 oklab 里把电池绿与强调蓝插值，hue 被拖到 178°（青）。

**一卡一族**：CPU 蓝 / GPU 靛 / 内存 青绿三段 / 压力 橙（1m → 5m → 15m 次级递减）/ 磁盘 **石墨**（读＝石墨、写＝琥珀次级）；**状态带四段各一色**：SoC 温度 红橙 / 电池环 绿 / Wi-Fi 蓝 / 估功耗 紫，每族另配一个 ink 变体用于数值与图例文字。完整色值、浅/深对比度、语义映射与磁盘石墨决策见 [设计决策.md](系统页-v2-配色与二级页/设计决策.md)（本文不再重复长表）。

对比度由 `SystemPaletteContrast.pairs`（60 对）在浅/深两套逐条断言：**文字 ≥ 4.5:1、图形 ≥ 3:1**（WCAG 2.1）。`meta` 在八种底（面板 / 四联 / 五张卡 wash / 状态带）上逐块算过：压力卡橙 wash 余量最小（浅 4.63:1、深 4.76:1），仍过 4.5:1。深色下内存三段明度阶梯反向（深底上「更深」= 更看不见），三段数值文字统一走 `memoryInk`，不染成段色。

### 二级详情页（全部用现有字段）

| 页面 | 内容 | 入口 | 数据来源 |
|---|---|---|---|
| **CPU** | 总利用率（28pt）· 60 点用户/系统堆叠面积 · 每核 10 格热力（每行 9 格，10 核排 9+1；P0–P7 / E0–E1 逐核 %）· P/E 核均值与核数 · 忙/闲拆分 | 整卡点击 | `CPUSnapshot` 全核 + `splitCores` |
| **GPU** | 活跃利用率 · 60 点 0–10% 量程曲线 · 已用显存 · 当前状态（空闲/使用中）· 采样周期 | 整卡点击 | `GPUSnapshot`（显存总量与 GPU 核数本机无字段，脚注说明） |
| **内存** | 已用/总量 · 压力徽标 · 四段条 + 四段 GB 与占比 · 60 点三段堆叠 · 交换 / 压力等级 / 物理内存 | 整卡点击 | `MemorySnapshot` + 控制器注入的三段历史 |
| **磁盘** | 已用/总量 · 已用比例与可用容量 · 容量条 · 读写双列曲线 · 读/写 IOPS · 繁忙度 | 整卡点击 | `DiskSnapshot`（卷名本机无字段，脚注说明） |
| **压力** | 负载三线 + 核数参考虚线 · **进程 Top-10** · **CPU 榜 / 内存榜切换** · 底部口径行 | 压力卡「全部 ›」或整卡点击 | `LoadSnapshot` + `ProcessResourceSnapshot`（采样缓存 10 条） |

导航与键盘：面板内覆盖（同一 320pt 宽），返回条「‹ 系统」；**Esc 在详情页先返回首屏**、再按 Esc 才收面板；进入详情不抢 firstResponder（面板 Tab / ↑↓ 遍历由 `MenuPanelView` 统一处理），**返回时滚动归零、焦点环还给进入前的卡片**；首屏五张卡进入 `focusableCards` 焦序遍历（Tab / ↑↓ 移动，Return / Space 进入）。

### 图表层次（定稿 B 手法）

- 面积 / 堆叠段一律**同族纵向渐变**（顶部 alpha 0.28–0.30 → 底部 0.02–0.03），不再整块平涂；
- 参考线走 `grid`（虚线），轨道分两档：`track`（轨道底）/ `trackSecondary`（每核格底 / 繁忙条底）；
- 环形与堆叠条保持实色（定稿原型即实色），段间留 0.5pt 卡底色缝，压力态整条 1pt 内描边；
- 面积/柱阵/环/堆叠条的配色全部走 token，不在视图里写裸色值。

## 数据源

除温度（IOHID）与 GPU 功耗（IOReport）走私有符号（dlopen + dlsym，失败即降级）外，均为公开接口。

| 指标 | 首选 API | 采样器 | 档位 |
|---|---|---|---|
| CPU 总 / 每核 / user-system | `host_processor_info(PROCESSOR_CPU_LOAD_INFO)` 差分 | `SystemCPUSampler` | 1 s |
| 内存 / 压力 / swap | `host_statistics64(HOST_VM_INFO64)` + `host_page_size()`、`kern.memorystatus_vm_pressure_level`、`vm.swapusage` | `SystemMemorySampler` | 1 s |
| 磁盘容量 / 速率 / IOPS / 繁忙度 | `statfs("/")`、`IOBlockStorageDriver` → `Statistics` 差分 | `SystemDiskSampler` | 1 s |
| GPU 利用率 | `IOAccelerator` → `PerformanceStatistics` | `SystemGPUSampler` | 1 s |
| SoC 温度 | `IOHIDEventSystemClient`（私有） | `SystemThermalReader` | 1 s（成本 3.6 ms，取 2–4 个 PMU 传感器） |
| 负载 / 热压力 / 低电量 | `getloadavg()`、`ProcessInfo.thermalState` / `.isLowPowerModeEnabled` | `SystemLoadSampler` | 5 s |
| 进程 Top-N CPU% / 常驻内存 | `proc_listpids` + `proc_pidinfo(PROC_PIDTASKINFO)` 差分 | `SystemProcessSampler` | 5 s |
| GPU 功耗 | `IOReport` `Energy Model` → `GPU Energy`（单位 nJ） | `SystemGPUPowerReader` | 5 s |
| 电池 / 适配器 | `IOPSGetPowerSourceDescription` + `AppleSmartBattery` + `IOPSCopyExternalPowerAdapterDetails` | `SystemBatterySampler` | 5 s |
| Wi-Fi 链路（RSSI / 噪声 / 信道 / 带宽 / 速率 / PHY） | **`CWWiFiClient`（CoreWLAN，公开框架，非私有 API）**：`rssiValue()` / `noiseMeasurement()` / `wlanChannel()` / `transmitRate()` / `activePHYMode()` | `SystemWiFiLinkSampler` | 5 s（成本约 3.9 ms，禁止塞进 1 s 档） |

**只有一个定时器**：5 s 档（负载 / 进程 Top-N / GPU 功耗 / 电池 / Wi-Fi 链路五项）不是第二个 `Timer`，而是 `poll()` 按上次慢采时间判断本帧是否顺带采集（`SystemMonitor+SlowMetrics.swift:42-52`）；未到点的那几帧沿用上一帧的慢节拍结果（`SystemMonitor.swift:110-113,192-194`）。

Wi-Fi 是这条规则里唯一的例外：慢采**到点**的那帧用 `slowResult.map { $0.wifi }` 而不是 `??`（`SystemMonitor.swift:195-197`），即断网 / 关 Wi-Fi 时必须让读数真的消失，不能沿用上一帧的旧链路。

## 口径

| 指标 | 换算 / 规则 | 代码 |
|---|---|---|
| CPU 总 | `totalBusy / totalAll`，`busy = user + system + nice`、`all = busy + idle`；与 `HOST_CPU_LOAD_INFO` 对账差 < 0.3pp | `SystemMetricsCalculations.swift:42-81` |
| CPU user / system 双序列 | **`totalUsage` 是唯一真相源**，用户态由 `total − system` 现算，不读独立 `userUsage` 字段；否则两枚数字各自取整后凑不出总量（「总 25 / 用户 13 / 系统 13」），也与图上叠加带对不上 | `SystemPaneView+Metrics.swift:25-28`、`SystemPaneView+Legend.swift:74-89` |
| CPU 每核 | 同式差分；单核增量 0 → 记 0（不产生 NaN）；计数倒退该槽位按 0（`current >= previous ? … : 0`） | `SystemMetricsCalculations.swift:84-86` |
| 每核顺序 | **E 核在前、P 核在后**（`ioreg` 实测 cpu0/1 `cluster-type="E"`、cpu2…9 `="P"`）；前 `efficiencyCores` 个为 E | `SystemMetricsFormatting.swift:68-78` |
| P/E 核数 | `hw.perflevel0.physicalcpu`（P）/ `hw.perflevel1.physicalcpu`（E）；取不到返回 (0,0)，退化为按顺序展示 | `SystemCPUSampler.swift:63-67` |
| 内存四段 | `wired`（`wire_count`）/ `active`（`active_count`）/ `compressed`（`compressor_page_count`）/ 空闲；**`used = active + wired + compressed`，不含 inactive**（可随时回收，计进去读数长期偏高） | `SystemMemorySampler.swift:40-45`、`SystemPaneView+Metrics.swift:76-97` |
| 内存压力 | 主键 1 正常 / 2 警示 / 4 紧张；不可读回退 `vm.memory_pressure` 0/1/2；仍不可读按正常 + 记 issue | `SystemMemorySampler.swift:77-88`、`SystemMetrics.swift:124-131` |
| 磁盘容量 | `total = f_blocks × f_bsize`、`used = total - f_bavail × f_bsize`（非特权可用量，同「关于本机」） | `SystemDiskSampler.swift:15-23` |
| 磁盘速率 / IOPS | 按 **`IORegistryEntryGetRegistryEntryID`** 配对两次快照，Δ ÷ 实际间隔；只累加两次都存在的实例，计数器回退按 0 | `SystemMetricsCalculations+Disk.swift:131-174` |
| 磁盘繁忙度 | `(Δ读服务时间 + Δ写服务时间) / 1e9 / elapsed`，clamp 0…1；`Total Time (Read/Write)` 单位是**纳秒** | `SystemMetricsCalculations+Disk.swift:110-118` |
| IOPS 展示 | 只给数值（次/秒），**不再画对数刻度虚线**：版2 首屏磁盘卡压成单行，IOPS 与繁忙度明细进磁盘详情页；读数仍是 0…3000 op/s 量级，文字比虚线更直接 | `SystemPaneView+Disk.swift` |
| 磁盘三键同判 | IOPS 读、IOPS 写、繁忙度**任一为 nil 就整组降级为「—」**（三键必然同源同缺），单位一并隐藏 | `SystemPaneView+Metrics.swift`、`SystemDetailPaneView+Disk.swift` |
| GPU 利用率 | `PerformanceStatistics["Device Utilization %"] / 100`；只看键是否存在，不把 0% 当不可用；**首帧丢弃**（冷读恒 0%） | `SystemMetricsCalculations.swift:97-103`、`SystemMonitor.swift:50,167` |
| GPU 显存 | `In use system memory` 作已用；`memoryTotal` 恒 nil（统一内存），版2 首屏只留一行已用数值、不画占比条 | `SystemGPUSampler.swift:25-26`、`SystemPaneView+Metrics.swift`、`SystemDetailPaneView+GPU.swift` |
| 温度 | 只读最多 4 个 PMU 传感器，取最大值；读数须落在 −20…150 °C；> 85 °C 转警示色 | `SystemThermalReader.swift:47,65-78`、`SystemPaneView+Components.swift:16` |
| 负载量程 | `cap = max(核数 × 1.2, 近 60 秒峰值 × 1.15, 1)`；核数参考虚线按 `核数 / cap` 的真实比例画，三线越过虚线即「有进程在排队」 | `SystemPaneView+Load.swift:125-129` |
| 负载归一化 | `load / 核数`；核数 ≤ 0 → nil（不猜分母）；结果不封顶（排队越严重越该显眼） | `SystemMetricsSupplementCalculations.swift:34-37` |
| 进程 CPU% | `Δticks × nsPerTick / 1e9 / elapsed × 100`；**单位是 mach ticks 不是纳秒**（时基坑见 [进程 CPU 百分比时基换算](../踩坑/运行时/进程CPU百分比时基换算.md)）；**不 clamp 到 100**（多线程合法超过，实测 3 线程自旋 298%） | `SystemMetricsSupplementCalculations.swift:52-62` |
| 进程条形 | **sqrt 绝对刻度** `min(1, sqrt(cpuPercent) × 13 / 100)`，满条 = 100% = 占满一个核；条长只由该进程自身 CPU% 决定，不随榜首联动（榜首归一化实测会让同一条在 26%~197% 间乱跳） | `SystemProcessBoard.swift`、`SystemPaneView+Process.swift` |
| 进程榜单 | 采样层两份分开给（CPU 榜 / 内存榜），缓存 **Top-10**（`SystemProcessSampler.topLimit`）；首屏只显示 Top-2，压力详情显示 Top-10 并可在 CPU 榜 / 内存榜间切换；内存榜条形为 `常驻 / 物理内存` 线性占比 | `SystemProcessBoard.swift`、`SystemMonitor+SlowMetrics.swift:78-87` |
| 详情页每核 | 热力档位 `< 10% / < 30% / ≥ 30%`；百分比 < 10% 保留一位小数、≥ 10% 取整；P/E 均值走紧凑百分比（整数不带小数位） | `SystemDetailFormatting.swift`、`SystemDetailHeatGridView.swift` |
| GPU 功耗 | `Δ纳焦耳 / 1e9 / elapsed`；单位读通道自带 label（同组混着 uJ/nJ/mJ，**禁止硬编码**），未知单位返回 nil；结果按 0…1000 W 合理性过滤 | `SystemGPUPowerReader.swift:129-137`、`SystemMetricsSupplementCalculations.swift:117-124` |
| 电池 | 电量 = `Current Capacity / Max Capacity`（两者都是百分比，非 mAh）；`TimeRemaining = 65535` 是 AC 哨兵值须过滤；健康度百分比不可得，只给 `CycleCount` | `SystemBatterySampler.swift:54-61,13-18,75-92` |
| 电池环配色 | **纯 `systemGreen`，禁止与 accent 混色**：v3 用 `success + accent 40%` 在 oklab 插值后 hue 落到 178°（青）被打回；< 20% 转黄、< 10% 转红 | `SystemPaneView+Style.swift:64-70`、`SystemPaneView+StateBand.swift:127-129` |
| 估算功耗标注 | 状态带固定写「估功耗」而非「功耗」：GPU Energy 是累加器估算，不是功耗计读数 | `SystemPaneView+StateBand.swift:38-40,134-143` |
| Wi-Fi RSSI | 有效区间 **−100…−20 dBm**（含端点）；区间外的 0 / 正数 / 越界负值都是 CoreWLAN 未连接时的占位值，一律按不可用（**绝不显示 0 dBm**） | `WiFiLinkCalculations.swift:19-49` |
| Wi-Fi 噪声 / SNR | 噪声区间 −120…−20 dBm；`snr = rssi − noise` 且必须满足 **> 0 且 ≤ 80**，否则 nil（拿占位值算会得出「信噪比 96 dB」这种荒谬值） | `WiFiLinkCalculations.swift:24,70-84` |
| Wi-Fi 频段 / 带宽 / PHY | **只做 rawValue 数值映射**，不引用 `CWChannelBand.BandUnknown` 等静态名（Swift 3 已废弃）：频段 0 未知 / 1 2.4G / 2 5G / 3 6G；带宽 1 20MHz / 2 40MHz / 3 80MHz / 4 160MHz；PHY 1 11a…6 11ax / 7 11be | `WiFiLinkCalculations.swift:93-132` |
| Wi-Fi 信道频率 | 按频段三套公式：**2.4G** `2407 + 5n`（信道 1…13，信道 14 固定 2484）；**5G** `5000 + 5n` 且必须命中标准信道集合（36–64 / 100–144 / 149–177，步进 4）；**6G** `5950 + 5n` 且 `(ch−1) % 4 == 0`。信道号非法 / 频段未知 → nil，不猜一个「看起来合理」的频率 | `WiFiLinkCalculations.swift:31-39,145-161` |
| Wi-Fi 速率 | 协商速率（PHY 值，非实测吞吐）：非有限 / ≤ 0 → nil（未连接返回 0）；**上限 10000 Mbps** 过滤脏值 | `WiFiLinkCalculations.swift:169-172` |
| Wi-Fi 不读 SSID | **不调用 `ssid()` / `bssid()`**：macOS 11+ 受定位授权门控，未授权恒返回 nil；菜单栏 App 不为两个字段弹定位授权，模型里也不留该字段 | `SystemWiFiLinkSampler.swift:20-22`、`WiFiLinkSnapshot.swift:8-9` |
| 展示 | 比例 0…1，>1 封顶、非有限归 0；不可得统一「—」 | `SystemMetricsFormatting.swift:18-22`、`SystemPaneView+Components.swift:18-22` |

## 关键决策

1. **不用 powermetrics / SMC**。前者非 root 直接 exit 1，不做常驻特权进程；后者在 macOS 27 只匹配到 `AppleSMCKeysEndpoint`，旧协议 `selector=2` 返回 `0xe00002c2`。温度改走 IOHID，失败整块降级为 nil。
2. **不做整机功耗**。IOReport「Energy Model」的 `CPU Energy` 等通道连续 4 轮恒 0，缺 CPU 项无法合成；只展示 GPU 功耗估算值并标「估」。
3. **温度卡收进状态带**。省下一整张卡头与卡间距，GPU 仍保持独立卡（v3 曾并入 CPU 卡，已回滚）。
4. **首屏按优先级分配**。520pt 是硬上限；版2 靠四处信息下沉把内容压到 495pt，一屏看全六块，下沉项全部可点卡取回（见 [设计决策.md](系统页-v2-配色与二级页/设计决策.md)）。若字体 / 本地化导致溢出，滚动容器兜底。
5. **进程条用绝对 sqrt 刻度，不做榜首归一化**。榜首跳变会让所有条联动缩放（同一 15.77% 进程条长在 26.2–197.1pt 间摆动，波动 170.8pt；绝对刻度下恒 51.6pt，波动 0）。
6. **GPU `memoryTotal` 为 nil**。统一内存下加速器只暴露 `In use system memory`；UI 只显示已用量、不画占比条（避免半条假进度）。
7. **首帧速率为 nil 而非 0**。CPU、磁盘速率 / IOPS / 繁忙度、进程 CPU% 都是差分指标，首帧只有基线；GPU 首帧整帧丢弃（`hasGPUBaseline`），第二帧起才可信。
8. **E 核在前**。Mach 编号顺序与 sysctl `perflevel` 相反；按 P 先切分会把 P 核标成 E，故 `splitCores` 固定「前 E 后 P」，详情页热力格标签 `P0… / E0…`（与定稿原型一致）。
9. **采集在后台串行队列**。`SystemMonitor` 为 `@MainActor`，`poll()` 主线程只取基线并排队，系统调用在 `com.networkmonitor.system-metrics` 执行，跨队列只传 Sendable 值类型。
10. **5 s 档共用一个定时器**。负载虽然便宜，但进程全量扫描与 IOReport 没必要 1 秒一跑；慢节拍由 `poll()` 按时间戳判定，避免两套 Timer 互相漂移。
11. **Wi-Fi 跨页同源，网络页不另起采样器**。链路值由 `SystemWiFiLinkSampler` 采一次、挂在 `SystemMetricsSnapshot.wifi` 上；网络页通过同一条系统刷新链 `MenuPanelController.renderSystem()` → `MenuPanelView.updateWiFiLink()` 拿到同一份快照（`MenuPanelController+SystemMetrics.swift:38-43`、`MenuPanelView+DataUpdates.swift:59-61`）。若网络页自行采样，两处 RSSI 会各读各的、互相漂移，且 3.9 ms 的成本要付两遍。
12. **Wi-Fi 慢采到点不留旧值**。其余慢节拍照例是 `??` 沿用上一帧，Wi-Fi 用 `slowResult.map`：关 Wi-Fi / 断网必须让读数真的消失，否则面板会一直显示一个已经不存在的链路（`SystemMonitor.swift:195-197`）。

| 屏幕亮度 | `DisplayServicesGetBrightness` 私有 API 在 Apple Silicon 内置屏返回 −1 |

## 已知限制与待办

- **菜单栏标题 CPU%**：实现只到偏好键 `systemMonitor.menuBar.showsCPU`（默认关），菜单栏仍只显示网速，未接线。
- **P-state 驻留：复核后判定不接入**（不是「待做」）。原结论「16 态聚合为 4 档进面板」已被推翻——本机 P 核稳态只有 IDLE / 满性能两态，非 IDLE 占比与 CPU 利用率差 0–4pp，不构成新信息维度；成本也更高（单次 2.86 ms + 一次性 54.7 ms 订阅）。详见 [第二批调研 §2.7 复核](../调研/系统监控-第二批指标-可行性调研.md)。
- **SoC 电压（PMP）：复核后维持不接入**。`Volt-Temp HM` 是「电压_温度」联合态，稳态下电压几乎不变（2 s 窗口里固定在一个电压档）、也解不出单值；采样 7.9 ms 是所有免 root 项里最贵的一档。详见 [第二批调研 §2.8 复核](../调研/系统监控-第二批指标-可行性调研.md)。
- **网络页只剩 4pt 余量**：加入 Wi-Fi 链路条后实测 516pt（上限 520pt），是靠把链路条前后间距从 10pt 收到 4pt 换来的。**再往网络页加区块会立刻出滚动条**，要加就得先砍别的（`NetworkPaneView.swift:94-98` 有原注释）。
- **原型契约偏差**：`sys-strip`、`last-update`、`refresh-dot` 未实现；卡片提示用原生 `toolTip`。
- **Intel 机型未实测**：全部结论来自 Apple Silicon，温度与 P/E 分组路线待验证（取不到 P/E 核数时已退化为按顺序展示）。
- **进程榜**：首屏固定 Top-2、压力详情固定 Top-10（采样缓存 10 条），未做滚动展开更多。
- **磁盘卷名 / GPU 核数**：现有 `DiskSnapshot` / `GPUSnapshot` 无对应字段，详情页不显示该行，改在脚注说明「本机未采集」，不为照截图改采样器。
- **详情页无动效**：本轮只做静态配色与跳转；进 / 出详情只切 `isHidden`，没有转场动画（与定稿原型一致）。

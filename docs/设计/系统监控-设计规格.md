# 系统监控设计规格

> 何时阅读：维护菜单面板「系统」分段、改动取数口径（`SystemMetrics/*`）或系统页 UI 时。
> 本文以**代码现状为准**（v4 五卡 + 状态带）。实测证据见 [系统监控 CPU/GPU 可行性调研](../调研/系统监控-CPU-GPU-可行性调研.md) 与 [第二批指标可行性调研](../调研/系统监控-第二批指标-可行性调研.md)；冻结原型 `.open-design/system-monitor-prototype/11-prototype-v4.html`，契约与首屏实测见同目录 `07-contract.md`。

## 目标

菜单面板第 6 个分段「系统」（`MenuPanelTab.system`，`MenuTabBarView.swift:12`），只读、免 root、默认 1 s 采样：

- **顶部四联**：CPU / GPU / 内存 / 负载 四个 hero 小格（`SystemPaneView.swift:22-28`，行高 54pt，四格等分约 71pt）。
- **五张卡**：CPU / GPU / **压力** / 内存 / 磁盘，装配顺序见 `SystemPaneView.swift:116-123`。
- **底部 20pt 状态带**：SoC 温度 · 电池环 · 估功耗，一行三段横跨面板（`SystemPaneView+StateBand.swift:55`）。
- 界面只留数值、单位、≤4 字标签，口径说明全部进卡片 `toolTip`（集中在 `SystemPaneView+Tips.swift`）；采样周期 0.5–5 s（默认 1 s），面板按 5 s 节流渲染，曲线保留 60 点历史。

**温度卡已下线**：v1/v2 的 `thermal-card` / `thermal-gauges` 锚点废弃，温度降为状态带上的单读数。设置页原「温度卡开关」语义随之变为「状态带里的温度是否显示」（`SettingsSystemPane.swift:18-19`、`SystemPaneView+Cards.swift:167-169`）。实现时不要再去找 `thermal-card`。

## 版面与首屏预算

面板硬上限 `MenuPanelStyle.maxHeight = 520pt`（`MenuPanelStyle.swift:15`），内容超出后由内部 `NSScrollView` 垂直滚动，**不裁切**（`MenuPanelView.swift:32`）。原型 v4 实测总高 743.5pt（`07-contract.md`），实现态同样必然滚动：判据不是「能否塞进一屏」，而是「520pt 首屏里看到什么」。

实现态首屏实测（320×520 视口，`NM_SNAPSHOT_DIR` 出图后按内容行统计，坐标自视口顶端）：

| 区块 | y 区间（实测） | 高度 | 首屏内 |
|---|---|---|---|
| tab 条 | 10–37 | 28pt | 完整 |
| 四联 `sys-hero-row` | 50–103 | **54pt** | 完整 |
| CPU 卡 | 112–184 | 73pt | 完整 |
| GPU 卡 | 193–282 | 90pt | 完整 |
| **压力卡** | 291–415 | 125pt | **完整（含进程 Top-3）** |
| 内存卡 | 424–478 | 55pt | 完整 |
| 磁盘卡 | 487–507+ | 被 520 边界截断 | 首屏下方 |
| 状态带 | 滚动后可见 | 20pt | 首屏下方 |

即**首屏完整覆盖「四联 + CPU + GPU + 压力（含 Top-3）+ 内存」**，磁盘与状态带需滚动。**压力卡排在 GPU 之后、内存之前**正是为守住这条预算：任何新增区块若插到内存卡之前，就会把压力卡顶出首屏。状态带只在滚动后可见，故快照另出一张滚到底的图（`MenuPanelSnapshot.swift:79-82`）。

## 数据源

除温度（IOHID）与 GPU 功耗（IOReport）走私有符号（dlopen + dlsym，失败即降级）外，均为公开接口。

| 指标 | 首选 API | 采样器 | 档位 |
|---|---|---|---|
| CPU 总 / 每核 / user-system | `host_processor_info(PROCESSOR_CPU_LOAD_INFO)` 差分 | `SystemCPUSampler` | 1 s |
| 内存 / 压力 / swap | `host_statistics64(HOST_VM_INFO64)` + `host_page_size()`、`kern.memorystatus_vm_pressure_level`、`vm.swapusage` | `SystemMemorySampler` | 1 s |
| 磁盘容量 / 速率 / IOPS / 繁忙度 | `statfs("/")`、`IOBlockStorageDriver` → `Statistics` 差分 | `SystemDiskSampler` | 1 s |
| GPU 利用率 | `IOAccelerator` → `PerformanceStatistics` | `SystemGPUSampler` | 1 s |
| SoC 温度 | `IOHIDEventSystemClient`（私有） | `SystemThermalReader` | 1 s（成本 3.6 ms，读 4 个传感器） |
| 负载 / 热压力 / 低电量 | `getloadavg()`、`ProcessInfo.thermalState` / `.isLowPowerModeEnabled` | `SystemLoadSampler` | 5 s |
| 进程 Top-N CPU% / 常驻内存 | `proc_listpids` + `proc_pidinfo(PROC_PIDTASKINFO)` 差分 | `SystemProcessSampler` | 5 s |
| GPU 功耗 | `IOReport` `Energy Model` → `GPU Energy`（单位 nJ） | `SystemGPUPowerReader` | 5 s |
| 电池 / 适配器 | `IOPSGetPowerSourceDescription` + `AppleSmartBattery` + `IOPSCopyExternalPowerAdapterDetails` | `SystemBatterySampler` | 5 s |

**只有一个定时器**：5 s 档不是第二个 `Timer`，而是 `poll()` 按上次慢采时间判断本帧是否顺带采集（`SystemMonitor+SlowMetrics.swift:41-50`）；未到点的那几帧沿用上一帧的慢节拍结果（`SystemMonitor.swift:110-113,191-193`）。

## 口径

| 指标 | 换算 / 规则 | 代码 |
|---|---|---|
| CPU 总 | `totalBusy / totalAll`，`busy = user + system + nice`、`all = busy + idle`；与 `HOST_CPU_LOAD_INFO` 对账差 < 0.3pp | `SystemMetricsCalculations.swift:42-81` |
| CPU user / system 双序列 | **`totalUsage` 是唯一真相源**，用户态由 `total − system` 现算，不读独立 `userUsage` 字段；否则两枚数字各自取整后凑不出总量（「总 25 / 用户 13 / 系统 13」），也与图上叠加带对不上 | `SystemPaneView+Metrics.swift:25-28`、`SystemPaneView+LoadNumbers.swift:76-88` |
| CPU 每核 | 同式差分；单核增量 0 → 记 0（不产生 NaN）；计数倒退该槽位按 0（`current >= previous ? … : 0`） | `SystemMetricsCalculations.swift:84-86` |
| 每核顺序 | **E 核在前、P 核在后**（`ioreg` 实测 cpu0/1 `cluster-type="E"`、cpu2…9 `="P"`）；前 `efficiencyCores` 个为 E | `SystemMetricsFormatting.swift:68-78` |
| P/E 核数 | `hw.perflevel0.physicalcpu`（P）/ `hw.perflevel1.physicalcpu`（E）；取不到返回 (0,0)，退化为按顺序展示 | `SystemCPUSampler.swift:63-67` |
| 内存四段 | `wired`（`wire_count`）/ `active`（`active_count`）/ `compressed`（`compressor_page_count`）/ 空闲；**`used = active + wired + compressed`，不含 inactive**（可随时回收，计进去读数长期偏高） | `SystemMemorySampler.swift:40-45`、`SystemPaneView+Metrics.swift:76-97` |
| 内存压力 | 主键 1 正常 / 2 警示 / 4 紧张；不可读回退 `vm.memory_pressure` 0/1/2；仍不可读按正常 + 记 issue | `SystemMemorySampler.swift:77-88`、`SystemMetrics.swift:120-127` |
| 磁盘容量 | `total = f_blocks × f_bsize`、`used = total - f_bavail × f_bsize`（非特权可用量，同「关于本机」） | `SystemDiskSampler.swift:15-23` |
| 磁盘速率 / IOPS | 按 **`IORegistryEntryGetRegistryEntryID`** 配对两次快照，Δ ÷ 实际间隔；只累加两次都存在的实例，计数器回退按 0 | `SystemMetricsCalculations+Disk.swift:131-174` |
| 磁盘繁忙度 | `(Δ读服务时间 + Δ写服务时间) / 1e9 / elapsed`，clamp 0…1；`Total Time (Read/Write)` 单位是**纳秒** | `SystemMetricsCalculations+Disk.swift:110-118` |
| IOPS 绘图刻度 | **对数** `log10(1+v) / log10(1+3000)`：0…3000 op/s 跨两个数量级，线性刻度会把日常量级全压到底部；真实数值仍写在文字上 | `SystemPaneView+Charts.swift:22-31` |
| 磁盘三键同判 | IOPS 读、IOPS 写、繁忙度**任一为 nil 就整组降级为「—」**，并撤掉虚线——不留「有数值无虚线」或「有虚线无数值」的半显状态（三键必然同源同缺） | `SystemPaneView+Metrics.swift:136-152` |
| GPU 利用率 | `PerformanceStatistics["Device Utilization %"] / 100`；只看键是否存在，不把 0% 当不可用；**首帧丢弃**（冷读恒 0%） | `SystemMetricsCalculations.swift:97-103`、`SystemMonitor.swift:50,166` |
| GPU 显存 | `In use system memory` 作已用；`memoryTotal` 恒 nil（统一内存），细条不画比例 | `SystemGPUSampler.swift:24-25`、`SystemPaneView+Metrics.swift:46-57` |
| 温度 | 只读最多 4 个 PMU 传感器，取最大值；读数须落在 −20…150 °C；> 85 °C 转警示色 | `SystemThermalReader.swift:47,65-78`、`SystemPaneView+Components.swift:16` |
| 负载量程 | `cap = max(核数 × 1.2, 近 60 秒峰值 × 1.15, 1)`；核数参考虚线按 `核数 / cap` 的真实比例画，三线越过虚线即「有进程在排队」 | `SystemPaneView+Load.swift:125-129` |
| 负载归一化 | `load / 核数`；核数 ≤ 0 → nil（不猜分母）；结果不封顶（排队越严重越该显眼） | `SystemMetricsSupplementCalculations.swift:34-37` |
| 进程 CPU% | `Δticks × nsPerTick / 1e9 / elapsed × 100`；**单位是 mach ticks 不是纳秒**（时基坑见 [进程 CPU 百分比时基换算](../踩坑/运行时/进程CPU百分比时基换算.md)）；**不 clamp 到 100**（多线程合法超过，实测 3 线程自旋 298%） | `SystemMetricsSupplementCalculations.swift:52-62` |
| 进程条形 | **sqrt 绝对刻度** `min(1, sqrt(cpuPercent) × 13 / 100)`，满条 = 100% = 占满一个核；条长只由该进程自身 CPU% 决定，不随榜首联动（榜首归一化实测会让同一条在 26%~197% 间乱跳） | `SystemPaneView+Process.swift:90-98` |
| 进程榜单 | 两份分开给（CPU 榜 / 内存榜），切换按钮即时重排；显示 Top-3，采样保留 Top-5；内存榜条形为 `常驻 / 物理内存` 线性占比 | `SystemPaneView+Metrics.swift:194-236`、`SystemMetricsSupplementCalculations.swift:74-105` |
| GPU 功耗 | `Δ纳焦耳 / 1e9 / elapsed`；单位读通道自带 label（同组混着 uJ/nJ/mJ，**禁止硬编码**），未知单位返回 nil；结果按 0…1000 W 合理性过滤 | `SystemGPUPowerReader.swift:129-137`、`SystemMetricsSupplementCalculations.swift:117-124` |
| 电池 | 电量 = `Current Capacity / Max Capacity`（两者都是百分比，非 mAh）；`TimeRemaining = 65535` 是 AC 哨兵值须过滤；健康度百分比不可得，只给 `CycleCount` | `SystemBatterySampler.swift:54-61` |
| 电池环配色 | **纯 `systemGreen`，禁止与 accent 混色**：v3 用 `success + accent 40%` 在 oklab 插值后 hue 落到 178°（青）被打回；< 20% 转黄、< 10% 转红 | `SystemPaneView+Style.swift:64-70`、`SystemPaneView+StateBand.swift:115` |
| 估算功耗标注 | 状态带固定写「估功耗」而非「功耗」：GPU Energy 是累加器估算，不是功耗计读数 | `SystemPaneView+StateBand.swift:33-37,121-129` |
| 展示 | 比例 0…1，>1 封顶、非有限归 0；不可得统一「—」 | `SystemMetricsFormatting.swift:18-22`、`SystemPaneView+Components.swift:18-22` |

## 关键决策

1. **不用 powermetrics / SMC**。前者非 root 直接 exit 1，不做常驻特权进程；后者在 macOS 27 只匹配到 `AppleSMCKeysEndpoint`，旧协议 `selector=2` 返回 `0xe00002c2`。温度改走 IOHID，失败整块降级为 nil。
2. **不做整机功耗**。IOReport「Energy Model」的 `CPU Energy` 等通道连续 4 轮恒 0，缺 CPU 项无法合成；只展示 GPU 功耗估算值并标「估」。
3. **温度卡收进状态带**。省下一整张卡头与卡间距，GPU 仍保持独立卡（v3 曾并入 CPU 卡，已回滚）。
4. **首屏按优先级分配，不是「塞进一屏」**。520pt 是硬上限，743pt 的内容必然滚动；资源只投向「首屏必须看到什么」。
5. **进程条用绝对 sqrt 刻度，不做榜首归一化**。榜首跳变会让所有条联动缩放（同一 15.77% 进程条长在 26.2–197.1pt 间摆动，波动 170.8pt；绝对刻度下恒 51.6pt，波动 0）。
6. **GPU `memoryTotal` 为 nil**。统一内存下加速器只暴露 `In use system memory`；UI 只显示已用量、细条不画比例（避免半条假进度）。
7. **首帧速率为 nil 而非 0**。CPU、磁盘速率 / IOPS / 繁忙度、进程 CPU% 都是差分指标，首帧只有基线；GPU 首帧整帧丢弃（`hasGPUBaseline`），第二帧起才可信。
8. **E 核在前**。Mach 编号顺序与 sysctl `perflevel` 相反；按 P 先切分会把 P 核标成 E，故 `splitCores` 固定「前 E 后 P」，UI 标签 `P1… / E1…`。
9. **采集在后台串行队列**。`SystemMonitor` 为 `@MainActor`，`poll()` 主线程只取基线并排队，系统调用在 `com.networkmonitor.system-metrics` 执行，跨队列只传 Sendable 值类型。
10. **5 s 档共用一个定时器**。负载虽然便宜，但进程全量扫描与 IOReport 没必要 1 秒一跑；慢节拍由 `poll()` 按时间戳判定，避免两套 Timer 互相漂移。

## 降级矩阵

任一字段不可得只影响该字段，**整卡不隐藏、不空白**，统一显示「—」。

| 不可得项 | 触发条件 | UI 表现 |
|---|---|---|
| `cpu` | 首帧（无基线）、tick 读取失败、差分长度不一致 | 四联 CPU「—」、卡头「—」、用户 / 系统图例「—」、每核柱阵清空 |
| `gpu` | 无 IOAccelerator、缺 `Device Utilization %` 键、首帧预热 | GPU「—」、环形 0 且中心「—」 |
| `gpu.memoryTotal` | 统一内存机型（常态） | 只显示已用字节，细条 fraction 0 |
| `memory` | `host_statistics64` 失败、`hw.memsize` 为 0 | 四联内存「—」、堆叠条清空、压力点灰、四段数值行全部「—」（空态不填 0） |
| 内存压力 | 两路 sysctl 均不可读 | 按「正常」渲染（不隐藏徽标），记 issue |
| `disk` | `statfs` 失败 / 总量 0 | 容量「—」、速率 / IOPS / 繁忙度「—」 |
| 磁盘速率 | 首帧、`elapsed<=0`、无配对实例 | 仅该侧「—」，容量照常 |
| 磁盘 IOPS / 繁忙度 | 首帧；或 Statistics 缺 `Operations` / `Total Time` 键 | **三键整组「—」且撤掉虚线**，字节速率照常 |
| `load` | `getloadavg` 返回 0 个样本 | 四联负载「—」、三值「—」、三线图退化为一条灰中线 |
| `load.thermalState` | 系统新增档位 | 按 `.unknown` 处理，toolTip 少一句热压力描述 |
| `processes` | 首帧无基线、`proc_listpids` 失败、全部 pid 无基线 | 进程榜三行「—」+ 空条形描边（与实心条明确区分） |
| 单个进程不可读 | `proc_pidinfo` 返回 −1（权限 / 僵尸 / 已退出） | 跳过该 pid，**不刷日志**（本机实测多数进程可读，属正常现象） |
| `battery` | 台式机无电池、读取失败 | 状态带电池环灰、电量「—」、状态小字为空 |
| `battery.percentage` | 读不到容量键 | 环 0 + 不可用色调，但 **AC / 充电小字照常显示**（「— AC」与「—」是两种事实） |
| `thermal` | `dlopen` / 符号缺失、无 PMU 传感器、读数全越界 | 状态带温度「—」，估功耗「—」 |
| `thermal.powerWatts` | IOReport 不可用、首帧、单位未知、通道缺失 | 估功耗「—」 |
| 温度段整体 | 设置页关掉「显示 SoC 温度」 | 状态带隐藏温度两项，其余两段照常 |

温度段可隐藏，但仅由设置页开关驱动，不因数据缺失自动隐藏。

## 恒不可得清单

以下项**没有采集路径**，UI 不出该项、也不留空位（证据见两份调研）：

| 项 | 原因 |
|---|---|
| CPU 功耗 / 整机功耗 | IOReport `CPU Energy` / `EACC_CPU` / `PACC*_CPU` / `DRAM0` / `ANE0` 连续多轮恒 0，无法合成 |
| 风扇转速 | 5 条路径穷举为空（IOService 2205 节点 / IODeviceTree 358 节点 fanNodes 均 0、SMC 端点 22 props 无风扇键、82 个 HID Product 无 fan/rpm/blower） |
| CPU 频率绝对值（MHz） | `hw.cpufrequency = nil`，IOReport 9225 通道中无 CPU 频率通道；只能给 P-state 驻留占比（本期未接入 UI） |
| GPU 独立温度 | `IOAccelerator.PerformanceStatistics` 无温度键，`GPU Stats` 的 Temperature 子组全 raw=0 |
| 电池健康度百分比 | 51 个 `AppleSmartBattery` 属性中既无 `BatteryHealth` 也无 `DesignCapacity`，只给循环次数 |
| Wi-Fi SSID / BSSID | 需 Location 授权，菜单栏 App 不为此弹权限，返回 nil |
| 屏幕亮度 | `DisplayServicesGetBrightness` 私有 API 在 Apple Silicon 内置屏返回 −1 |

## 已知限制与待办

- **菜单栏标题 CPU%**：实现只到偏好键 `systemMonitor.menuBar.showsCPU`（默认关），菜单栏仍只显示网速，未接线。
- **P-state 驻留未接入**：IOReport「CPU Stats」可读（16 态，1.21 ms），但 32 态需聚合为 4 档才能进 320pt，本期未做。
- **SoC 电压（PMP）未接入**：`Volt-Temp HM` 是「电压_温度」联合态，无连续量纲，只适合进 toolTip。
- **Wi-Fi 链路未接入**：RSSI / 噪声可读（3.24 ms），但需降到 2–5 s 采样才划算。
- **原型契约偏差**：`sys-strip`、`last-update`、`refresh-dot` 未实现；卡片提示用原生 `toolTip`。
- **Intel 机型未实测**：全部结论来自 Apple Silicon，温度与 P/E 分组路线待验证（取不到 P/E 核数时已退化为按顺序展示）。
- **进程榜只显示 3 行**：原型提到「滚动展开 5 条」，实现固定 Top-3、未做展开交互。

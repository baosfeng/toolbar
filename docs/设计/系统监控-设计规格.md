# 系统监控设计规格

> 何时阅读：维护菜单面板「系统」分段、改动取数口径（`SystemMetrics/*`）或系统页 UI 时。
> 实测证据见 [系统监控 CPU/GPU 可行性调研](../调研/系统监控-CPU-GPU-可行性调研.md)；冻结原型见 `.open-design/system-monitor-prototype/`。

## 目标

菜单面板第 6 个分段「系统」（`MenuPanelTab.system`，`MenuTabBarView.swift:12`），一屏看完全部本地指标，只读、免 root、默认 1 s 采样：

- 顶部三联读数区（CPU / GPU / 内存三个 hero 小格）+ 5 张指标卡（CPU / GPU / 内存 / 磁盘 / 温度）= 默认可见 6 个区块。
- **温度卡默认显示**（`defaultVisibleItems` 含 `.thermal`，`SystemMonitorPreferences.swift:32`），设置页可关；其余四卡无开关。
- 界面只留数值、单位、≤4 字标签，口径说明进卡片 `toolTip`；采样周期 0.5–5 s（默认 1 s），面板按 5 s 节流渲染，曲线保留 60 点历史。

## 数据源

除温度走 IOHID 私有符号（dlopen + dlsym，失败即降级）外，均为公开接口。

| 指标 | 首选 API | 采样器 |
|---|---|---|
| CPU 总 / 每核 | `host_processor_info(PROCESSOR_CPU_LOAD_INFO)` 差分，0.007 ms | `SystemCPUSampler` |
| 内存 / 压力 / swap | `host_statistics64(HOST_VM_INFO64)` + `host_page_size()`、`kern.memorystatus_vm_pressure_level`、`vm.swapusage`，1 ms 级 | `SystemMemorySampler` |
| 磁盘容量 / 读写 | `statfs("/")`、`IOBlockStorageDriver` → `Statistics` 差分，0.008 ms，多实例需 entryID 配对 | `SystemDiskSampler` |
| GPU 利用率 | `IOAccelerator` → `PerformanceStatistics`，空闲 0% / 满载 94–100%，0.041 ms | `SystemGPUSampler` |
| SoC 温度 | `IOHIDEventSystemClient`（私有），64 个 PMU 传感器，2 个读数 1.975 ms | `SystemThermalReader` |

## 口径

| 指标 | 换算 / 规则 | 代码 |
|---|---|---|
| CPU 总 | `totalBusy / totalAll`，`busy = user + system + nice`、`all = busy + idle`（等价 `1 - idle 占比`）；与 `HOST_CPU_LOAD_INFO` 对账差 < 0.3pp | `SystemCPUSampler.swift:60-70` |
| CPU 每核 | 同式差分；单核增量 0 → 记 0（不产生 NaN）；tick 用 `&-` 回绕减法 | `SystemCPUSampler.swift:54-62` |
| 每核顺序 | **E 核在前、P 核在后**（`ioreg` 实测 cpu0/1 `cluster-type="E"`、cpu2…9 `="P"`）；前 `efficiencyCores` 个为 E，其后为 P | `SystemMetricsFormatting.swift:61-78` |
| P/E 核数 | `hw.perflevel0.physicalcpu`（P）/ `hw.perflevel1.physicalcpu`（E）；取不到返回 (0,0)，退化为按顺序展示 | `SystemCPUSampler.swift:87-91` |
| 内存已用 | `used = active + wired + compressed`（不含 inactive / free），各项 × `host_page_size()` | `SystemMemorySampler.swift:32-40` |
| 内存压力 | 主键 1 正常 / 2 警示 / 4 紧张；不可读回退 `vm.memory_pressure` 0/1/2；仍不可读按正常 + 记 issue | `SystemMetrics.swift:108-115`、`SystemMemorySampler.swift:69-80` |
| 磁盘容量 | `total = f_blocks × f_bsize`、`used = total - f_bavail × f_bsize`（非特权可用量，同「关于本机」） | `SystemDiskSampler.swift:15-23` |
| 磁盘速率 | 按 **`IORegistryEntryGetRegistryEntryID`** 配对两次快照，Δ 字节 ÷ 实际间隔；只累加两次都存在的实例，计数器回退按 0 | `SystemDiskSampler.swift:41,61-79` |
| GPU 利用率 | `PerformanceStatistics["Device Utilization %"] / 100`；只看键是否存在，不把 0% 当不可用；**首帧丢弃**（冷读恒 0%） | `SystemGPUSampler.swift:20-25`、`SystemMonitor.swift:142` |
| GPU 显存 | `In use system memory` 作已用；`memoryTotal` 恒 nil（统一内存） | `SystemGPUSampler.swift:24-25` |
| 温度 | 只读最多 4 个 PMU 传感器（2 个 `tdie` + 2 个其他），取最大值作 CPU 温度；读数须落在 −20…150 °C | `SystemThermalReader.swift:47,65-78,141-148` |
| 展示 | 比例 0…1，>1 封顶、非有限归 0；不可得统一「—」；温度 > 85 °C 转警示色 | `SystemMetricsFormatting.swift:18-22`、`SystemPaneView+Components.swift:13,16` |

## 关键决策

1. **不用 powermetrics / SMC**。前者非 root 直接 exit 1，不做常驻特权进程；后者在 macOS 27 只匹配到 `AppleSMCKeysEndpoint`，旧协议 `selector=2` 返回 `0xe00002c2`（bad argument）。温度改走 IOHID，失败整块降级为 nil。
2. **不做 CPU 功耗**。IOReport「Energy Model」的 `CPU Energy` 连续 3 轮恒 0，同组 `GPU Energy` 才有值；缺 CPU 项无法合成整机功耗，故 UI 不出「整机功耗」。
3. **GPU `memoryTotal` 为 nil**。统一内存下加速器只暴露 `In use system memory`，没有独立显存总量；UI 只显示已用量、细条不画比例（避免半条假进度）。
4. **首帧速率为 nil 而非 0**。CPU 与磁盘读写都是差分指标，首帧只有基线：写 0 会把「还没测」显示成「完全不忙」，且无法与真实 0 区分。GPU 首帧整帧丢弃（`hasGPUBaseline`），第二帧起才可信。
5. **温度只读少数传感器**。64 个 PMU 全读 64.2 ms / 次（1 s 周期占 6.4% CPU）；选 4 个后 < 3 ms，client 与传感器列表启动时缓存一次。
6. **E 核在前**。Mach 编号顺序与 sysctl `perflevel` 相反（逻辑 CPU 0、1 = E 核）；按 P 先切分会把 P 核标成 E、分错明度，故 `splitCores` 固定「前 E 后 P」，UI 标签 `P1… / E1…`。
7. **采集在后台串行队列**。`SystemMonitor` 为 `@MainActor`，`poll()` 主线程只取基线并排队，系统调用在 `com.networkmonitor.system-metrics` 执行，跨队列只传 Sendable 值类型。

## 降级矩阵

任一字段不可得只影响该字段，**整卡不隐藏、不空白**，统一显示「—」。

| 不可得项 | 触发条件 | UI 表现 |
|---|---|---|
| `cpu` | 首帧（无基线）、tick 读取失败、差分长度不一致 | 三联 CPU「—」、卡头「—」、每核柱阵清空 |
| `gpu` | 无 IOAccelerator、缺 `Device Utilization %` 键、首帧预热 | GPU「—」、环形 0 且中心「—」 |
| `gpu.memoryTotal` | 统一内存机型（常态） | 只显示已用字节，细条 fraction 0 |
| `memory` | `host_statistics64` 失败、`hw.memsize` 为 0 | 三联内存「—」、堆叠条清空、压力点灰、SWAP「—」 |
| 内存压力 | 两路 sysctl 均不可读 | 按「正常」渲染（不隐藏徽标），记 issue |
| `disk` 或读写速率 | `statfs` 失败 / 总量 0；速率首帧、`elapsed<=0`、无配对实例 | 容量「—」；速率则仅该侧「—」，容量照常 |
| `thermal` | `dlopen`/符号缺失、无 PMU 传感器、读数全越界 | 温度「—」，详情行 GPU 温度 / 功耗均「—」 |
| `thermal.powerWatts` / `fanRPM` | 功耗未接入 GPU 读取；风扇本机不可得 | 功耗位「—」（整机功耗永不展示）；风扇不单列 |
| `thermal.gpuTemperatureCelsius` | 与 SoC 共用传感器，无独立来源 | 详情行 GPU 温度「—」 |

温度卡可整卡隐藏，仅由设置页开关驱动，不因数据缺失自动隐藏。

## 已知限制与待办

- **菜单栏标题 CPU%**：原型有「图标 + CPU%」小样（B 版）；实现只到偏好键 `systemMonitor.menuBar.showsCPU`（默认关），菜单栏仍只显示网速，未接线。
- **GPU 功耗**：IOReport `GPU Energy` 可读（≈3.2 W，nJ 为推断单位），未接入；接入需先校准并标注「估算」。
- **风扇转速**：SMC 键路径不存在、IOHID 未暴露，不出该项。
- **GPU 温度 / CPU 频率**：前者无独立传感器；后者「CPU Stats」组存在但未解析出每核频率。
- **原型契约偏差**：`sys-strip`、`last-update`、`refresh-dot` 未实现；卡片提示用原生 `toolTip`。
- **文案待修**：温度卡 tooltip 仍写「取自 SMC」，实际取数为 IOHID。
- **Intel 机型未实测**：结论全部来自 Apple Silicon，温度路线待验证。

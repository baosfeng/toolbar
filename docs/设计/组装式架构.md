# 组装式架构（Assembly Architecture）

> **何时阅读：** 要新增一个功能模块 / 一页面 / 一个 provider，或想知道「为什么代码现在长这样」时。
>
> 本文是**结论与契约**，不是调研过程。现状证据、逐条 file:line 在 `.arch-audit/`（四份只读审计）。

## 一句话

**一个功能 = 一份声明（Module）；宿主只读声明，不认识具体类型。** 新增功能 = 新建文件 + 注册一行，不改任何既有 switch、字典字面量或测试里的数字。

## 一、体检结论（回答「架构完善吗」）

| 问题 | 现状 | 判定 |
|---|---|---|
| 统一数据库访问层 | 是。单一 SQLite 实例 / 单写队列 + READONLY 读连接 + WAL；App 与 UI 目标 `import SQLite3` **零命中**；UI 层 SQL **零命中** | ✅ 通路统一 |
| 统一 HTTP 访问层 | **否**。6 个实现 / 17 个出网点，只有 6 个走同一个封装，且该封装在 App target，Core 侧 3 家 provider 物理上 import 不了 → 各自重写 transport | ❌ 未成层 |
| 分层依赖方向 | Core / UI / App 三层干净：Core 不 import AppKit，UI 不依赖 AppKit；唯一"反向"是 Core 内 30 处 `= AppContext.shared` 隐式默认参数 | ⚠️ 有缝 |
| 单一职责 | 文件体积门禁在；但**同族门禁被改名绕过**（3 处书面证据：改名是为了"让门禁看不见增长"）；MenuPanel 104 文件 / 15830 行、Settings 60 / 8387 | ❌ 形状由门禁驱动而非职责驱动 |
| 装配机制 | 手写顺序装配：`AppCoordinator.start()` 14 阶段，依赖只靠代码位置与注释；`stop()` 手写逆序 | ❌ 无声明式装配 |
| 扩展成本（面板加一页） | 改 **10 个既有文件 + 新建 1 个**，其中 **7 处是穷尽 switch**，测试还写死"剩 5 个" | ❌ 组装不起来 |
| 扩展成本（设置加一类） | 改 5 个 + 2 处测试硬编码 | ⚠️ 已半装配 |
| 事务完整性 | **无事务 API**；BEGIN/COMMIT 手写在 6 文件 20 处、形态不一；删板跨两个事务（崩则板在条目全没） | ❌ 硬缺陷 |
| Schema 迁移 | 双轨制（user_version 阶梯 + 纯 IF NOT EXISTS），`migrateIfNeeded()` 硬编码 2 行；加一张表 6–8 文件 / 7–8 步 | ❌ 不可组装 |
| 可观测性 | 498 处日志 + 脱敏成形；但成功率/耗时/失败原因三元组**零实现**，崩溃上报零，看门狗只罩菜单面板 | ⚠️ |
| 测试体系 | 186 文件 / 22775 行；但 `main.swift` 437 行（门禁线 500，余量 63）、178 个手工登记入口、`assertEqual` **首错即 exit(1)** | ❌ 加一个组件验不动 |
| 门禁矩阵 | 只有"体积"一条线；格式化 / 静态分析 / 复杂度 / 覆盖率 / dead code 全缺；同族门禁 CI 里没有 | ❌ |
| 文档与代码一致性 | 抽查 5 条全脱节，其中 `SKILL.md` 写的 Hook SPI 在代码里**零命中**（幽灵规范） | ❌ |

**总评**：数据通路已经"统一"，但**抽象停在"谁都能拿裸指针"这一层**——加功能仍要字节级懂库、要照着 10 个文件抄接线。缺的不是"再套一层"，是**声明式装配机制**。

## 二、目标形态

参考 `exelban/stats`（Module 基类 + 每模块一份贡献点声明 + 宿主里一行数组）、`sindresorhus/Settings`（pane 数组 + 协议）、VS Code / IntelliJ 的**贡献点（contribution point）**范式，落到本项目：

```
NetworkMonitorCore   领域 + 基础设施      协议 / 事务原语 / 迁移登记表 / HTTP 传输
NetworkMonitorUI     纯值声明 + 纯逻辑    *Descriptor / 贡献点枚举（无 AppKit、无闭包）
NetworkMonitor       AppKit 视图 + 装配   *Module（Descriptor + 工厂闭包）/ 注册表 / 装配器
```

**Descriptor 与 Module 分开**：带 `makePane: () -> NSView` 的装配件进不了 UI target（TestRunner 要能断言纯口径），所以声明拆两层——Descriptor 是可测真源，Module 是 App 侧装配件。

### 贡献点（当前规划 6 个，上限 12）

| 贡献点 | 声明内容 | 取代什么 | 批次 |
|---|---|---|---|
| `panelTab` | id / 标题 / 图标 / 快照后缀 / 取证键 / 首屏 / 动作 / 数据刷新 / dataNeeds | 7 处穷尽 switch | 第一批 |
| `settingsSection` | id / 标题 / 图标 / 副标题 / 分组 / 工厂 | 4 个 switch + 字典字面量 | 第一批 |
| `billingProvider` | kindID / 标题 / 工厂 | 已是注册表，补 Module 化 | 第二批 |
| `notificationEvent` | 事件 / 文案 / 默认音 / 偏好键 / 卡片 | 6 处 + 测试硬编码计数 | 第二批 |
| `menuBarMetric` | 指标 id / 渲染 / 偏好键 | 菜单栏 17 项指标 | 第三批 |
| `snapshotProbe` | 屏幕 id / 帧尺寸 / 取数闭包 | 快照通道 | 第三批 |

## 三、装配

14 阶段手写顺序 → `AssembleStage`（名字 + requires + run），按 `requires` 拓扑排序；缺依赖/成环 = **启动即失败并 log.error**（现在是静默错位）。

## 五、反例（别做）

- 不引 DI 容器：把 165 处 `AppContext.shared` 换成 `Container.resolve()` 只是把编译期错误挪到运行期，**这正是现状的病**。
- 不做运行时插件发现（dlopen / C 段扫描）：收益针对千级贡献者场景，本项目为零。
- 不拆 target：11.5 万行跨 target 会把大量 internal 逼成 public。
- 不靠改名规避行数门禁：本次要把这条病根治掉（门禁口径改成"同族合计 + 新增文件必须属于已登记的族"）。

## 六、验收判据

1. `grep` 面板 / 设置上不再有 title / symbol 类穷尽 switch。
2. 加一个分页 = 新建 1 文件 + 组合根 register 1 行（无测试数字改动）。
3. `BEGIN/COMMIT/ROLLBACK` 字面量只出现在事务原语一个文件里。
4. 加一张表 = 1 个 migration 文件 + 1 行注册。
5. 加一条 HTTP 出网点 = 1 个 Endpoint 声明，不含 transport 代码。

# Token 监控 · 原型交接

- 产物：`.open-design/harness-token-prototype/`（两版原型 + 变体说明）
- 对比页：`.open-design/harness-token-compare.html`
- 截图：`.open-design/shots/token-{a,b}-{light,dark}.jpg`
- 模版 / 风格：沿用 `.open-design/01-template.md`（web-prototype · desktop）与 `.open-design/02-style.md`（apple，320pt 尺度取舍表），未另起风格。

## 1. 需求口径

- toolbar 菜单浮层新增第 5 个分段「Token」，统计**全部** DSH 会话（`~/.dsh/sessions/**/session.v4.jsonl.zstd`），不只当前项目。
- 数据源字段：`assistant/message` 事件的 `usage{inputTokens, outputTokens, totalTokens, cacheReadTokens}` + `time`。`inputTokens` = 未缓存输入，`cacheReadTokens` = 缓存命中读。
- 必须出现的指标：今日 / 本周 / 累计三项分开（未缓存输入 · 输出 · 缓存读）、近 7/30 天按天趋势、按项目 Top N（含会话数）、按模型 Top 5 + 其余合并、缓存命中率。
- 画布 320×600（`00-brief.md` 的 canvas），纵向滚动；深浅色都要成立；无 emoji；数字 tabular-nums。

## 2. 数据事实（2026-10-24 全量扫描，34 个有数据日）

| 口径 | 未缓存输入 | 输出 | 缓存读 | 请求数 |
|---|---|---|---|---|
| 今日 10-24 | 4,976,763 | 2,107,626 | 348,674,382 | 3,107 |
| 本周（10-19 起，6 天） | 22,152,704 | 9,231,234 | 1,819,420,670 | 13,432 |
| 累计 34 天 | 123,844,537 | 62,819,879 | 10,162,026,489 | 72,683 |

- 会话数 1,048；覆盖 2026-09-07 至 2026-10-24。
- **空档**：09-22~09-24、09-27~10-07 无会话，趋势图用斜纹占位、不插值、不补假数据。
- **缓存命中率 = cacheRead ÷（cacheRead + 未缓存输入）**：全量 98.80%，今日 98.59%，近 7 天 98.92%。含义是「输入里有多少是复用上下文」，命中部分单价更低，**不等于**省下的钱；原型里保留这句口径说明。
- 模型 Top5（输入+输出）：deepseek-account/deepseek-flash 44.26M、ollama/deepseek-v4.1-flash 35.38M、ollama-flash/deepseek-v4.1-flash:cloud 28.33M、opencode-go/deepseek-flash 23.60M、deepseek-official/deepseek-flash 18.98M；其余 6 个合并约 36.10M。
- 项目 Top5（输入+输出）：my-dsh-plugins 120.95M（576 会话）、android-monitor 36.22M（182）、skills 15.52M（190）、toolbar 11.16M（57）、ssh-docs 2.42M（9）。
- 与更早一版估值的差异（以本次日表求和为准）：in 122,192,627 → 123,844,537；out 62,298,482 → 62,819,879；cache 10,039,730,947 → 10,162,026,489；请求 72,704 → 72,683。

## 3. 变体差异与取舍

### a · 总览优先（`a-总览优先.html`）
三列平权指标 → 本周/累计对照 → 命中率细条 → 按天柱状 → 按项目 Top5 → 按模型 Top4。
- 取舍：打开先回答「今天/本周烧了多少」，三项指标等权；分布区靠下要滚动。
- 代价：命中率只占一行，趋势图 78px 高，信息量小于 b。

### b · 趋势优先（`b-趋势优先.html`）
三项合计 hero + 三格占比 chips → 命中率环形仪表 + 口径说明 → 96px 大图（柱/折线可切）→ 本周/累计 → 按项目/模型 Top3 可展开。
- 取舍：先看走势与结构；绝对数字下沉为 chips；分布默认 3 行。
- 代价：总量 hero 用的是「输入+输出+缓存读」相加，三种 token 单价不同，这个合计只适合当量级参考（见待拍板 2）。

### 共同
- 320×600 纵向滚动，两版实测 `documentElement.scrollWidth === clientWidth === 320`，无横向溢出；分段条 5 段实测 57×26px，「Token」四字母 + 12px 图标未挤压（scrollWidth == clientWidth）。
- 空态 / 加载态 / 范围切换（今日·近 7 天·近 30 天）/ 刷新 / 分布展开 全部真交互；今日视图的趋势图显示近 7 天并把今日高亮（黑色柱），避免单柱占满画布。
- 深色：`prefers-color-scheme` + `data-theme` 双通道，深色只用 `--dark-*` 重绑语义 token，原始值只在 `:root` 出现一次。
- 演示控件（状态/主题切换）在 320×600 视口之外，标了 `data-od-id="demo-only:controls"`，不进产品。

## 5. 待用户拍板

1. **选版**：a（总览优先）还是 b（趋势优先）？两版都过门禁，差别在信息层级。
2. **b 的「三项合计」口径**：in/out/cache 单价不同，合并成 2.42B 只适合当量级。要不要改成「缓存读为主 + 另两项小字」，或干脆去掉合计。
3. **今日视图的趋势图**：现在是「近 7 天 + 今日高亮」。是否接受这个折中，还是坚持只画当天（需要额外的按小时数据源）。
4. **Top N**：a 默认 5/4 行、b 默认 3 行 + 展开。真实产品里要不要「点击项目/模型 → 详情页」。
5. **命中率文案**：98.8% 容易被读成「省了 98.8% 的钱」，是否保留现有免责说明，或改成「缓存复用率」这个更准确的名字。
6. **成本估算**：如果 DSH 侧有单价表，可以加「估算花费」；当前刻意没做，避免编造价格。
7. **标签语言**：分段条目前是「网络 / 剪贴板 / 传送 / 额度 / Token」，前四个中文、第五个英文。是否统一改成「用量」。
